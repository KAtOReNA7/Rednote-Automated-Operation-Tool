## 四、Content Brief V1 聚合根

定义严格、版本化合同：

* `ContentBrief`
* `ContentBriefVersion`
* `BriefAudience`
* `BriefObjective`
* `BriefJudgment`
* `BriefArgument`
* `BriefCounterargument`
* `BriefEvidenceRef`
* `BriefStructurePlan`
* `BriefSpoilerPlan`
* `BriefScorePlan`
* `BriefExpressionPolicy`
* `BriefForbiddenExpression`
* `BriefFieldLock`
* `BriefDependency`
* `BriefReadinessSnapshot`
* `BriefGenerationPlan`
* `BriefGenerationRun`

ContentBrief 是稳定 identity，绑定：

* 一个 TopicCandidate identity；
* 创建时的 Topic version；
* 可选 Experiment/Design/Assignment identity；
* 主要 Work/Expression/Edition 集合；
* current version pointer。

每个 Brief version immutable，至少保存：

* schema、policy、prompt versions；
* 完整结构化 payload；
* 字段 provenance；
* 字段 lock snapshot；
* Topic、Experiment、Dossier、Authenticity、Evidence dependencies；
* input hash、readiness 和 reason codes；
* status、revision、previous version；
* createdAt、confirmedAt、lockedAt；
* bounded warnings。

同一 Brief 只能有一个 current version。历史版本不可原地覆盖或物理删除。

## 五、简报必需字段

每个 Brief 必须包含：

1. `targetAudience`

   * 目标读者；
   * 已有知识水平；
   * 选择或阅读需求；
   * 不得使用未经来源支持的敏感画像。

2. `contentObjective`

   * 希望读者理解、判断或比较什么；
   * 不是“制造爆款”等不可验证承诺。

3. `coreJudgment`

   * 一个明确中心判断；
   * 标注 `OPINION / FACTUAL_SYNTHESIS / MIXED`；
   * 包含可证伪或可限定条件；
   * 不得冒充已经发布的结论。

4. `supportingArguments`

   * 有限数量；
   * 每项包含 argument kind、claim、evidence refs 和 limitation；
   * 事实与观点分开。

5. `strongestCounterargument`

   * 真实、最强的反方或限定条件；
   * 不得构造稻草人；
   * 事实部分同样需要 Evidence；
   * 包含 response/qualification，但不要求强行反驳。

6. `evidenceMap`

   * 每个事实性 argument 对应受控引用；
   * 不保存完整网页、整份 Dossier 或大段原文。

7. `structurePlan`

   * 段落功能、顺序和内容槽位；
   * 不是成品标题或成品正文。

8. `spoilerPlan`

   * NO、LIGHT、FULL；
   * warning required/placement；
   * core trick/ending flags；
   * 用户确认要求。

9. `scorePlan`

   * NONE、PERSONAL_SCORE、RESEARCH_ANALYSIS_SCORE；
   * scale、value source、public label requirement；
   * INTERNAL_PREDICTION 永远禁止进入 Brief。

10. `expressionPolicy`

    * PERSONAL_EXPERIENCE 或 PUBLIC_RESEARCH_ANALYSIS；
    * 第一人称权限；
    * R2 assertion allowlist；
    * required public labels。

11. `forbiddenExpressions`

    * 全局、类型、真实性、证据和用户自定义禁用表达；
    * reason 和 policy source。

12. `openQuestionsAndLimitations`

    * 尚未解决的资料缺口；
    * 不得把 gap 补写成确定结论。

## 六、五类 Brief Profile

建立与 Issue 022 五类 Topic 一一对应的有限 `BriefProfileRegistryV1`。

1. `NON_SPOILER_SINGLE_BOOK_VERDICT`

   * 精确一个主要 Work；
   * spoiler 必须 NO；
   * 包含适合或不适合读者、主要优点、主要缺点和购买或阅读判断；
   * 禁止泄露核心诡计、真凶、结局或答案。

2. `FULL_TRICK_LOGIC_ANALYSIS`

   * spoiler 必须 FULL；
   * 保存封面、标题和正文开头警告要求；
   * 结构至少区分诡计复盘、伏线公平性、逻辑成立性、误导与漏洞；
   * 完整剧透本身不阻止 Brief ready。

3. `CROSS_WORK_COMPARISON`

   * 至少两个主要 Work；
   * 使用 Issue 022 已验证 comparison dimension；
   * 每个 Work 使用同一比较维度和对称 evidence slots；
   * 不允许以一个作品的资料替代另一个作品。

4. `WEB_VS_PUBLISHED_MYSTERY`

   * 包含已验证的网络或出版形态；
   * 比较创作、结构或阅读体验，不自动推断商业优劣；
   * publication relationship 只作为事实输入，不参与产品门禁或评分。

5. `MYSTERY_AND_CULTURAL_PHENOMENON`

   * 绑定至少一个 Work 和可追溯文化主题；
   * context-only 可作为讨论背景，但不能冒充已验证关键事实；
   * 禁止退化为无书目主体的泛热点文案。

Profile 必须验证必需槽位、主体数量、比较对称性和 spoiler 兼容性。

## 七、证据映射

每个 `BriefEvidenceRefV1` 必须引用现有且 current 的：

* DossierVersion/DossierEntry；
* AtomicClaim；
* FactEvaluation；
* EvidenceLocator；
* SourceRevision。

可按实际仓储保存最小引用集合，但必须能完整追溯上述链路。

每个 evidence ref 至少包含：

* ref identity；
* brief field/argument identity；
* fact-or-context role；
* claim/evaluation/evidence/source revision IDs；
* bounded display summary；
* source language；
* current/stale status；
* dependency hash。

冻结规则：

* 只有 current `VERIFIED` FactEvaluation 可支持关键事实；
* supporting-only/context-only 必须保留角色，不得升级；
* `FACT_BLOCKED`、stale 或 invalid locator 不能支撑生成就绪 Brief；
* opinion 可以没有 Claim，但其事实前提必须有映射；
* counterargument 的事实部分同样需要证据；
* 不允许模型编造 ID、URL、excerpt 或引用；
* runtime 必须验证每个模型输出引用确实在输入 allowlist 中；
* Brief JSON 不复制整页正文、完整 Evidence excerpt 或完整 Dossier；
* Evidence 更新后精确失效相关 Brief。

Issue 026 未来仍会检查 Draft 中的正文事实映射；Issue 024 的 Brief evidence map 不替代 Issue 026。

## 八、真实性、第一人称与评分

Brief 必须消费 current `ExpressionPermissionSnapshotV1`。

PERSONAL_EXPERIENCE：

* R1 可使用第一人称和 PERSONAL_SCORE；
* R2 只能引用当前、逐条确认的 ExperienceAssertion ID；
* R3、S1、S2、UNCLASSIFIED 不得使用具体第一人称体验；
* Personal 权限不绕过 Dossier/FactPolicy。

PUBLIC_RESEARCH_ANALYSIS：

* 必须有 current READY Dossier；
* 必须保存“公开资料整理”标签要求；
* 如使用评分，只能是 RESEARCH_ANALYSIS_SCORE；
* 必须保存“资料分析评分”标签要求；
* 不得使用“我读完”“我看到这里”“我的阅读体验”等表达。

Score：

* PERSONAL_SCORE 只使用 Issue 021 允许的个人分；
* RESEARCH_ANALYSIS_SCORE 只使用资料分析分；
* INTERNAL_PREDICTION 不得进入 schema、DTO、renderer、模型输入或输出；
* UNKNOWN 不伪造 0；
* Brief 可保存评分使用计划和值引用，但不让模型擅自创建用户个人评分。

R2 assertion 撤销、ReadingState 或 permission revision 变化时，只精确失效相关 Brief。

## 九、禁用表达与风格约束

定义版本化 `ForbiddenExpressionRegistryV1`，至少区分：

* `GLOBAL_ACCOUNT`
* `AUTHENTICITY`
* `FACT_POLICY`
* `SPOILER`
* `CONTENT_TYPE`
* `USER_CUSTOM`

系统级规则至少包括：

* 不得伪造第一人称亲历；
* 不得把资料分析评分写成个人评分；
* 不得把模型记忆写成事实来源；
* 不得把 gap 或 UNKNOWN 写成确定事实；
* 非剧透类型不得出现答案性表达；
* 不讨论账号是 AI 运营实验；
* 不使用粉圈引战或攻击作者、读者、群体的表达；
* 不将“神作”“封神”“后劲太大”等空泛词作为未解释的核心判断。

账号风格目标作为 Brief 约束保存：

* 观点鲜明；
* 短句直接；
* 少量冷幽默；
* 批评作品，不攻击作者或读者；
* 不为互动刻意制造对立。

规则：

* 用户可新增自定义禁用表达；
* 用户不能删除系统冻结规则；
* 禁用表达是未来写作约束，不在 Issue 024 扫描不存在的正文；
* AI 标识和版权不得成为禁用表达、readiness 或锁定因素。

## 十、字段编辑、来源与锁定

每个可编辑字段保存 provenance：

* `SYSTEM_DERIVED`
* `MODEL_CANDIDATE`
* `USER_EDITED`
* `USER_CONFIRMED`

字段锁状态：

* `EDITABLE`
* `USER_LOCKED`
* `SYSTEM_LOCKED`

SYSTEM_LOCKED 至少包括：

* Topic identity/version；
* Experiment assignment identity，可空；
* evidence dependency IDs；
* policy versions；
* authenticity、score、spoiler permission；
* system forbidden rules。

用户可以锁定：

* target audience；
* objective；
* core judgment；
* argument/counterargument；
* structure slots；
* user custom forbidden expressions；
* 有限 style choices。

规则：

* 用户编辑或锁定创建新 BriefVersion，不原地覆盖；
* expected revision、preview diff、显式确认；
* sender/window 绑定、短期、单次 token；
* 锁定字段在 regenerate 时保持逐字或逐值不变；
* regenerate 只改未锁定字段；
* 模型不得解锁或覆盖 USER_LOCKED；
* 依赖失效不能静默修改锁定字段，只将 Brief 标记 stale；
* 解锁需要独立确认和 audit；
* 支持 undo、clone、archive、restore；
* 所有历史和 transition append-only。

## 十一、Brief Readiness

定义纯确定性 `BriefReadinessPolicyV1`，状态至少包括：

* `DRAFT_INCOMPLETE`
* `DOSSIER_NOT_READY`
* `FACT_BLOCKED`
* `AUTHENTICITY_BLOCKED`
* `SPOILER_POLICY_INCOMPLETE`
* `EXPERIMENT_MISMATCH`
* `EVIDENCE_MAPPING_INCOMPLETE`
* `STALE`
* `READY_FOR_DRAFT_GENERATION`

`READY_FOR_DRAFT_GENERATION` 必须同时满足：

* Topic current、eligible、非 HELD/ARCHIVED；
* 所有主要 Dossier current 且 ready；
* ExpressionPermission current 并允许选择的 analysis mode；
* score origin 合法；
* spoiler plan 完整；
* 五类 Profile 必需槽位完整；
* 每个事实性 argument 有 current evidence mapping；
* 无会阻止核心判断的 FACT_BLOCKED；
* 如绑定 Experiment，design/assignment current 且 Brief 与 arm/controlled conditions 一致；
* 所有 SYSTEM_LOCKED 依赖 current；
* JSON Schema/runtime validator 全部通过。

低覆盖度、冲突或 stale 时：

* 可以保存 `DRAFT_INCOMPLETE` 或对应阻止状态的编辑草稿；
* 不能标记为 `READY_FOR_DRAFT_GENERATION`；
* 不能入队 Issue 025；
* 不自动触发 Dossier rebuild 或事实处理。

AI 参与度、AI 标识、版权、出版归属和普通负面观点不参与 readiness。

## 十二、Experiment 绑定

Brief 可以不绑定 Experiment。

如绑定 Issue 023 Assignment：

* Topic/Work 必须与 AssignmentUnit 一致；
* replication structure fingerprint 必须一致；
* primary variable arm value 必须进入 Brief 的实验字段；
* controlled conditions 必须保持；
* popularity stratum 只作为实验快照，不影响 Brief 事实或表达权限；
* Experiment 必须 LOCKED、current、非 stale；
* 不得将 Experiment 的 hypothesis 写成已验证结果；
* Brief 不保存 effect、winner、p value 或真实 metric value。

用户编辑若违反 arm 或 controlled condition：

* Brief readiness 返回 `EXPERIMENT_MISMATCH`；
* 不自动修改 Experiment；
* 不自动把 Topic 移到另一个 arm；
* 用户只能恢复兼容值、解除 Brief 的实验绑定，或在 Issue 023 创建新的实验版本；
* 所有操作显式确认并审计。

## 十三、纯本地 Scaffold 与结构化生成

必须提供不配置模型也可用的纯本地 scaffold：

* 从 Topic、Profile、Dossier/Permission snapshot 创建字段骨架；
* 填入受控主体、evidence refs、标签、spoiler、score、forbidden rules；
* 未能确定的 judgment 或 argument 保持空缺或 open question；
* 不使用模板伪造内容判断；
* 用户可手工完成并锁定。

同时实现 provider-neutral `ContentBriefGenerationV1`：

* 只经 ModelExecutionService；
* structured JSON capability 必须 current、SUPPORTED；
* 明确 preview、预算、用户确认；
* 复用缓存、usage、model_runs、reservation 和 cost ledger；
* credential 只在 main transport 最终阶段解析；
* after-send ambiguous 不自动重试、repair、fallback 或换模型。

模型输入只包含：

* 选定 Topic 的有界结构化字段；
* 选定 Dossier entries、Claim summaries 和允许的 evidence refs；
* 当前 Experiment arm/controlled conditions，可空；
* ExpressionPermission、score、spoiler 标签要求；
* Profile Schema；
* forbidden-expression rules；
* 已锁定字段。

模型输出：

* 只能是 strict ContentBrief candidate；
* 不包含标题、正文、标签、置顶评论或图片 prompt；
* 每个事实性字段引用输入 allowlist；
* 不能新增 Work、Claim、Evidence 或 assertion；
* 不能修改系统策略或 locked fields；
* 不能声称实验结果；
* 经过 runtime Schema、引用、权限、readiness 和 lock-preservation 验证后才可保存为 `MODEL_CANDIDATE` version。

页面或 Dossier 文本视为不可信数据，prompt injection 不能改变 schema、政策或任务。

测试只使用 Scripted Mock；本轮真实请求和费用为 0。

## 十四、Generation Plan、队列与恢复

定义有界 `BriefGenerationPlanV1`，preview 至少显示：

* Topic、Experiment、subject IDs；
* Profile；
* 输入 DossierEntry、Claim、EvidenceRef 数；
* locked/editable field 数；
* 最大输入字符和输出字节；
* 精确最大模型请求数；
* capability 和预算结论；
* 预计本地写入；
* dependency、input、preview hash；
* expiry、expected revisions。

新增有限 `CONTENT_BRIEF_GENERATE_V1` handler：

* 只有桌面显式确认的 producer；
* payload 只含 ID、版本、hash 和有限计数，不含正文或 evidence excerpt；
* executionId 幂等；
* 同 Brief 同时最多一个 active generation；
* 模型调用期间不持有 DB 长事务；
* pause、cancel、shutdown 和 recovery 沿用 JobQueue；
* pre-send 可以安全恢复；
* after-send ambiguous 不自动重发；
* 发布 candidate version 前重验依赖、input hash 和 lock snapshot；
* stale、失败或取消不替换 current ready version；
* result 不含 Brief payload、正文、路径、secret 或 raw response；
* 不自动创建 Draft 或启动 Issue 025。

## 十五、依赖与精确失效

保存至少以下 dependency：

* TopicCandidate version/state/eligibility；
* TopicQuotaPlan version，可空；
* Experiment/Design/Assignment version，可空；
* Work/Expression/Edition identities；
* DossierVersion/Entry；
* Claim/FactEvaluation/Evidence/SourceRevision；
* ExpressionPermission/ReadingState/R2 assertion；
* score、spoiler、authenticity、profile、forbidden policy versions；
* prompt、schema、profile versions；
* lock snapshot。

以下变化只失效相关 Brief：

* Topic 版本、资格、hold/archive；
* Dossier current/readiness 或 Evidence、Claim、Source 变化；
* ReadingState、assertion、permission、score、spoiler policy 变化；
* Experiment design、assignment、stratum 变化；
* Work merge、split、undo；
* Profile、Schema、Prompt、Forbidden registry 版本变化。

要求：

* 失效幂等；
* 不自动 regenerate；
* 不自动解锁字段；
* 不自动创建 Draft；
* 无关 Topic、Work、Source 不触发全库 stale；
* 显式 regenerate 创建新版本；
* 相同 input 与 locks 为 deterministic no-op；
* 关键依赖查询使用索引，不做 O(n²) 扫描。

## 十六、Migration 与仓储

追加运行时发现的下一条连续 migration；不预置版本号或 checksum，不修改历史 migration。

优先规范并扩展现有 `content_briefs`，避免第二套 Brief 真相。至少覆盖：

* brief identity/current version；
* immutable brief versions；
* audience、objective、judgment、arguments、counterargument；
* structure、spoiler、score、expression plan；
* evidence refs；
* forbidden expressions；
* field provenance/locks；
* readiness snapshot；
