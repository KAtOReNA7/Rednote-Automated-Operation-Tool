## 四、Draft 聚合根与版本

定义严格、版本化合同：

* `ContentDraft`
* `ContentDraftVersion`
* `DraftTitle`
* `DraftBody`
* `DraftBlock`
* `DraftTagSet`
* `DraftPinnedComment`
* `DraftSpoilerWarnings`
* `DraftLineageRef`
* `DraftFieldLock`
* `DraftDependency`
* `DraftStructuralValidation`
* `DraftGenerationPlan`
* `DraftGenerationRun`
* `DraftRewritePlan`
* `DraftRewriteRun`

ContentDraft 是稳定 identity，绑定：

* 一个 ContentBrief identity；
* 创建时 BriefVersion；
* TopicCandidate identity/version；
* 可选 Experiment Design/Assignment；
* 主要 Work 集合；
* current DraftVersion pointer。

每个 DraftVersion immutable，至少保存：

* title；
* ordered body blocks；
* tags；
* pinned comment；
* spoiler warning artifacts；
* lineage refs；
* field provenance/lock snapshot；
* prompt/schema/style/model/execution versions；
* input/output hash；
* structural validation；
* dependencies；
* status、revision、previous version；
* createdAt、confirmedAt；
* bounded warnings/reasons。

同一 Draft 只能有一个 current version。历史版本不得原地覆盖或物理删除。

## 五、产物边界和状态

Issue 025 产物必须醒目标记为“未经质量检查”。

Draft status 至少包括：

* `MANUAL_DRAFT`
* `MODEL_CANDIDATE`
* `STRUCTURE_INVALID`
* `READY_FOR_QUALITY_PIPELINE`
* `STALE`
* `SUPERSEDED`
* `ARCHIVED`

`READY_FOR_QUALITY_PIPELINE` 只表示：

* 结构化字段齐全；
* Brief、锁定和权限依赖在生成时匹配；
* 输出满足基本长度、字符、JSON 和引用 allowlist；
* 可以交给未来 Issue 026—030。

它不表示：

* 事实已经逐句核验；
* 第一人称或评分已完成全文检查；
* 剧透泄露检查通过；
* 重复度和标题一致性通过；
* 已审批、可导出或可发布。

UI、DTO、文档和测试不得使用 `APPROVED`、`PUBLISHABLE`、`QUALITY_PASSED` 等错误状态。

## 六、文案产物 V1

1. 标题

* 至少一个 current selected title；
* 可以有有限数量备选标题；
* 每个标题有 title ID、kind、text、provenance；
* 标题长度由版本化 `ContentFormatPolicyV1` 限制；
* 不把该限制宣称为小红书实时官方规则；
* 非剧透标题不得泄露答案；
* FULL 类型必须携带 Brief 要求的标题剧透标识。

2. 正文

* 由有序、稳定 ID 的 DraftBlock 组成；
* block kind 来自有限 registry；
* 每个 block 绑定 Brief structure slot/argument lineage；
* 允许观点、事实综合、反方、限定、结论、警告等有限功能；
* 不保存模型内部推理；
* 不要求 Issue 025 直接生成 Claim 映射结论。

3. 标签

* 有界数组；
* Unicode 规范化；
* 去重；
* 单项及总字符上限；
* 不保存 `#` 的多种等价形式造成重复；
* 不生成无关热点、AI 实验或粉圈引战标签。

4. 置顶评论

* 有界纯文本；
* 不得新增 Brief 外的新关键事实；
* 非剧透内容不得在评论中泄露答案；
* 资料分析与评分标签要求保持；
* FULL 内容必要时重复剧透提示。

5. 剧透警告

* `coverWarningText`：供后续视觉阶段使用的文本，不生成图片；
* `titleWarningMarker`；
* `bodyOpeningWarningText`；
* 可选 `pinnedCommentWarningText`；
* 与 Brief spoiler plan 的 required placements 精确一致；
* 完整剧透本身允许，缺少要求的 warning artifact 时结构验证失败。

## 七、五类 Copy Profile

建立与 Topic、Brief 一致的 `CopyProfileRegistryV1`。

1. `NON_SPOILER_SINGLE_BOOK_VERDICT`

   * 明确判断是否值得读、适合与不适合谁；
   * 包含优点、缺点和限定；
   * 标题、正文、标签、置顶评论均不得泄露核心答案。

2. `FULL_TRICK_LOGIC_ANALYSIS`

   * 允许完整拆解；
   * 必须生成 cover、title、body opening 所需警告文本；
   * 结构覆盖诡计、伏线公平性、逻辑成立性、误导和漏洞；
   * 不因为完整剧透本身拒绝 Draft。

3. `CROSS_WORK_COMPARISON`

   * 对所有 Work 使用相同比较维度；
   * 结构和篇幅基本对称；
   * 不用一部作品的 Evidence 替代另一部；
   * 结论允许有胜负，但要保留适用条件。

4. `WEB_VS_PUBLISHED_MYSTERY`

   * 明确网络或出版形态；
   * 比较结构、阅读体验或创作机制；
   * 不自动推导商业价值或版权归属；
   * publication relationship 不参与门禁和排序。

5. `MYSTERY_AND_CULTURAL_PHENOMENON`

   * 书目主体和文化主题均可追溯；
   * context-only 只能作为背景措辞；
   * 不退化为无书目的泛热点文章。

每类 profile 必须验证对应 Brief slots 已被消费，并保留遗漏 reason。

## 八、账号文风 V1

定义版本化 `AccountVoicePolicyV1`：

* `OPINIONATED`
* `SHORT_DIRECT_SENTENCES`
* `LIGHT_DRY_HUMOR`

具体规则：

* 核心判断明确，不堆砌模糊褒义词；
* 句子和段落偏短，但不机械切碎；
* 冷幽默有限、服务观点，不嘲讽作者或读者；
* 可以批评作品，不攻击作者、读者或群体；
* 不为互动刻意制造对立；
* 不讨论账号是 AI 运营实验；
* 避免把“神作”“封神”“后劲太大”当作无解释判断；
* 不模仿具体在世作者、博主或账号的独特风格；
* 不凭空加入网络流行语或热点。

Style policy 输出：

* required traits；
* forbidden traits；
* bounded sentence/paragraph targets；
* humor upper bound；
* reason codes；
* policy version。

这些是生成约束，不替代 Issue 029 的完整风格、一致性与重复度检查。

## 九、真实性、评分和公开标签继承

Draft 必须逐值继承 Brief 的：

* expression mode；
* allowed first-person state；
* R2 ExperienceAssertion allowlist；
* score origin；
* score value/reference；
* required public labels；
* spoiler plan；
* system forbidden expressions。

规则：

* R1 可按 Brief 使用第一人称；
* R2 只能消费 Brief 明确 allowlist 内的 current assertion；
* R3、S1、S2、UNCLASSIFIED 不得由 generator 获得新的第一人称权限；
* PUBLIC_RESEARCH 必须包含“公开资料整理”要求对应的可见文本 artifact；
* RESEARCH_ANALYSIS_SCORE 必须包含“资料分析评分”可见文本 artifact；
* PERSONAL_SCORE 不得由模型新建或修改；
* INTERNAL_PREDICTION 不进入 prompt、schema、Draft、DTO 或 renderer；
* Brief 未授权的第一人称或评分输出直接拒绝保存；
* Issue 027 仍须对完整正文做独立真实性检查。

## 十、Brief Lineage 与未来事实映射准备

每个 title、body block、tag、comment 可以保存有限 `DraftLineageRefV1`：

* Brief field、argument、structure slot ID；
* Work identity；
* 允许的 BriefEvidenceRef ID 集合；
* 可选 ExperienceAssertion ID；
* provenance；
* input hash。

冻结规则：

* lineage 只表示“生成来源于哪个 Brief 槽位”；
* 不等于正文事实已经映射或验证；
* 模型输出只能引用输入 allowlist 中的 ID；
* 不允许编造 Claim、Evidence、Source、Brief field 或 assertion ID；
* 不复制 Evidence excerpt、完整 Dossier 或 Source 正文；
* 没有 lineage 的事实性 block 可保存为 STRUCTURE_INVALID 或待人工修正，但不能进入 `READY_FOR_QUALITY_PIPELINE`；
* Issue 026 将建立正文 statement—Claim—Evidence 的正式映射。

## 十一、Prompt 与模型运行版本

定义不可变、版本化：

* `CopyPromptTemplateV1`
* `CopyOutputSchemaV1`
* `CopyGenerationPolicyV1`
* `CopyRewritePolicyV1`

每次模型运行保存：

* prompt template version；
* schema、style、profile、policy versions；
* provider、model、protocol identity；
* ModelExecution ID；
* Brief、input、lock hash；
* cache、usage、cost 状态；
* output hash；
* run outcome；
* createdAt。

不得保存：

* 明文密钥；
* Authorization header；
* raw provider response；
* 模型内部推理；
* 完整渲染 prompt 到普通日志或 audit；
* 无关 Dossier、Source 正文。

Prompt 只消费当前选择的有界 Brief 字段、lineage allowlist、locked values 和系统政策。

所有研究文本均视为不可信数据，prompt injection 不得改变任务、schema、锁定字段或政策。

## 十二、完整生成

实现 provider-neutral `CopyGenerationV1`：

* 只经 ModelExecutionService；
* structured JSON capability 必须 current、SUPPORTED；
* 明确 preview、预算和用户确认；
* 复用缓存、usage、model_runs、reservation 和 cost ledger；
* credential 只在 main transport 最终阶段解析；
* 每次完整生成最多一个外部模型请求；
* 不自动 retry、repair、fallback 或换模型；
* after-send ambiguous 不自动重发。

模型输入至少包括：

* current READY ContentBrief；
* 五类 Copy Profile；
* locked values；
* Brief evidence/lineage allowlist；
* expression、score、spoiler、public-label requirements；
* Experiment arm/controlled conditions，可空；
* AccountVoicePolicy；
* forbidden expressions；
* strict output schema。

模型输出必须：

* 是 exact structured object；
* 只包含标题、正文块、标签、置顶评论、warning artifacts 和 lineage refs；
* 不包含图片 prompt、质量结论、审批或发布字段；
* 通过大小、枚举、字符、allowlist、lock preservation 和 profile validator；
* 不能声明实验结果；
* 不能修改 Topic、Brief 或 Experiment；
* 验证失败时保留失败 run，不保存 current DraftVersion。

本轮测试只使用 Scripted Mock，真实调用和费用为 0。

## 十三、手工 Draft 路径

未配置模型时，用户必须仍可：

* 从 READY Brief 建立空白结构化 Draft scaffold；
* 手工编辑标题、正文块、标签、置顶评论和 warning 文本；
* 添加、删除、排序允许的正文块；
* 绑定 Brief lineage；
* 预览并保存新版本；
* 锁定字段；
* 将结构完整的版本标记为 `READY_FOR_QUALITY_PIPELINE`。

手工路径使用相同 schema、profile、permission、lineage 和结构 validator。

不得因“手工输入”绕过系统锁定或生成新的真实性权限。

## 十四、局部重写

定义有限 `RewriteScopeV1`：

* `SELECTED_TITLE`
* `TITLE_VARIANTS`
* `BODY_BLOCK`
* `BODY_BLOCK_RANGE`
* `TAG_SET`
* `PINNED_COMMENT`
* `SPOILER_WARNING_ARTIFACT`

每次 rewrite 必须：

* 用户明确选择 DraftVersion 和 scope；
* 显示 before/after preview；
* 只允许一个连续、有界 scope；
* 绑定 expected revision、input hash 和 lock snapshot；
* 最多一个模型请求；
* 保存 rewrite instruction 的有限结构，不保存自由形式秘密；
* 新建 DraftVersion，不原地覆盖。

不可变规则：

* scope 外所有字段逐字节或逐规范值保持不变；
* USER_LOCKED 和 SYSTEM_LOCKED 字段不可重写；
* BODY_BLOCK rewrite 保留 block ID 或明确生成新 ID、lineage；
* 不允许通过局部重写改变 content type、expression mode、score origin、spoiler level、Experiment arm 或 controlled conditions；
* rewrite 输出仍通过完整 schema、profile、permission、lineage validator；
* after-send ambiguous 不自动重发；
* 同 input、scope、instruction、cache key 幂等；
* 用户可以撤销到历史版本。

## 十五、字段锁、编辑和版本 Diff

Draft 字段 provenance 至少包括：

* `SYSTEM_DERIVED`
* `MODEL_GENERATED`
* `USER_EDITED`
* `USER_CONFIRMED`

锁状态：

* `EDITABLE`
* `USER_LOCKED`
* `SYSTEM_LOCKED`

SYSTEM_LOCKED 至少包括：

* Brief、Topic、Experiment identities；
* expression、score、spoiler mode；
* required public labels；
* system forbidden rules；
* policy、schema versions。

用户可锁定：

* selected title；
* 单个正文 block；
* tag set；
* pinned comment；
* warning text；
* 允许的 style choices。

要求：

* 编辑、锁定、解锁、重排都创建新版本；
* expected revision、preview diff、显式确认；
* sender/window 绑定、短期、单次 token；
* transition、audit append-only；
* 并发 stale fail closed；
* lock 在完整生成和局部重写中保持；
* 支持 undo、archive、restore；
* diff 有界，长正文按 block 或字段比较，不输出无限全文。

## 十六、结构验证与质量边界

Issue 025 只实现 `DraftStructuralValidationV1`：

* schema exactness；
* required fields；
* 长度、字符和集合边界；
* 五类 profile slots；
* Brief lineage allowlist；
* field lock preservation；
* required public-label artifacts；
* spoiler warning artifact presence；
* Experiment controlled-condition shape；
* forbidden exact 或 system patterns 的基础拒绝；
* dependency currentness。

明确不在 Issue 025 完成：

* 正文事实是否与 Claim 一致；
* 每个句子的 factual 或 opinion 分类；
* 复杂第一人称语义识别；
* 隐含剧透检测；
* 历史相似度；
* 标题正文语义一致性；
* 模板损坏综合判断；
* 质量总分或质量通过状态。

这些分别留给 Issues 026—030。

## 十七、Generation、Rewrite Plan、队列与恢复

定义有界 preview，至少显示：

* Draft、Brief、Topic、Experiment IDs；
* operation：FULL_GENERATION 或 REWRITE；
* profile 和 rewrite scope；
* 输入 Brief fields、lineage refs、locked fields 数量；
* 最大输入字符、输出字节、标题、block、tag 数；
* 精确最大模型请求数；
* capability、cache 和预算结论；
* 预计本地写入；
* dependency、input、lock、preview hash；
* expiry、expected revisions。

新增有限 handler：

* `COPY_GENERATE_V1`
* `COPY_REWRITE_V1`

可共享内部执行器，但必须：

* 只有桌面显式确认的 producer；
* payload 只含 ID、版本、hash、scope 和有限计数；
* executionId 幂等；
* 同 Draft 同时最多一个 active mutation；
* 模型调用期间不持有 DB 长事务；
* pause、cancel、shutdown 和 recovery 沿用 JobQueue；
* pre-send 可安全恢复；
* after-send ambiguous 不自动重发；
* 发布新版本前重验 Brief、dependency、lock、input hash；
* stale、失败、取消不替换 current version；
* result 不含 Draft 正文、Brief 内容、路径、secret 或 raw response；
* 不自动启动 Issue 026 或质量流程。

## 十八、依赖与精确失效

至少保存：

* BriefVersion、readiness、locks；
* TopicCandidate version、state、eligibility；
* Experiment Design、Assignment，可空；
* Dossier、Evidence、Authenticity dependencies 的 Brief snapshot；
* Work identities；
* profile、style、schema、prompt、policy versions；
* ModelExecution、run；
* Draft lock snapshot。

以下变化只失效相关 Draft：

* Brief current、readiness、field lock 或内容变化；
* Topic version、eligibility、hold、archive；
* Experiment design、assignment、stale；
* Dossier、Evidence、ReadingState 或 permission 导致 Brief stale；
* Work merge、split、undo；
* profile、style、schema、prompt、forbidden policy 版本变化。

要求：

* 失效幂等；
* 不自动 regenerate 或 rewrite；
* 不自动解锁；
* 不自动运行质量检查；
* 无关 Brief、Topic、Work 不触发全库 stale；
* 显式生成创建新版本；
* 相同 input 与 locks 为 deterministic no-op；
* 依赖查询有索引，不做 O(n²) 扫描。

## 十九、Migration 与仓储

追加运行时发现的下一条连续 migration；不预置版本号或 checksum，不修改历史 migration。

优先规范并扩展现有 `drafts`，避免第二套 Draft 真相。至少覆盖：

* draft identity、current version；
* immutable draft versions；
* titles、body blocks、tags、pinned comments、warnings；
* lineage refs；
* field provenance、locks；
* structural validation；
* generation、rewrite plan/run；
* prompt、model execution references；
* dependencies、invalidation；
* transition、audit。

要求：

* 真实 FK、STRICT、CHECK、unique、delete policy 和索引完整；
* current 切换事务化；
* historical versions、blocks、locks、transitions append-only；
* 旧 `drafts` 数据保守迁移为 MANUAL_DRAFT 或 STRUCTURE_INVALID，不伪装 quality-ready；
* Issues 018—024 数据完整保留；
* brief、current draft、status、block lineage、stale、generation 查询使用索引；
* 列表、详情、历史、diff 有界分页；
* 新库、升级、迁移前备份、失败回滚、quick_check、foreign_key_check 全部测试；
* DB、WAL、SHM 不保存 raw response、secret、Authorization、内部推理或绝对路径。
