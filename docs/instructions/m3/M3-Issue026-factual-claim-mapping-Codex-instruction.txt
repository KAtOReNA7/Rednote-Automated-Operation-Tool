二、授权目标
------------

实现一个版本化、可审计、可人工复核的事实映射检查：

- 对 current 且结构有效的 DraftVersion 建立精确公开文本快照；
- 把公开文案拆成可定位、可分类的原子 Statement；
- 区分事实、观点、分析判断、个人体验、修辞、标签/警告和混合/不确定表达；
- 将每条事实 Statement 映射到既有 current AtomicClaim；
- 从 Claim 回溯到 current FactEvaluation、Evidence、EvidenceLocator 和 SourceRevision；
- 对数字、日期、排名、奖项、入围、出版信息和书目身份实施强化规则；
- 对缺少有效 Claim/证据、冲突、值不一致或 scope 不一致的关键事实输出 `FACT_BLOCKED`；
- 允许用户查看并修正 Statement 边界、分类和既有 Claim 映射；
- 支持纯本地手工检查，以及经 ModelExecutionService 的可选单请求辅助分类/候选映射；
- 保存检查器、分段、分类、匹配、FactPolicy 和输入版本；
- 在 Draft、Claim、Evidence、SourceRevision 或政策变化时精确失效；
- 将完成结果以现有 `QualityCheckType.FACT_MAPPING` 接入质量记录；
- 在内容生产页面提供事实映射检查工作台；
- 为 Issue 030 保留只读、版本化的汇总输入，但不实现质量编排。

四、事实来源与语义依赖
----------------------

Issue 026 必须复用并尊重以下冻结事实：

1. Draft 来源

- 只检查一个明确 Draft identity 的一个 immutable DraftVersion；
- DraftVersion 必须具有完整 payload hash、BriefVersion、profile、Work、lineage 和 lock snapshot；
- current DraftVersion 变化不能改写历史检查；
- `STRUCTURE_INVALID`、`STALE`、`ARCHIVED` 或缺少依赖的 DraftVersion 不得产生 PASS。

2. Claim 来源

- 只能引用 Issue 019 已持久化的 AtomicClaim；
- Claim 必须具有受控 subject、predicate、类型化 value 和规范化 scope；
- 映射不能新建业务 ID，不能以自由文本伪造 Claim；
- alias/redirect 必须先解析为 current canonical entity。

3. Evidence 来源

- 只有绑定 immutable SourceRevision 和有效 EvidenceLocator 的 Evidence 可参与；
- SearchCandidate、Search snippet、模型输出、中文摘要、用户备注和无 locator 文本不能参与；
- BrowserClip 固定为 discussion/context，不能满足关键事实来源要求；
- `SUPPORTS`、`CONTRADICTS`、`QUALIFIES` 必须分别可见，不能只展示支持项。

4. FactPolicy 来源

- 关键事实只有在 current FactEvaluation 为 `VERIFIED` 时才满足；
- 一个 `OFFICIAL_PRIMARY + KEY_FACT_ELIGIBLE`，或两个已确认独立 lineage group 的
  `INDEPENDENT_SECONDARY + KEY_FACT_ELIGIBLE` 才能验证关键事实；
- unresolved material conflict、`FACT_BLOCKED`、`STALE_REVIEW_REQUIRED`、`REJECTED`、
  context-only、dependent 或未知独立性不能被映射器升级；
- Issue 026 只消费评估，不重新定义或绕过 FactPolicy。

5. Brief 与 Lineage

- DraftLineageRef 和 BriefEvidenceRef 只用于建立有界候选 allowlist；
- lineage 表示生成来源，不等于正文事实已经验证；
- lineage 中存在 Evidence ID 不能自动让 Statement PASS；
- 最终仍须验证 Statement—Claim 语义、Claim evaluation 和完整证据链。


五、检查对象与公开文本表面
--------------------------

定义 `DraftPublicArtifactV1`，只检查当前 DraftVersion 的以下实际公开文本：

- `SELECTED_TITLE`
- `BODY_BLOCK`
- `TAG`
- `PINNED_COMMENT`

以下不作为独立事实 Statement：

- `coverWarningText`
- `titleWarningMarker`
- `bodyOpeningWarningText`
- `pinnedCommentWarningText`
- 系统要求的“公开资料整理”“资料分析评分”等固定标签文本

但固定标签或警告中夹带了标签本身以外的新事实时，必须被识别为越界文本并进入人工复核，不能
利用 artifact kind 逃避检查。

`BODY_BLOCK` 是主要验收对象。标题、标签和置顶评论纳入检查，是为了防止把事实从正文移到其他
公开表面后绕过映射；这不等于实现 Issue 029 的标题正文一致性。

每个 artifact 保存或派生：

- DraftVersion ID；
- artifact kind；
- stable artifact ID；
- block/tag order，可空；
- 规范化文本 hash；
- Unicode code point 长度；
- profile、Work 和 Brief lineage allowlist；
- 只读 currentness。

不得把整篇 Draft 复制到 job payload、audit、普通日志、诊断或错误 DTO。


六、精确文本定位器
------------------

定义 `DraftTextLocatorV1`：

- `draftVersionId`
- `artifactKind`
- `artifactId`
- `textHash`
- `startCodePoint`
- `endCodePoint`
- `locatorVersion`
- `selectedTextHash`

规则：

- 区间为 Unicode code point 闭开区间；
- 创建和读取时从 immutable DraftVersion 的 artifact 文本重新切片并校验；
- artifact ID、文本 hash、区间或 selected text hash 任一不一致即 fail closed；
- 空区间、越界、重叠冲突和跨 artifact locator 被拒绝；
- 中文、日文、英文、emoji、组合字符和 CRLF/LF 规范化有专项测试；
- 数据库保存 locator 与 hash，不重复保存整段 Draft 文本；
- renderer 通过受限详情接口取得当前 Draft 中的有界片段，不从检查记录读取复制正文。


七、Statement 原子化
--------------------

定义 immutable `DraftStatementV1`。每条 Statement 必须：

- 只属于一个 DraftVersion 和一个 artifact；
- 具有一个精确 DraftTextLocator；
- 对应一个最小、可独立判断的语义断言或非事实表达；
- 记录 segmentation policy/version、provenance、revision 和 createdAt；
- 记录 statement text hash，但不在普通日志或队列中保存全文；
- 不跨 block、标题、标签或评论；
- 不把多个主语、谓词、值或 scope 的事实强行合成一个 Statement。

原子化规则：

- “A 获奖并于 2024 年出版”必须拆成至少两个 Statement；
- 一个包含多个作品的事实比较，优先映射到既有关系 Claim；没有该 Claim 时必须拆分或待复核；
- 事实与观点混合的句子必须拆分；无法无损拆分时标记 `MIXED`；
- 引号内原话与“某人曾这样说”的归属事实分开处理；
- 文本中的段落序号、列表序号和排版数字不自动成为事实；
- 完整诡计分析允许存在 plot/structure Statement，但仍按事实或分析判断分类；
- 分段器不得改变 Draft 文本。

Statement provenance 至少包括：

- `DETERMINISTIC`
- `MODEL_CANDIDATE`
- `USER_DEFINED`
- `USER_CONFIRMED`

模型候选永远不是最终用户确认，也不能直接产生质量 PASS。


八、事实性分类合同
------------------

定义有限 `StatementKindV1`：

- `FACT`
- `OPINION`
- `ANALYTICAL_JUDGMENT`
- `PERSONAL_EXPERIENCE`
- `RHETORICAL`
- `LABEL_OR_WARNING`
- `MIXED`
- `AMBIGUOUS`

定义 `FactMaterialityV1`：

- `KEY_FACT`
- `SUPPORTING_FACT`
- `NOT_APPLICABLE`

定义 `FactDomainV1`：

- `BIBLIOGRAPHIC`
- `AWARD`
- `NUMERIC`
- `DATE_TIME`
- `RANKING`
- `QUOTATION_ATTRIBUTION`
- `PLOT_OR_STRUCTURE`
- `INDUSTRY_OR_MARKET`
- `CREATOR_OR_PUBLISHER`
- `OTHER`
- `NOT_APPLICABLE`

分类规则：

- `FACT` 必须具有 materiality 和 domain；
- 其他 kind 的 materiality/domain 必须为 `NOT_APPLICABLE`，除非处于待拆分的 `MIXED`；
- `OPINION` 表达喜恶、价值判断或推荐，不因没有 Claim 而失败；
- `ANALYTICAL_JUDGMENT` 是可争论的结构/逻辑解释，不得伪装为外部事实；
- `PERSONAL_EXPERIENCE` 只表示本轮不做事实映射，仍必须留给 Issue 027 检查；
- `RHETORICAL` 不得包含可独立核验的对象、值和归属；
- `LABEL_OR_WARNING` 只能是系统冻结标签或纯警告；
- `MIXED` 和 `AMBIGUOUS` 不能 PASS，必须拆分或人工确认；
- 模型不得把具有受保护事实信号的文本静默降级为观点、修辞或标签。

分类与“真伪”分离：Statement 是 FACT 不表示其内容为真；是否可公开由 Claim、FactEvaluation 和
Evidence 链决定。


九、关键事实与受保护信号
------------------------

定义版本化 `KeyFactPolicyV1`。以下通常为关键事实：

- 书名、原名、译名、作者、译者、出版社、版本、ISBN、出版/连载时间；
- 获奖、入围、提名、榜单、排名和评委/奖项身份；
- 明确数字、百分比、金额、销量、播放量、下载量、评分、样本量或市场份额；
- 日期、时间区间、先后顺序和“首部/首次/唯一/最高”等可核验断言；
- 对作者、出版社、奖项、改编、版权交易或产业主体的具体行为归属；
- 引语及其说话人、场合和时间归属；
- 会显著影响读者理解、购买判断或作品比较结论的书目、情节或结构事实。

受保护信号 detector 至少覆盖：

- 阿拉伯数字、中文数字、百分号、货币和单位；
- 年/月/日与有限日期表达；
- 第一、TOP、排名、销量、冠军、入围、获奖、提名等版本化词表；
- ISBN、书名号和明确书目身份组合；
- 中文、日文和英文有限奖项/排名提示词；
- 断言性引用归属。

规则：

- detector 只产生“必须分类/复核”的信号，不单独证明 Statement 是事实或真实；
- “我给这本书 8 分”可以被确认是观点/个人评分，但不能被 detector 静默忽略；
- 列表序号、章节号、标题中作品固有数字和固定警告不得误判为数值事实；
- 模型不能独自移除 protected signal；
- 用户把 protected signal 确认为非事实时必须给出有界 reason，并保留 audit；
- 数字、日期、奖项和排名事实不得只做文本相似匹配，必须校验类型化值和 scope。


十、Claim 候选集合
------------------

定义有界 `ClaimCandidateSetV1`，按以下顺序构建：

1. Draft artifact 的 DraftLineageRef 所允许的 BriefEvidenceRef；
2. BriefVersion 的 required/current EvidenceRef；
3. 上述 Evidence 实际所属的 current AtomicClaim；
4. Draft/Brief 所绑定 canonical Work、Expression、Edition、Agent 的 current Claim；
5. 对 cross-work profile，分别按每个 Work 构建，禁止跨作品借用。

候选集合必须：

- 全部来自本地已持久化记录；
- 记录构建 policy/version 和 input hash；
- 有固定最大 Claim、Evidence、SourceRevision 和字符数量；
- 按 canonical subject、predicate、scope 和稳定 ID 确定性排序；
- 去除 duplicate/redirect 后保留 provenance；
- 过滤 deleted/unavailable/rejected 记录；
- 保留 conflicted/stale 候选供 UI 解释，但不得满足 PASS；
- 不读取 Source 全文进入 renderer；
- 不执行 Search、Fetch、模型联网或新增研究任务。

候选集为空不是自动创建 Claim 的理由；对应事实进入 `NO_CLAIM`。


十一、Statement—Claim 映射
---------------------------

定义 immutable `StatementClaimMappingV1`。一个原子 FACT Statement 在 V1 最终只能由一个 current
AtomicClaim 满足；如果需要多个 Claim 才能表达，必须先拆分 Statement，或使用已有的关系 Claim。

`MappingRelationV1` 至少包括：

- `EXACT`
- `SUPPORTED_PARAPHRASE`
- `NARROWER_THAN_CLAIM`
- `BROADER_THAN_CLAIM`
- `VALUE_CONFLICT`
- `SCOPE_MISMATCH`
- `SUBJECT_MISMATCH`
- `PREDICATE_MISMATCH`
- `MULTIPLE_CANDIDATES`
- `NO_CLAIM`
- `STALE`
- `NOT_APPLICABLE`

只有以下 relation 可以进入满足判定：

- `EXACT`
- 经过本地约束和人工确认的 `SUPPORTED_PARAPHRASE`
- Statement 确实比 Claim 更窄、且没有引入新值/新 scope 的 `NARROWER_THAN_CLAIM`

以下永远不能 PASS：

- `BROADER_THAN_CLAIM`
- 任意 value/scope/subject/predicate mismatch；
- multiple candidates 未解决；
- no claim；
- stale；
- 把相似措辞误当语义支持。

映射保存：

- Statement ID/version；
- Claim ID/revision；
- current FactEvaluation ID/revision/policy version；
- relation；
- candidate provenance；
- mapper provenance；
- decision reason，可空；
- input/semantic hash；
- createdAt。

不得复制 Claim 的自由文本值、Evidence 正文或 Source 正文到普通 mapping details JSON。


十二、类型化值、数字、日期和奖项校验
------------------------------------

实现本地、确定性的 `TypedFactCompatibilityV1`：

- `INTEGER` 使用整数；
- `DECIMAL_TEXT` 使用规范十进制字符串，不使用浮点；
- 百分比保留原始单位与规范值；
- 金额必须保留币种和量级；
- 日期保留 `YEAR / MONTH / DAY` 精度；
- range、before/after 和大约值不得被精确值替代；
- identifier 必须精确规范化；
- entity ref 先解析 canonical identity；
- enum 和 boolean 必须匹配 registry；
- scientific notation、NaN、Infinity 和不可解析值被拒绝。

数字规则：

- Statement 中每个事实数字都必须被对应 Claim value/scope 消费；
- Claim 中存在数字但 Statement 省略，不必失败；
- Statement 新增 Claim 没有的数字、单位、排名或比较级时为 `VALUE_CONFLICT` 或
  `BROADER_THAN_CLAIM`；
- 不允许用“约”“超过”“不足”等限定词掩盖精确不一致。

日期规则：

- 日期按 Issue 019 精度语义比较；
- `2024` 可与更精确日期兼容，但 Statement 不能凭较粗 Claim 宣称具体到日；
- 不同月份、年份或不兼容区间必须失败。

奖项规则：

- 作品/作者/译者主体必须匹配；
- “获奖”“入围”“提名”“候选”“榜首”是不同 predicate，不得互换；
- 奖项届次、年份、类别和 territory/language scope 必须兼容；
- 媒体书单、销售榜和正式奖项不得互换；
- 只有 current verified Claim 的证据链可以满足。


十三、Evidence 与 SourceRevision 回溯
------------------------------------

每个可满足的映射必须可确定性展开为：

`DraftTextLocator → DraftStatement → AtomicClaim → FactEvaluation
→ Evidence → EvidenceLocator → SourceRevision → Source`

UI 和详情 DTO 至少显示：

- Statement 有界片段；
- Claim subject/predicate/类型化 value 的安全格式化摘要；
- FactEvaluation 状态、policy version 和 observedAt；
- 每条 Evidence 的 supports/contradicts/qualifies；
- Source 分类、独立性、lineage group、语言、标题/站点；
- SourceRevision ID、content hash 摘要和 currentness；
- 有界精确 evidence excerpt；
- 中文摘要仅以“非证据摘要”展示，不参与通过计数。

规则：

- 不把 source URL、完整网页正文或受控文件绝对路径放入普通列表 DTO；
- 需要查看来源时只通过已有安全来源详情能力，Issue 026 不新增任意 URL 打开器；
- Evidence locator 在读取时重新验证；
- 任何 contradicting evidence、material conflict 或 unavailable/retracted revision 必须可见；
- 两个二级来源必须展示独立 lineage group，不能只显示“2 个来源”；
- 映射器不能自行改变 Source 分类、独立性或 FactEvaluation。


十四、检查结果与状态机
----------------------

定义 `FactMappingCheckV1` 稳定 identity，绑定一个 Draft identity；定义 immutable
`FactMappingCheckVersionV1`，每个版本绑定一个明确 DraftVersion。

`FactMappingRunStatusV1`：

- `PLANNED`
- `QUEUED`
- `RUNNING`
- `AWAITING_REVIEW`
- `PASS`
- `FACT_BLOCKED`
- `FAILED`
- `CANCELLED`
- `AMBIGUOUS`
- `STALE`
- `SUPERSEDED`

`StatementDispositionV1`：

- `SATISFIED`
- `NOT_APPLICABLE`
- `NEEDS_REVIEW`
- `BLOCKING_KEY_FACT`
- `UNMAPPED_SUPPORTING_FACT`
- `CONFLICTED`
- `STALE`

聚合规则：

- `PASS`：所有 in-scope artifact 已覆盖；所有 FACT Statement 都映射到 current verified Claim；
  所有非事实分类已确定；没有 MIXED、AMBIGUOUS、冲突、stale 或未检查 protected signal；
- `FACT_BLOCKED`：至少一个 KEY_FACT 为 no claim、invalid mapping、非 VERIFIED、冲突、
  unavailable、stale 或类型化值/scope 不匹配；
- `AWAITING_REVIEW`：存在 MIXED、AMBIGUOUS、multiple candidates、待拆分或 supporting fact
  尚未解决；
- `FAILED`：本地校验、持久化或 pre-send 技术失败；
- `AMBIGUOUS`：模型请求可能已发送但无法确认结果，不能自动重发；
- `STALE`：依赖快照变化；
- `CANCELLED` 不产生 PASS/FAIL；
- historical check version 不原地更新。

`AWAITING_REVIEW` 不是 PASS。用户完成复核后必须创建新的 immutable check version 或 decision
revision，再重新本地汇总。


十五、与现有 QualityCheck 的集成
--------------------------------

复用现有：

- `QualityCheckType.FACT_MAPPING`
- `QualityCheckOutcome.PASS`
- `QualityCheckOutcome.FAIL`

不新增第二个事实检查类型，不改变其他七类 QualityCheckType。

权威数据：

- Statement、Mapping、Dependency、Decision 和 FactMappingCheckVersion 是 Issue 026 的详细真相；
- `quality_checks` 只保存对某个 DraftVersion、checker version 和 run 的汇总桥接记录；
- PASS 只对应 FactMappingCheckVersion `PASS`；
- `FACT_BLOCKED` 和完成后的 `AWAITING_REVIEW` 对应 QualityCheckOutcome `FAIL`，severity/reason
  使用有限 registry；
- technical FAILED、CANCELLED、AMBIGUOUS、STALE 不得伪造成质量 FAIL 或 PASS；
- 相同 DraftVersion + FACT_MAPPING + checker version + input hash 幂等；
- 新 DraftVersion 不继承旧 DraftVersion 的 PASS；
- Issue 026 不根据单项 PASS 推进 Draft、Content、Approval 或 Export 状态。

如果现有 `quality_checks` 无法精确绑定 DraftVersion/run，必须通过下一条 migration 保守扩展或
重建，并完整保留旧行；不得用无限 `details_json` 或拼接 checker version 绕过真实关系。


十六、手工检查与人工复核
------------------------

无模型配置时必须完整可用：

- 从 READY DraftVersion 建立 deterministic artifact snapshot；
- 本地 detector 标出 protected signals；
- 用户逐条建立或调整 Statement 边界；
- 用户把 Statement 分类为 FACT、OPINION、ANALYTICAL_JUDGMENT 等；
- 对 FACT 从有界 ClaimCandidateSet 中选择既有 Claim；
- 查看 Claim—Evidence—SourceRevision 链；
- 确认、撤销、重新分类、拆分和重新映射；
- 重新运行本地 compatibility 与 FactPolicy 汇总；
- 形成 PASS、FACT_BLOCKED 或 AWAITING_REVIEW。

人工操作必须：

- preview 显示 before/after、DraftVersion、locator、classification、Claim、evaluation 和结果影响；
- 使用 expected revision、preview hash、sender/window 绑定的短期单次 token；
- protected signal 被改为非事实时要求有界非空 reason；
- mapping 到非 current、非候选、非 VERIFIED 或不兼容 Claim 时拒绝；
- undo/reopen 创建新 decision，不改写历史；
- stale revision、重复消费和并发竞争 fail closed；
- audit 只保存 ID、枚举、hash、reason code 和有限 reason，不保存整篇 Draft 或 Source 正文。

Issue 026 不提供“忽略事实检查”“强制通过”“把冲突当作通过”等绕过开关。

十九、依赖与精确失效
--------------------

每个 check version 至少保存：

- Draft identity、DraftVersion、payload/artifact hashes；
- BriefVersion、BriefEvidenceRef 和 DraftLineageRef snapshot；
- Work/Expression/Edition/Agent canonical identities；
- AtomicClaim ID/revision/semantic fingerprint；
- FactEvaluation ID/revision/policy/input hash；
- Evidence ID/revision/locator/hash；
- Source/SourceRevision ID、revision、content hash、availability；
- conflict decision revision；
- alias/merge/split/redirect revision；
- segmentation/classification/keyFact/mapping/checker policy versions；
- 可选 ModelExecution/run。

失效规则：

- 新 DraftVersion 不改写旧检查；旧检查保留历史并变为非 current，新版本状态为未检查；
- 目标 DraftVersion 本身不可变，如 hash 不匹配则 fail closed；
- Claim value/scope/status/revision 变化只失效引用该 Claim 的检查；
- Evidence、SourceRevision、classification、independence、lineage 或 availability 变化只失效其
  依赖检查；
- material conflict resolve/undo/reopen 精确失效相关检查；
- Work merge/split/undo/redirect 精确失效关联 subject；
- FactPolicy、predicate registry、value schema 或本 Issue policy version 变化使匹配输入失效；
- 无关 Draft、Work、Claim 或 Source 变化不触发全库 stale；
- 失效幂等，不自动重跑、不自动改 Draft、不自动研究；
- stale 查询、反向依赖和 current check 查询必须有索引，禁止 O(n²) 全库扫描。
