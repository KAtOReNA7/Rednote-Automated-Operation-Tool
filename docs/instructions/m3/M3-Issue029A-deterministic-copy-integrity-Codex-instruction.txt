五、DUPLICATION 规则

1. 使用 NFC、LF 与冻结 whitespace 规范化，结果版本化。
2. 检查当前稿内 public artifact 的 exact duplicate，并返回当前稿 Unicode code-point locator、artifact identity、hash、reason 与有限修改建议；不得复制完整正文。
3. 检查不同 draft root 之间完整 public-artifact 集合的规范化 exact duplicate。
4. 同一 draft root 的旧版本只是历史上下文，不因正常版本继承自动 BLOCK、删除或归档。
5. 有界 Unicode shingle/containment 只产生可解释候选与 `REVIEW_REQUIRED`；任何单一相似度阈值均不得自动删除、改写、归档或推进内容。
6. eligible historical DraftVersion 必须按冻结条件和稳定 tie-break 确定性排序，以 indexed eligibility + LIMIT(cap+1) 读取。
7. corpus 超 cap 时 `truncated=true`，记录总量/已比较量并进入 `REVIEW_REQUIRED`；不得静默 PASS，也不得全库 pairwise materialization。
8. finding 数量、artifact 数量、shingle 数量、扫描 code points、候选数与 details_json 均有硬上限。

六、TITLE_BODY_CONSISTENCY 规则

1. 只使用权威 workId、Brief field/argument/slot lineage、选中标题与 materialized body surface 信号。
2. 对 title/body 的 lineage 覆盖、完全不相交、缺失或结构上不可能的引用给出 bounded reason、artifact/hash/locator。
3. 只有权威合同能证明的结构矛盾才可 `BLOCKED`；语义不确定、lineage 缺失或 lexical 可疑一律 `REVIEW_REQUIRED`。
4. 不声称理解隐喻、修辞、同义表达或完整主题语义。
5. 事实冲突继续由 Issue 026 Fact Mapping 独占；普通观点争议不得变成本检查门禁。

七、publication 与历史真相

1. publication 为 0 时，记录 eligible published baseline count=0。
2. 存在 publication 且能解析到精确不可变 DraftVersion 时，才允许纳入 corpus。
3. publication 只能连接 draft root/current head、不能解析发布时精确版本时，返回 `PUBLISHED_BASELINE_UNAVAILABLE` / `REVIEW_REQUIRED`。
4. 绝不能把当前 draft head 冒充历史发布正文，也不得在本 Issue 新增 Schema 修补该缺口。

八、状态、持久化与 freshness

每个已实现 check 单独保存和显示：`PASS / BLOCKED / REVIEW_REQUIRED`；`STALE / NOT_RUN` 为查询派生态。

1. 复用 `quality_checks`，0 Schema 变更。
2. 每个 summary id 由 checkType + exact draftVersionId + checkerVersion + inputHash 内容寻址。
3. 只执行 INSERT OR IGNORE，随后逐字段 read-back；不一致 fail closed。不得 UPDATE/DELETE 历史 summary。
4. preview 完全只读，externalRequestCount=0，costState=`NOT_APPLICABLE`。
5. confirm token 绑定 senderFrame/origin/window、draft root/revision/version、preview hash、input hash、短 TTL 与单次消费。
6. confirm 在写事务前重新 prepare；draft head、revision、Brief、history corpus、publication、policy 或 checker 变化都拒绝旧 token。
7. 输入 hash 至少覆盖：
   - contract/checker/policy/corpus-selection 版本；
   - draftId、revision、draftVersionId、contentHash；
   - briefVersionId、Brief input/dependency/lock hashes；
   - materialized artifact identity/hash/lineage；
   - eligible corpus 的完整计数、truncated、稳定排序及 versionId/contentHash 集合；
   - publication 计数、精确 published version 集合和 unavailable-lineage 标记；
   - exact-current Issue 025 structural truth identity。
8. input hash 不得包含时间戳、随机值、原文、AI 标识、版权风险、模型、密钥或机器路径。

九、数据最小化与安全

1. details_json、IPC、日志、audit、诊断和证据文档不得保存/输出完整正文、历史 payload、密钥、请求头、绝对路径或 SQL。
2. finding 只含 allowlist identity、hash、code-point locator、reason、计数、截断状态和规则版本。
3. Renderer 只能通过两条窄 preload 方法，不能导入 Node/Electron/SQLite/fs/net/crypto。
4. IPC exact-object 校验、大小限制、sender frame/origin/BrowserWindow 绑定必须保持。
5. AI 标识固定为 false，且 AI 参与度不进入 hash、状态、评分、审批、优先级、排期或导出。
6. 版权风险完全不进入字段、check type、hash、状态、评分、审批、优先级或排期。
