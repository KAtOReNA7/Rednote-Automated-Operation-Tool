## 四、Experiment Design V1

定义严格、版本化的合同：

* `Experiment`
* `ExperimentDesignVersion`
* `ExperimentHypothesis`
* `PrimaryVariable`
* `ExperimentArm`
* `ControlledCondition`
* `MetricSpec`
* `GuardrailSpec`
* `SamplePlan`
* `StratificationPlan`
* `AssignmentPlan`
* `AssignmentUnit`
* `ExperimentDependency`

Experiment 是稳定 identity；所有可执行设计存在 immutable version。

同一 Experiment 只能有一个 current design version，但必须保留完整历史。current 切换使用 expected revision、事务和 append-only audit。

设计版本至少保存：

* experiment/design identity；
* hypothesis；
* primary variable；
* arms；
* controlled conditions；
* primary metric；
* guardrails；
* sample/stratification/assignment plan；
* dependency hash；
* schema/policy versions；
* design status、revision、previous version；
* createdAt、lockedAt、archivedAt；
* bounded warnings/reasons。

历史设计不得原地覆盖或物理删除。

## 五、可检验假设

`ExperimentHypothesisV1` 至少包含：

* target audience/context；
* intervention；
* comparator；
* expected direction；
* primary outcome；
* rationale；
* falsification condition；
* scope；
* bounded assumptions。

要求：

* 假设必须能被未来明确指标反驳；
* 不接受“效果更好”“更容易爆”但没有指标和方向的空假设；
* 不声称实验一定成功；
* rationale 可以引用 Topic/Dossier，但不是事实证据的替代物；
* 不把模型置信度当作假设强度；
* 不把当前没有的运营数据伪造成 baseline；
* UI 明确显示“实验尚未执行，无效果结论”。

## 六、一次实验只允许一个主要变量

定义有限、版本化 `ExperimentVariableRegistryV1`，至少可描述：

* `CONTENT_STRUCTURE`
* `TITLE_PATTERN`
* `COVER_INFORMATION_DENSITY`
* `SPOILER_MODE`
* `COMPARISON_FORMAT`
* `PUBLICATION_TIME_WINDOW`

Issue 023 只建立设计合同，不实现未来标题、图片、排期等具体生产能力。未实现能力对应的变量可以保存为 future-bound design intent，但不得显示为已经生成。

PrimaryVariable 必须：

* 精确一个 variable kind；
* 至少两个、至多有限数量的 arms；
* 每个 arm 有唯一有限 value identity；
* 明确 control arm；
* 只改变一个主要维度。

ControlledCondition 必须记录其他关键维度保持方式，例如：

* Topic content type；
* analysis mode；
* spoiler requirement；
* 内容结构（若不是 primary variable）；
* 作品热度分层；
* 发布窗口（若不是 primary variable）；
* 未来视觉或标题策略的固定或未实现状态。

验证器必须拒绝：

* 同时改变标题模式和封面密度；
* control/treatment 在多个主要字段上不同；
* 没有 control；
* 重复 arm；
* arm value 不属于对应 registry；
* 把 Work identity 当作 primary variable；
* 把 AI 标识、版权或出版归属当作实验变量。

若用户确需多变量测试，必须拆成多个 Experiment，不在 V1 中实现 factorial design。

## 七、Replication Structure 与跨三本书复现

定义 `ReplicationStructureV1`，只描述实验结构意图，不是 Content Brief：

* structure identity/version；
* Topic content type；
* analysis mode；
* spoiler level；
* structural slots/sequence 的有限标识；
* comparison dimension，可空；
* required labels；
* semantic fingerprint。

规则：

* 同一 structure fingerprint 必须应用于至少 3 个不同 Work，才能标记 `REPLICATION_READY`；
* 三本书必须是 canonical Work identity 不同；
* 同一 Work 的不同 Edition 不能冒充三本书；
* 每个 Work 的 Topic 必须 current、eligible 且未 archived/held；
* Topic 的内容类型、模式、剧透和结构必须与实验设计兼容；
* 对同一结构只换书名或事实输入是允许的复现；
* 不要求三本书热度相同，但必须记录热度 strata；
* 少于三本时设计保持 `INSUFFICIENT_REPLICATION`；
* 不为凑数复制 Topic 或 semantic fingerprint。

Issue 023 只验证结构可复现和样本计划；实际 Brief 要到 Issue 024。

## 八、作品热度分层

定义有限 `WorkPopularityStratumV1`：

* `HOT`
* `WARM`
* `COLD`
* `UNKNOWN`

热度只是实验分层字段，不是事实门禁、Topic eligibility 或 ranking 的替代物。

每个非 UNKNOWN 分层必须带：

* observation/source kind；
* observedAt/window；
* bounded metric or category reference；
* provenance；
* confidence/availability；
* policy version。

冻结规则：

* 当前没有真实运营数据时默认 `UNKNOWN`；
* 不根据模型记忆、书名知名度或出版社身份自动推断；
* UNKNOWN 不等于 COLD；
* 测试使用明确 synthetic fixture；
* 用户可手工确认有限分层，但必须显示依据和时间窗口；
* 分层变化使相关 AssignmentPlan stale，不自动重排；
* 热度不参与 AI 标识、版权、真实性或事实政策；
* 不在 Issue 023 建立真实平台热度抓取或数据导入。

## 九、指标与护栏合同

定义版本化 `MetricRegistryV1` 和严格 MetricSpec。

Primary metric 精确一个，至少可描述：

* metric identity/version；
* numerator；
* denominator，可空；
* unit；
* observation window；
* missing-value policy；
* zero-denominator policy；
* direction；
* availability state。

有限 availability：

* `DEFINED_NOT_AVAILABLE`
* `AVAILABLE_FOR_FUTURE_COLLECTION`
* `UNSUPPORTED`

当前尚未实现 M5 数据回收，因此 Issue 023 的真实指标默认不能显示为已有数据。

可在 registry 中定义未来候选，例如：

* `SAVE_RATE`
* `COMMENT_RATE`
* `FOLLOW_CONVERSION_RATE`
* `ENGAGEMENT_RATE`
* `PROFILE_VISIT_RATE`
* `APPROVAL_WORK_UNITS`
* `FACT_BLOCK_RATE`

但必须：

* 明确哪些依赖未来平台数据；
* 不伪造 numerator、denominator、baseline 或 effect size；
* 缺失与 0 严格区分；
* 不为无效分母计算 rate；
* 不计算当前结果。

Guardrail：

* 可以有 0—有限数量；
* 不能与 primary metric 重复；
* 必须定义方向和违反条件；
* 只记录未来判断规则；
* 不自动阻止 Topic、Brief 或发布，因为执行链尚不存在；
* 不包含 AI 标识或版权风险。

## 十、样本计划

定义 `SamplePlanV1`：

* assignment unit；
* target Topic/Work set；
* inclusion/exclusion rules；
* arm target counts；
* minimum distinct Work count；
* replication requirement；
* popularity strata；
* deterministic seed；
* blocking keys；
* sample warnings；
* plan status。

V1 assignment unit 必须基于 Issue 022 TopicCandidate，并保留 canonical Work identity。

计划状态至少包括：

* `DRAFT`
* `INSUFFICIENT_SAMPLE`
* `INSUFFICIENT_REPLICATION`
* `UNBALANCED`
* `READY_TO_LOCK`
* `STALE`

冻结规则：

* 至少 3 个不同 Work 复现同一 structure；
* Topic 必须 current、eligible，且不处于 HELD/ARCHIVED；
* 同一 Topic 只能进入一个 arm；
* 同一 Work 在同一实验中的重复使用受版本化上限约束；
* FIRST_30 plan membership 可作为纳入条件，但不能被实验自动修改；
* 数量不足时返回 shortfall，不复制样本；
* 当前 30 篇样本较小时必须显示有限性，不得声称统计功效充足；
* 未有历史 effect size 时不得伪造 power 或 minimum detectable effect；
* 样本计划不等于发布排期。

## 十一、分层和确定性分配

实现 `AssignmentPolicyV1`：

1. 校验所有 Topic eligibility/current dependencies；
2. 按 content type、popularity stratum 和必要 blocking key 分层；
3. 使用保存的 deterministic seed 和稳定 tie-break 分配 arms；
4. 尽可能平衡每个 arm 的 Work 数和 strata；
5. 输出 imbalance、shortfall 和 reason；
6. 不静默放宽 inclusion/exclusion；
7. 不自动改变用户 LOCKED Topic 状态。

每个 AssignmentUnit 至少保存：

* Topic/version；
* Work identity；
* structure fingerprint；
* assigned arm；
* popularity stratum snapshot；
* blocking key；
* assignment order/reason；
* dependency versions。

要求：

* 相同输入、seed 和 policy 得到完全相同分配；
* 输入乱序不改变结果；
* seed 不是密钥，但必须稳定保存；
* 分层不足时 fail visibly，不把 UNKNOWN 静默并入 HOT/COLD；
* 不把 ranking score 当作实验结果；
* 不使用随机试到“平衡”为止的不可复现算法；
* 分配算法复杂度有界，不做 O(n²) 全库比较。

## 十二、Experiment 状态机

Experiment/Design 状态至少包括：

* `DRAFT`
* `VALIDATED`
* `ASSIGNMENT_READY`
* `LOCKED`
* `HELD`
* `ARCHIVED`
* `SUPERSEDED`
* `STALE`

本 Issue 不使用 `RUNNING`、`COMPLETED`、`WINNER` 等暗示真实执行或结果的状态。

支持：

* create draft；
* validate；
* preview assignment；
* confirm/lock；
* hold/resume；
* clone as new version；
* archive/restore。

规则：

* LOCKED 只表示设计与分配冻结，不表示已发布或开始实验；
* 锁定后内容变更必须 clone 新版本，不能原地改写；
* expected revision、preview hash、显式确认；
* sender/window 绑定、短期、单次 token；
* append-only transition/audit；
* 并发 stale fail closed；
* 旧版本保留；
* 不自动触发 Brief、Draft、排期或模型任务。

## 十三、依赖与失效

保存精确 dependency，至少包括：

* TopicCandidate version/state/eligibility；
* TopicQuotaPlan version，可空；
* Work identity；
* Dossier/ExpressionPermission snapshot identity；
* structure fingerprint/version；
* variable/metric/assignment policy versions；
* popularity stratum snapshot；
* experiment design version。

以下事件只使相关设计或分配 stale：

* Topic eligibility、version、hold/archive 变化；
* TopicQuotaPlan current version 变化；
* Work merge/split/undo；
* Dossier 或真实性权限失效；
* structure/variable/metric/assignment policy version 变化；
* popularity stratum 变化。

要求：

* 失效幂等；
* 不自动重新分配；
* 不自动解锁；
* 显式重建生成新 assignment/design version；
* 相同输入为 deterministic no-op；
* 无关 Topic/Work 变化不触发全库 stale；
* stale design 不能标记 READY/LOCKED；
* 关键依赖查询使用索引。
