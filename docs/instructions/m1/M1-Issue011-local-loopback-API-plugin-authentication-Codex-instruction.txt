packages/local-api

- 稳定错误 DTO；

六、监听地址、端口与生命周期
----------------------------

唯一允许的监听地址：

127.0.0.1

禁止：

- localhost；
- 0.0.0.0；
- ::；
- ::1；
- 任意 LAN IP；
- 任意公网 IP；
- named pipe；
- Unix socket；
- remote tunnel；
- proxy；
- 端口转发；
- Windows 服务；
- 防火墙规则修改。

使用用户可配置固定端口，而不是每次启动随机端口。默认：

43119

合法范围：

1024—65535。

原因：

- 浏览器插件需要跨应用重启后稳定找到本地服务；
- PRD 允许动态端口或用户配置；
- 不进行端口扫描或服务发现；
- 端口不是秘密。

服务默认关闭。用户必须在设置页明确启用“本地插件连接”。首次启用时：

1. 验证本地项目已就绪；
2. 验证设置和 DB 可用；
3. 以 host=127.0.0.1、配置端口启动；
4. 读取 server.address()；
5. 精确断言 address=127.0.0.1、family=IPv4、port=配置值；
6. 任一不符立即关闭并返回稳定错误。

端口冲突：

- 返回 LOCAL_API_PORT_IN_USE；
- 不静默选择其他端口；
- 不覆盖用户配置；
- 不重试一串端口；
- UI 提示用户修改端口；
- 旧服务状态保持确定。

修改端口采用两阶段流程：

1. 验证新端口；
2. 停止旧 listener；
3. 尝试绑定新端口；
4. 成功后持久化新设置；
5. 持久化失败时关闭新 listener，并尽力恢复旧 listener；
6. 无法恢复时进入 ERROR_RESTART_REQUIRED，不伪装运行。

服务状态至少包括：

- DISABLED
- DISABLED_NO_PROJECT
- STARTING
- RUNNING
- STOPPING
- PORT_IN_USE
- ERROR
- ERROR_RESTART_REQUIRED

Electron app.whenReady() 后才允许组装和启动。关闭顺序：

1. 停止接受新请求；
2. 取消所有 pairing session；
3. server.close()；
4. 在限定时间后 closeAllConnections()；
5. 清理 socket registry、timer 和 rate limit state；
6. 确认端口已释放；
7. 再关闭 DB 和 app。

应用退出后不得残留 Electron、Node、listener 或端口占用。

八、插件 token 与配对协议
------------------------

未来插件安装时自行生成 32-byte CSPRNG token。Issue 011 不实现插件，只用运行时测试
客户端模拟该行为。

配对流程：

1. 用户在桌面设置页点击“开始配对”。
2. main 生成 32-byte base64url pairing code。
3. pairing code：
   - 只存在内存；
   - TTL 默认 120 秒；
   - 单次使用；
   - 绑定当前 listener instance、port 和发起窗口；
   - 最多 5 次失败尝试；
   - 取消、超时、服务停止或窗口销毁时立即失效。
4. UI 可以暂时显示并复制 pairing code、端口和到期时间。
5. UI 不显示、复制或接收长期插件 token。
6. 测试客户端向 POST /v1/pairings/exchange 提交：
   - pairingCode；
   - extensionOrigin；
   - clientToken；
   - 可选 clientLabel。
7. HTTP Origin header 必须与 body 中 extensionOrigin 精确一致。
8. pairing code 验证通过后：
   - 规范化 origin；
   - 对 clientToken 计算 digest；
   - SQLite 事务写入 client；
   - 同 origin 重新配对时原 active token 立即失效；
   - pairing code 立即销毁。
9. 响应只返回：
   - paired=true；
   - clientId；
   - apiVersion；
   - createdAt。
10. 响应绝不返回 token、digest 或 pairing code。

重新配对同一 origin 等同于安全轮换。旧 token 必须立即得到 401。

撤销：

- 用户在设置页明确确认；
- 只传 clientId，不传 token 或 digest；
- 设置 revoked_at；
- 后续请求立即 401；
- 不因 last_used 更新恢复；
- 可重新配对形成新 active client。

最多允许 8 个 active client。超过后拒绝配对，用户需先撤销。

十、Host、Origin 与 CORS
-----------------------

Host：

- 必须只有一个 Host header；
- 值必须精确等于 127.0.0.1:<actualPort>；
- 拒绝 localhost；
- 拒绝 0.0.0.0；
- 拒绝 [::1]；
- 拒绝其他 IP、域名、尾点、userinfo 和异常端口；
- 拒绝绝对形式 request-target 指向其他 host；
- 用于降低 DNS rebinding 和错误代理风险。

remote address：

- socket.remoteAddress 必须是 127.0.0.1；
- 其他值全部拒绝；
- 不相信 X-Forwarded-For、Forwarded、X-Real-IP；
- 不启用 trust proxy。

Origin：

- 所有应用 route 都必须有且只有一个 Origin；
- 只接受 chrome-extension://<32 位 a—p 小写 id>；
- 拒绝 null、file、http、https、moz-extension 和缺失 Origin；
- pairing 时允许当前有效 pairing session 的合法 Chromium origin；
- auth route 只允许与 active client 精确匹配的 origin；
- token 和 origin 必须同时匹配。

CORS：

- 不使用 Access-Control-Allow-Origin: *；
- 不使用 Access-Control-Allow-Credentials: true；
- 只对通过验证的精确 origin 回显 ACAO；
- 加 Vary: Origin；
- allow methods 只列实际 route；
- allow headers 只允许 authorization、content-type；
- expose headers 默认空；
- preflight max age 不超过 300 秒；
- 非法 preflight 不返回 ACAO；
- OPTIONS 是浏览器预检，不产生业务数据；它不使用 Bearer token，但必须通过 Host、
  remote address、Origin、request method 和 request headers 校验。

不要把 CORS 当作认证。Bearer token 是主认证，Origin 是附加绑定。


十一、请求与响应限制
--------------------

node:http server 必须显式配置并测试：

- maxHeaderSize：不超过 16 KiB；
- maxHeadersCount：不超过 32；
- headersTimeout：5 秒；
- requestTimeout：10 秒；
- keepAliveTimeout：2 秒；
- maxRequestsPerSocket：100；
- server.timeout：10 秒；
- maxConnections：32；
- backlog：32；
- insecureHTTPParser=false；
- 不支持 upgrade；
- 不支持 CONNECT；
- 不支持 WebSocket；
- 不支持 HTTP/2；
- 不支持压缩。

body：

- pairing route 只接受 application/json；
- 最大 8 KiB；
- 按流计数，超过上限立即终止并返回 413；
- 不信任 Content-Length；
- 重复或冲突 Content-Length 拒绝；
- GET/OPTIONS 不接受 body；
- JSON 深度、数组长度、字符串长度和字段数受限；
- exact-object，多余字段拒绝；
- 空 body、无效 UTF-8、BOM 或无效 JSON 拒绝；
- 不把 raw body 放进错误、日志或 audit。

response：

- JSON UTF-8；
- 最大 16 KiB；
- Cache-Control: no-store；
- Pragma: no-cache；
- X-Content-Type-Options: nosniff；
- Referrer-Policy: no-referrer；
- Content-Security-Policy: default-src 'none'；
- 不返回 Server、X-Powered-By、stack、SQL、绝对路径或内部类名；
- request id 只能是运行时随机无敏感信息 ID；
- 所有日期为 UTC；
- 错误使用稳定 code、有限 message 和 requestId。

不得记录整个 req/res 对象。

统一得到有限 401。

限流使用可注入 clock 的内存实现，不需要 Redis、DB 计数器或后台任务：

- pairing exchange：每个 active session 最多 5 次失败；
- pairing 全局：每分钟最多 10 次；

- app 退出不残留 timer。

并发：

- 同一 pairing code 并发只能一个成功；
- 同一 origin 并发重配对最终只有一个 active digest；
- 撤销与请求竞争时，事务提交后的新请求必须失败；
- last_used_at 更新节流，例如每 60 秒最多写一次，避免每请求写 DB；
- last_used 写入失败不能使已认证请求获得额外权限，也不能泄漏 token。
