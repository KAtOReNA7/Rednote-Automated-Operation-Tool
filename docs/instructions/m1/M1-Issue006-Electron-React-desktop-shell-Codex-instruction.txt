七、目标进程架构
----------------

建立清晰的 Electron 三层：

1. Main process
   - 创建窗口；
   - 管理生命周期；
   - 承担最小受信任能力；
   - 注册严格 IPC；
   - 执行 Electron 运行时能力检查；
   - 不承载 React。

2. Preload
   - contextBridge；
   - 只暴露最小、命名明确、类型安全的 API；
   - 不暴露 ipcRenderer；
   - 不暴露 Node 模块；
   - 不暴露任意文件、命令或网络能力。

3. Renderer
   - React；
   - 不启用 Node；
   - 不直接访问数据库；
   - 不直接访问文件系统；
   - 不直接访问 Electron 模块；
   - 只使用 preload 暴露的窄 API。

包边界建议：

apps/desktop/
  src/main/
  src/preload/
  tests/

apps/web-ui/
  src/app/
  src/pages/
  src/components/
  src/styles/
  tests/

可以根据现有仓库结构调整，但不能混合受信任和非受信任代码。


八、强制安全配置
----------------

BrowserWindow 必须显式配置：

- nodeIntegration: false
- nodeIntegrationInWorker: false
- contextIsolation: true
- sandbox: true
- webSecurity: true
- allowRunningInsecureContent: false
- webviewTag: false

不得依赖默认值代替显式配置。

官方参考：

Electron Security：
https://www.electronjs.org/docs/latest/tutorial/security

Context Isolation：
https://www.electronjs.org/docs/latest/tutorial/context-isolation

https://www.electronjs.org/docs/latest/tutorial/sandbox

Preload：
https://www.electronjs.org/docs/latest/tutorial/tutorial-preload

IPC：
https://www.electronjs.org/docs/latest/tutorial/ipc

其他要求：

1. Renderer 只加载本地受控资源。
2. Production 不加载远程网页。
3. 不使用 webview。
4. 不禁用 webSecurity。
5. 不允许任意 window.open。
6. 拒绝未授权导航。
7. 拒绝外部页面把当前窗口导航走。
8. 默认拒绝 permission request。
9. 不启用 remote module。
10. 不使用 eval 或 new Function。
11. 不使用 unsafe-eval CSP。
12. Production CSP 最少应包含：
    - default-src 'self'
    - script-src 'self'
    - style-src 只允许项目实际需要的来源
    - img-src 'self' data: blob:
    - connect-src 'self' 或更严格
    - object-src 'none'
    - frame-src 'none'
    - base-uri 'none'
13. Dev server 例外必须只在开发模式启用。
14. Development 和 production origin 必须分别验证。
15. Renderer 不能读取 process.env。


九、IPC 设计
------------

不得暴露：

- ipcRenderer.send
- ipcRenderer.invoke
- 任意 channel 名称；
- 任意文件路径读取；
- 任意 shell 命令；
- 任意 URL 请求；
- SQL；
- 数据库连接；
- JobQueueRepository；
- JobWorker；
- Node require；
- process；
- Buffer；
- child_process。

只允许建立最小只读 API，例如：

window.rednote.getAppInfo()
window.rednote.getRuntimeCapabilities()
window.rednote.getFoundationHealth()
window.rednote.getWindowState()

返回内容限制为：

- 应用版本；
- Electron/Node/Chrome 版本；
- 当前平台；
- node:sqlite 能力布尔值；
- 数据库迁移 smoke test 状态；
- 队列 smoke test 状态；
- 非敏感窗口状态。

不得返回：

- 用户目录完整路径；
- 数据库完整路径；
-环境变量；
-请求头；
-密钥；
-完整错误堆栈；
-任意 SQL；
-任意 payload。

要求：

1. IPC channel 使用常量和类型。
2. 每个 handler 有独立 schema 验证。
3. 验证 event.senderFrame 来源。
4. Production 只接受受控应用 origin。
5. Development 只接受实际 dev server origin。
6. 不注册通配或 generic invoke handler。
7. preload 暴露对象应冻结或不可随意变异。
8. API 类型在 renderer 编译期可见。
9. IPC 错误返回安全错误码和短消息。
10. 不把异常 stack 传给 renderer。

十八、Utility Process 决策
--------------------------

Electron 官方文档指出 Utility Process 适合独立 Node 工作，例如 SQLite 服务进程。

官方参考：

https://www.electronjs.org/docs/latest/tutorial/fuses
https://www.electronjs.org/docs/latest/api/utility-process

本 Issue 必须在 ADR 中评估：

方案 A：
短数据库操作位于 main process，未来长任务放 utility process。

方案 B：
数据库和任务 worker 统一放 utility process。

本轮默认：

- 不提前实现完整 utility-process 数据库服务；
