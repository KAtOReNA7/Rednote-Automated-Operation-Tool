M3 Issue 027 前验证可靠性修正

> 完整遵守当前 AGENTS.md。本任务是小型治理修正，不是 Issue 027，不实现产品功能。

## 1. 用户结果

解决两类已经实际发生的验证阻塞：

1. 长时间全量测试丢失摘要后无法判断失败位置；
2. 容量/性能测试在全量并发负载下瞬时超时，但隔离运行通过。

目标是让未来 Issue 能获得稳定、可定位且不重复的验证结果，而不是降低测试标准。

完成后停止，不进入 Issue 027。

## 2. 起点与范围

1. 动态读取仓库根、分支、HEAD、origin/main 和工作树。
2. 不预置路径、SHA、换行或工具补丁版本。
3. 除本指令外工作树必须干净；否则停止。
4. 将本指令唯一归档到现有治理 instructions 目录。

只允许修改：

- AGENTS.md 中验证失败分类与可观测执行规则；
- future Issue 指令模板；
- package/test 配置和 Windows CI 中容量测试的非重叠调度；
- 与验证可靠性直接相关的治理测试或简短文档。

禁止修改：

- 产品源码、Domain、Schema、migration、repository、IPC、preload 或 UI；

## 3. 先盘点再修改

静态识别全部容量、性能、长路径或大规模测试文件，并记录：

- 是否依赖墙钟时间；
- 是否在普通全量 Vitest 中自动发现；
- 是否适合与普通单元测试并发；
- 当前专项入口和 CI 调度；
- 如何做到普通套件与容量套件文件集合不重叠。

若无法在不删除断言、不提高阈值、不 skip 的条件下形成非重叠方案，停止并报告。

## 4. 验证失败分类

在 AGENTS 和 future Issue 模板中采用以下规则，且只保留一个权威定义：

- `PRODUCT_OR_TEST_FAILURE`：有明确失败文件/用例；精确修复后重跑失败项。
- `INFRASTRUCTURE_FAILURE`：进程、磁盘、权限或测试运行器异常；先修复环境，不改产品迎合。
- `OBSERVABILITY_FAILURE`：exit code 异常但摘要、失败身份或结果文件缺失；允许增强持久日志后诊断重跑一次。

精确测试采用进展式重试：每次失败后必须产生定位或修改；禁止无修改、无新信息盲跑，不设置机械的两次上限。

长任务开始前必须：

- 持久保存 stdout/stderr；
- 在工具支持时保存 JSON/JUnit 等结构化结果；
- 保存真实 exit code 和起止时间；
- 对同一运行进程持续等待，不因工具返回超时另启第二个进程。

## 5. 容量测试隔离

建立一个明确的容量/性能测试入口，并满足：

1. 普通 `npm test` 与容量入口的测试文件集合完全不重叠。
2. 容量入口采用受控并发或串行方式，避免普通全量竞争造成墙钟假失败。
3. 原测试数据规模、断言和超时阈值保持不变；不得通过放宽阈值获得绿色。
4. Windows CI 运行一次普通测试和一次容量测试；两者是不同信号，不再重复同一文件。
5. 专项开发 scripts 可保留，但不得重新加入固定 CI 重复链。
6. `fact-mapping-capacity.test.ts` 必须进入容量入口，而不再被普通全量自动发现。

优先复用现有 Vitest 配置和 portable runner，不新建大型通用命令框架。

## 7. 核心验收

1. 产品行为和 Issue 027 均未修改。
2. 三类验证失败有唯一、清晰且进展驱动的处置规则。
3. 长任务在运行前建立持久日志和结构化结果策略。
4. 普通测试与容量测试文件集合静态证明为零重叠。
5. 容量测试的规模、断言和性能阈值未弱化。
6. 普通测试与受控容量测试分别通过。
7. CI 只调度非重叠测试信号，不恢复旧的全部专项重复链。
8. 没有产品、Schema、IPC、dependency、网络或费用变化。

## 8. 有限验证

开发期只运行治理测试和容量入口的精确测试。

最终候选使用持久日志，最多运行：

1. format-check；格式修复后可再检查一次。
2. lint；只在修复本任务错误后重跑。
3. typecheck；只在修复本任务错误后重跑。
4. governance/CI 配置专项一次。
5. 普通测试入口一次。
6. 容量测试入口一次，并确认文件集合零重叠。

若出现 `OBSERVABILITY_FAILURE`，按本任务新增规则允许增强日志后诊断重跑一次。

不运行 npm ci、build、desktop/clipper package、Electron、packaged、真实浏览器 smoke 或 dependency audit。
