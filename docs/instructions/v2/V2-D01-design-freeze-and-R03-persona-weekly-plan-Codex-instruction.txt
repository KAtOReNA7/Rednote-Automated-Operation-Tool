五、V2-R03 唯一用户结果

用户可以用已经保存的账号人设生成一份确定性周计划，并完成：

生成 → 批量选择 → 任意日期/时间调整 → 冲突复核 → 确认或跳过 → 锁定 → 重启恢复 → 总览同步

这轮是业务闭环与持久化行为升级，不是七页 UI 重做。

六、必须实现

1. AccountPersona 与生成前校验
   - 复用 R02 已冻结的人设 DTO、repository 和设置页，不新增第二套人设模型；
   - 以实际 R02 合同为准验证必填字段、长度、受控枚举和 expectedRevision；
   - 人设不完整时给出明确字段级提示，不生成计划、不伪装成功。

2. ScriptedPlanningProvider
   - 只用确定性 Scripted provider；真实模型、Search、Fetch、图片和业务网络均为 0；
   - 输入为已保存人设快照、weekKey 和现有计划 revision；
   - 输出最多 40 个候选，固定 ID、固定排序、固定映射；禁止随机数、Date.now() 和环境依赖结果；
   - 相同输入重复生成得到相同语义结果，不重复追加候选；
   - 普通界面只显示产品信息，不出现 Dossier、Brief、Claim、Evidence、Job、Capability 或 Ledger。

3. 周计划状态与动作
   - 复用 v2_weekly_plan_snapshots，不新增表、migration、trigger 或任意 JSON；
   - 支持生成、选择、Shift 连续选择、确认、跳过、改期和锁定；
   - 所有 mutation 使用 expectedRevision；陈旧 revision 必须无副作用地失败并提示刷新；
   - LOCKED 后普通 mutation 被拒绝，UI 必须显示真实只读状态；
   - 不实现内容包生成、审批、导出或发布。

4. 任意日期与时间
   - 单篇和批量均可进入；
   - 三种模式：日期和时间、仅日期、仅时间；
   - 日期既可直接输入也可通过日期选择器选择；
   - 时间使用 24 小时格式；明确显示 Asia/Shanghai (UTC+8)；
   - 允许跨周移动，并在应用前说明影响篇数和目标周；
   - 批量模式支持从起点按 30 分钟依次排开；
   - 对无效日期、无效时间、空选择、超过 40 项和越界输入返回有限、可读错误。

5. 冲突处理
   - 应用前检测目标时间与已有内容、以及批量内容之间的冲突；
   - 展示“已有计划”和“本次调整”双方；
   - 默认不修改任何计划；
   - 用户只能返回修改，或明确选择“仍然应用”；
   - 不自动顺延、交换、覆盖、删除、跳过或选择所谓最佳时间；
   - 明确应用后可保留相同时间，并保存可追溯的有限冲突摘要。

6. 反馈与同步
   - 成功后显示影响篇数、日期、起始时间和间隔；
   - 如实现 D01 的“撤销”，只允许撤销当前会话中最后一次日期时间调整，使用 expectedRevision，不增加历史表，也不得宣称重启后仍可撤销；
   - OverviewReadModel 必须同步待确认数量、空位、异常和下一步行动；
   - 关闭并重启 V2 后，已确认、跳过、改期和锁定状态保持一致。
