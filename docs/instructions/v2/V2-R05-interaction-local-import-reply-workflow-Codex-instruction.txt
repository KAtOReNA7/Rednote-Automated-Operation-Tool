七、R05 数据合同

A. InteractionItem

每条互动项至少包含以下有限语义：

- 稳定 item ID、workspace ID；
- kind：COMMENT 或 DIRECT_MESSAGE；
- source：固定 USER_PASTE；
- 可选 relatedContentPackageId；
- 用户文本的 ManagedRelativePath、hash、实际字节数；
- 当前 reply version ID；
- 状态、revision、有限 UTC 时间；
- 不保存平台账号凭据、Cookie、联系人通讯录或真实平台对象。

B. ReplySuggestionVersion

- 稳定 suggestion/version ID 与 interaction item ID；
- provider kind 固定 SCRIPTED；
- 回复正文的 ManagedRelativePath、hash、实际字节数；
- version、状态关联和时间；
- 不保存 prompt、raw response、模型名、请求头或费用记录。

C. 状态机

采用最小、明确的产品状态：

NEW → SUGGESTED → CONFIRMED → MANUAL_SENT
                  ↘ SKIPPED

并满足：

1. NEW 可生成建议或跳过；SUGGESTED 可编辑、确认或跳过。
2. 实质编辑创建新建议版本；no-op 保存不升版。
3. 已确认建议再次编辑，当前项回到 SUGGESTED，旧确认不得沿用。
4. 只有精确当前建议版本处于 CONFIRMED 才能进入 MANUAL_SENT。
5. MANUAL_SENT 只表示用户确认自己已在官方端完成发送，不触发、暗示或模拟平台发送。
6. SKIPPED 可以由用户明确“重新打开”回到可处理状态。
7. MANUAL_SENT 为历史事实，不能通过编辑静默改写；如需纠正，只允许受控撤销回 CONFIRMED，
   并记录本地状态变化，不进行任何外部动作。
8. 所有 mutation 使用 expectedRevision，stale 页面不得覆盖新状态。

八、本地导入、去重、建议与删除

A. 导入

1. 第一版只支持用户在应用中主动粘贴一条评论或一条私信；可连续重复添加，但不解析任意批量格式。
2. 输入必须有明确类型，可选关联一个当前 workspace 的 R04 内容包；不要求填写发送者姓名。
3. 文本、上下文、条数和总字节必须有界；以现有 codec 风格确定合理上限并写入合同和测试。
4. 规范化后的 workspace + kind + related content + text hash 构成稳定去重语义；同一导入重放
   返回既有项并显示“已存在”，不得重复写文件或数据库。
5. 原始文本只存入受控文件仓库；SQLite 只保存 metadata 和 ManagedRelativePath。

B. Scripted 回复建议

1. 新增窄的 ScriptedReplyProvider port/实现，只读取有限人设、互动类型、可选内容标题摘要和用户文本。
2. 相同输入和幂等键产生稳定建议，不创建重复版本。
3. 不调用模型、搜索、抓取、OCR、网页、图片、业务 API 或外部网络，费用为 0。
4. 建议可编辑；必须区分“系统建议”“用户编辑后的当前版本”和“用户已确认”。
5. 不宣称 Scripted 建议具有真实语义理解能力或可代表最终回复质量。

C. 批量动作

1. 支持选择当前可处理项，并原子批量确认精确当前建议版本。
2. revision 混入 stale 项时整批失败，不允许部分成功。
3. 标记 MANUAL_SENT 默认逐项执行并进行明确确认；不得加入“自动发送”或容易误解为发送的按钮。

D. 本地保留与删除

1. 默认保留策略：数据只在本机保存，直到用户明确删除；R05 不设置静默自动过期。
2. UI 必须说明保存位置属于本地项目数据，不会上传。
3. 删除采用预览 → 明确确认 → 精确 tombstone/解除产品引用；删除后普通 UI、facade 和 IPC 均不得
   再读取正文或建议，也不得影响其他 item 或 R04 文件。
4. 对已确认无其他引用的 managed files，优先复用现有文件仓库安全删除能力；如果内容寻址或
   断电语义不能证明可立即物理删除，可将其保留为不可通过产品访问、可检测的 orphan/cleanup pending，
   并在证据中如实说明，不能宣称磁盘字节已删除。
5. 不得为物理清理引入宽泛扫描、普通 rm、glob、受控目录外删除或新的全库垃圾回收系统。
   产品级删除失败不得伪装成功，也不得出现删除后仍能从正常接口读取正文的矛盾状态。
6. 日志、audit、诊断、错误、测试快照和导出不得包含用户粘贴的正文、回复正文、联系人标识或绝对路径；
   只允许类型、状态、有限字节数、稳定错误码及去标识化计数。

九、功能 UI

4. 新 IPC channel 0；只扩展既有两个 channel 的受控 read/action 判别联合和 preload 具名方法。
5. 新 package、dependency、queue、worker、route、一级导航、云服务均为 0。

7. 只有因连续 migration 必须机械更新的既有 migration-tail 断言可作为例外：逐文件列出修改前后断言，
   保持数量与强度，最多额外 12 个文件；总文件绝对上限 37。不得挪作其他范围。

十二、核心验收

R05-01 COMMENT 和 DIRECT_MESSAGE 可分别通过 USER_PASTE 创建并重启恢复。
R05-02 输入边界、非法类型、空文本和超限文本 fail closed，且错误不泄漏正文。
R05-03 完全相同的导入重放返回既有项，不重复数据库行或 managed file。
R05-04 可选内容包关联只接受当前 workspace 的稳定 ID，不用标题猜测关联。
R05-05 相同输入的 Scripted 建议稳定、幂等并明确标注非模型生成。
R05-06 实质编辑升版、no-op 不升版；确认绑定精确当前版本。
R05-07 确认后再编辑回到 SUGGESTED，旧确认不能用于 MANUAL_SENT。
R05-08 SKIPPED 可明确重新打开；状态转换之外的命令被拒绝。
R05-09 只有 CONFIRMED 当前版本可标记 MANUAL_SENT；该动作外部连接和平台副作用均为 0。
R05-10 批量确认原子执行；混入 stale revision 时整批保持原状态。
R05-11 重启后用户文本、建议版本、状态、关联内容和 revision 一致恢复。
R05-12 删除具有精确预览/确认、产品不可再读、引用检查及诚实的 deleted/orphan 证据，
       不影响其他 item 或 R04 内容文件。
R05-13 日志、诊断、audit、错误、IPC 摘要和测试证据不包含用户正文、回复正文或绝对路径。
R05-14 renderer 无 Node/Electron/DB/FS/网络直连，V2 IPC 总数仍为 2。
R05-15 互动页核心操作键盘可达；无假发送、自动发送、旧术语或未接线按钮。
R05-16 legacy、R03 人设/计划、R04 内容/导出和冻结视觉保持回归。
R05-17 真实密钥、模型/API、业务网络、费用和平台操作均为 0。

十三、经济型验证

服从当前 validation gate matrix，采用“本地聚焦验证 + 托管完整门禁”，不恢复多次本地全量。

本地：

1. 编码前不跑全量，只动态选择 interaction、V2 repository/migration、storage cleanup、V2 IPC、
   renderer、硬约束和受影响 R04 回归测试建立基线。
2. 实现后运行 R05 新增专项与直接相邻测试；每次修复只精确复跑相关集合。
3. format-check、lint、typecheck、build 各取得一次最终通过；运行 git diff --check、secret/egress、
   预算及无 skip/todo/only 检查。
4. 本地 normal 全量、capacity、package、packaged smoke、dependency audit 默认交给远端 Windows CI；
   如 AGENTS 当前三层矩阵明确要求其他独立信号，按实际风险执行，但不无修改盲目重跑。

远端：

1. 创建 Draft PR 后让精确 PR HEAD 的 Windows required CI 完整运行一次，覆盖 normal、capacity
   （若适用）、Electron source/packaged smoke、build、desktop/clipper package、audit 和 cleanup。
2. packaged smoke 在隔离 ProjectDataRoot 中完成：导入评论和私信 → 去重 → 生成建议 → 编辑 →
   确认/跳过 → 标记 manual sent → 重启恢复 → 精确删除；外部业务连接必须为 0。
3. 失败先读取完整日志并定位根因；只有针对性修改后才重触发，不降低断言、不增加宽泛 timeout、
   不无修改连续 rerun。明确基础设施瞬时故障最多按治理规则记录一次重跑，仍失败则停止。

十四、Git、PR 与体验包

1. 建议主提交信息：feat(v2): add local interaction reply workflow。
2. 不要求唯一提交；CI 暴露的当前范围兼容修复可以追加普通小提交，禁止改写已推送历史。

4. PR 描述列出：用户结果、状态机、本地保留/删除、两表/migration、0 新 IPC、视觉延期、

5. 精确 PR HEAD CI 全绿后下载并静态核验 Windows artifact。体验包包含 V2/legacy 两个启动器、
   V2-R05-体验清单.txt 和精确 commit 标识，不依赖固定电脑路径。
6. 不替用户启动或操作应用，不使用计算机控制代替用户体验。

体验清单至少要求用户：

1. 打开 V2“互动”，分别粘贴一条评论和一条私信；
2. 可选给评论关联一个 R04 内容包，并验证重复粘贴不会产生第二条；
3. 为两条记录生成本地 Scripted 建议，确认页面明确说明不是模型生成且没有发送行为；
4. 编辑一条建议并确认；跳过另一条后重新打开；
5. 尝试对未确认建议标记手动发送，确认被拒绝；
6. 将已确认建议标记为“已在小红书官方端手动发送”，确认没有平台动作；
7. 关闭并重启，核对正文、当前建议版本和状态恢复；
8. 明确删除一条本地记录，确认另一条及 R04 内容包不受影响；
9. 查看总览互动待办（若接线）与互动页计数一致；
10. 启动 legacy，确认旧入口仍可打开；
11. 回复“接受 V2-R05”或列出阻塞问题。

- 未知工作树修改；
