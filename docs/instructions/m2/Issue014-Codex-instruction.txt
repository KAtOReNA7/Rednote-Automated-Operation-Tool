四、本 Issue 的核心术语与不可混淆语义
--------------------------------------

4.1 本地结果缓存

“本地结果缓存”指：

- 应用在 ProjectDataRoot 内保存已经完成且通过运行时验证的完整供应商无关输出；
- 相同语义输入再次执行时直接返回本地结果；
- 命中时不解析 credential；
- 命中时不发起任何外部网络请求；
- 命中时不产生新费用；
- 命中时仍创建一个有限 model_run 记录，状态为 CACHE_HIT；
- 命中时不新增 cost_ledger 项，也不占用预算预留。

4.2 供应商 Prompt Cache

“供应商 Prompt Cache”指：

- 外部供应商可能对相同前缀减少输入 token 计费或加速；
- 应用仍会向外部供应商发出真实请求；
- 仍可能产生费用；
- usage 可能返回 cached input tokens；
- 这不是本地结果缓存；
- 即使供应商返回 cached input tokens，model_runs.local_cache_hit 必须为 false；
- 供应商 cached input usage 只进入 usage 和价格计算，不改变本地缓存命中率。

不得把上述两种缓存合并为一个布尔字段。

4.3 费用与预算

- “费用”是已经发生或供应商明确报告的金额；
- “估算费用”是根据用户配置的版本化价格表和明确 usage 计算的金额；
- “预算预留”是外部请求开始前为并发安全保留的最大潜在金额或单位；
- “未知费用”必须保存为 NULL 和明确状态，不得保存为 0；
- “可能已执行”表示请求可能已经到达供应商，但本地没有确定终态；
- 可能已执行的调用不得自动重试；
- 可能已执行的预留在本计费周期内继续占用，除非有明确、可审计的供应商证据完成结算。

4.4 金额单位

所有美元金额决策使用整数 micro-USD：

- 1 USD = 1,000,000 micro-USD；
- 1 cent = 10,000 micro-USD；
- SQLite 使用 INTEGER 或可验证十进制字符串，不使用 REAL；
- TypeScript 计算使用 bigint 或经过范围证明的安全整数；
- UI 输入使用十进制字符串；
- 估算金额为保护预算而向上取整到 1 micro-USD；
- 不接受科学计数法、NaN、Infinity、负数、逗号分组或隐式区域格式；
- 不进行非美元外汇换算。

2. modelRole 或 modelSlot；
3. providerConfigFingerprint；
4. modelId；
5. protocolMode；
6. Provider 合同版本；
7. prompt template ID；
8. prompt template version；
9. prompt template content hash；
10. 规范化但不损失信息的 exact input hash；
11. parameter version；
12. canonical generation options；
13. output schema ID、version 和 schema hash；
14. 按稳定规则排序的 source content hashes；
15. 按稳定规则排序的 media content hashes；
16. cache key version。

缓存键不得包含：

- executionId；
- jobId；
- requestId；
- traceId；
- 时间戳；
- retry count；
- 运行机器路径；
- Windows 用户名；
- Git HEAD；
- credential、credential digest 或 binding envelope；
- Authorization；
- 供应商原始响应；
- AI 标识；
- 版权状态；
- UI 展示状态；
- 不影响结果的数据库 row ID。

当以下任一语义变化时必须 miss：

- 任务类型；
- 模型角色或槽位；
- Provider 配置指纹；
- 模型 ID；
- protocol mode；
- Provider 合同版本；
- prompt ID、版本或内容；
- exact input；
- 参数版本或实际生成参数；
- 输出 Schema ID、版本或内容；
- 任一来源内容 hash；
- 任一媒体内容 hash；
- cache key version。

仅仓库位置、盘符、用户名、Git HEAD、换行 checkout、运行时间或 executionId 变化不得导致 miss。


八、规范序列化与内容身份
------------------------

实现单一 canonical structural encoding：

- object key 按确定性规则排序；
- array 顺序保持；
- number 只接受有限、可安全表达的 JSON number；
- 金额不走 JSON number，使用十进制字符串或整数 micro-USD；
- 拒绝 NaN、Infinity、BigInt 未编码对象、Date 隐式字符串化、Map、Set、函数、Symbol、
  prototype 污染键和循环引用；
- undefined 的处理必须显式，禁止静默丢字段造成碰撞；
- 严格区分 null、空字符串、缺失字段、0 和 false；
- UTF-8 编码；
- 不静默 trim 用户正文；
- 不静默 Unicode normalize 用户正文；
- 不静默把 CRLF、CR 和 LF 统一为同一正文；
- 正文中不同字节或不同 Unicode code point 必须产生不同内容 hash；
- 只有被合同明确声明为非语义的结构性字段才允许规范化；
- 规范化规则必须版本化并写入合同。

hash 在运行时从 canonical bytes 计算 SHA-256，作为内容身份和完整性校验。

这里的运行时内容 hash 是业务数据，不是跨电脑的开工门禁。不得把某次实际 hash 预写进本
指令、ADR 或下一任务的固定前置条件。


九、缓存策略
------------

支持有限 CachePolicy：

- READ_WRITE：默认；先读，miss 后成功结果可写；
- READ_ONLY：只读；miss 后可以执行，但不得写缓存，是否允许执行必须由调用合同明确；
- BYPASS：不读、不写；
- REFRESH：不读旧 READY 结果；获得 singleflight 后执行并以新不可变 entry 取代 active
  pointer，旧文件按 GC 规则处理。

默认策略：

- 常规确定性文本/结构化/视觉/图片调用：READ_WRITE；
- Issue 013 capability probe：BYPASS；
- 联网搜索：BYPASS；
- 工具调用：BYPASS；
- 流式未完整聚合输出：BYPASS；
- 调试和诊断：BYPASS；
- 用户明确刷新：REFRESH；
- 未来业务不得在未审查情况下新增可缓存类型。

只有同时满足以下条件才能写缓存：

- Provider 请求确定已成功；
- 供应商无关输出已完整；
- runtime schema 验证通过；
- 输出不是 refusal；
- 输出不是 partial；
- 输出不是 truncated；
- 没有工具副作用；
- 没有联网搜索内容；
- 没有 ambiguous outcome；
- 没有用户取消；
- 文件完整落盘并校验；
- 数据库 finalize 事务成功。

以下永不缓存：

- error；
- refusal；
- cancelled；
- partial；
- invalid structured output；
- timeout-after-send；
- connection-lost-after-send；
- ambiguous；
- capability probe；
- web search；
- tool call 或 tool result；
- 原始供应商 envelope。


十、缓存条目与文件安全
----------------------

缓存 payload 使用 ProjectDataRoot 中受控类别，例如：

cache/model-results

实际目录名称由现有 storage 合同以仓库风格确定，但必须满足：

- 调用方不能传任意目录；
- SQLite 只保存 ManagedRelativePath；
- 数据库和 DTO 路径统一使用 /；
- 目标在 ProjectDataRoot 内；
- 拒绝 absolute、UNC、device、drive-relative、file URL、..、symlink 和 junction；
- 使用内容寻址；
- 文件名不含书名、用户正文、模型输出或 secret；
- 写入采用既有流式 hash、独占临时文件、sync、关闭和原子发布语义；
- 不先删除旧目标；
- 文件最大值有限；
- 全局缓存配额有限且可配置；
- 默认配额必须在 ADR 中明确，不能无限；
- 读取时验证内容 hash、字节数、format version 和 runtime schema；
- 缺失或损坏不返回内容；
- 损坏条目标记 CORRUPT；
- cache payload 不进入日志、audit、诊断、普通导出、安装包或 Git。

建议缓存 envelope 只包含：

- format/version；
- provider-neutral output type；
- validated provider-neutral output；
- output content hash；
- createdAt；
- schema identity；
- 必要且有限的媒体 metadata。

不得包含：

- credential；
- Authorization；
- Base URL；
- 原始 prompt；
- 原始用户来源正文；
- 原始请求头；
- 原始供应商 response envelope；
- Web Search 正文或 URL；
- tool arguments；
- stack；
- absolute path。


十一、缓存生命周期与安全清理
----------------------------

缓存状态至少包括：

- IN_FLIGHT；
- READY；
- CORRUPT；
- EVICTED；
- AMBIGUOUS。

用户清理缓存必须两阶段：

1. preview：
   - 精确条目数；
   - 精确或安全估算字节数；
   - 受影响结果类型；
   - 不返回内容或绝对路径；
   - 生成短期、单次、sender/window/settings revision 绑定 token。

2. confirm：
   - exact-object 校验；
   - token 单次使用；
   - 先在数据库中 tombstone 或标记 EVICTED；
   - 只删除精确、已验证、未被 READY entry 引用的 managed cache file；
   - 删除失败保留可检测 orphan；
   - 不自动删除可能被共享引用的内容寻址文件；
   - 不扫描或删除受控缓存目录以外的任何路径。

清理缓存不得删除或改变：

- books；
- authors；
- reading_states；
- sources；
- claims；
- clips；
- drafts；
- assets；
- post_packages；
- publications；
- metric_snapshots；
- account/settings；
- jobs；
- price schedules；
- cost ledger；
- model run 历史；
- ProjectDataRoot 根标记；
- SQLite 数据库和备份。

缓存 GC：

- 只处理 EVICTED、CORRUPT 或无引用 orphan；
- 有限批次；
- 可取消；
- 失败可重试；
- 不在 app startup 无界扫描；
- 不持有长事务；
- 不宣称所有断电场景绝对无 orphan。


十二、singleflight 与至少一次任务语义
-------------------------------------

同一 cache key 的并发执行必须防止重复付费。

实现：

- cache entry 或独立 coordination row 的 lease；
- owner token；
- lease expires at；
- heartbeat；
- revision；
- 原子 acquire；
- bounded waiter；
- no long transaction during Provider call。

流程：

1. 事务内查 READY；
2. 没有 READY 时尝试原子领取 IN_FLIGHT；
3. 领取者才可进入预算预留；
4. 其他调用成为 waiter；
5. waiter 有界等待或轮询；
6. READY 后从本地读取；
7. 超时但 owner lease 未过期时返回稳定 PENDING/IN_FLIGHT，不得自行发第二次请求；
8. owner 在“确定未发送”前崩溃，过期后可以安全回收；
9. owner 在“可能已发送”后失联，条目标记 AMBIGUOUS；
10. AMBIGUOUS 不自动 takeover、retry 或 refresh；
11. 用户未来显式决定前，不能产生第二次外部调用。

Job Queue 是 at-least-once。ModelExecutionService 必须用 executionId 实现业务幂等：

- 相同 executionId 再次调用返回已有 run；
- 不新建第二笔 cost ledger；
- 不新建第二个 reservation；
- 不发第二次外部请求；
- executionId 与不同语义 cache key 冲突时 fail closed；
- 不宣称 exactly-once；
- 外部副作用不确定时保持 AMBIGUOUS。


十三、统一执行顺序
------------------

ModelExecutionService 的顺序必须固定并有测试：

1. 严格校验 ModelExecutionRequest；
2. 构造 prompt identity 和 canonical input；
3. 计算 cache key；
4. 检查相同 executionId；
5. 按 policy 查询本地 READY cache；
6. cache hit 时校验文件并直接返回；
7. cache miss 时运行 CapabilityGuard；
8. 获取 singleflight lease 并再次检查 READY；
9. 执行预算 preflight；
10. 在 SQLite 事务中原子创建 reservation；
11. 创建或更新 model_run 为 IN_FLIGHT；
12. 仅在 main process 最后阶段解析 credential；
13. 在数据库事务外执行一次 Provider 调用；
14. 解析、验证 provider-neutral result；
15. 若可缓存，先不可变写入 managed cache file；
16. 在一个短事务中完成 run、cache entry、cost ledger 和 reservation 结算；
17. 清理本次 lease；
18. 返回有限结果。

cache hit 必须发生在 CapabilityGuard 和预算外部请求检查之前，因此：

- 当前能力 stale 不得阻止读取一个已经存在、身份完整且通过校验的本地结果；
- 达到硬预算不得阻止本地缓存命中；
- cache hit 不解析 credential；
- cache hit 不创建 reservation；
- cache hit 不写 cost ledger；
- cache hit external request count 为 0。

但 cache miss 必须先通过当前、非 stale 的 SUPPORTED CapabilityGuard。

十五、Provider usage 与 cost observation
----------------------------------------

在 provider-neutral 合同中定义有限 UsageObservationV1：

- inputTokens；
- outputTokens；
- totalTokens；
- cachedInputTokens；
- cacheWriteTokens；
- reasoningTokens；
- images；
- imageGenerationCalls；
- webSearchCalls；
- toolCalls；
- source/provenance；
- 每个字段可空；
- 只接受非负整数和有限上限。

不得：

- 缺失时写 0；
- 自行估算 token；
- 假设 total = input + output；
- 将 cachedInputTokens 重复计入 input 价格，除非价格表明确说明 inputTokens 是否已经包含；
- 将供应商 Prompt Cache 当本地 cache hit。

定义有限 ProviderCostObservationV1：

- currency；
- decimalAmountString；
- source evidence kind；
- provider request identity 的有限 hash 或 opaque ID；
- 不含完整 header 或 envelope。

只有同时满足以下条件才能视为 PROVIDER_REPORTED_USD：

- codec 为当前协议显式 allowlist；
- 字段语义明确是本次请求费用；
- currency 精确为 USD；
- 金额十进制字符串通过严格解析；
- 金额非负且在上限内；
- 不来自自然语言正文；
- 不来自模型猜测；
- 不来自 rate limit header；
- 不来自累计账户余额；
- 不来自非美元币种。

非 USD 金额保持 UNKNOWN，不做 FX 换算。


十六、精确金额与十进制解析
--------------------------

实现单一 DecimalMoney parser：

- 输入必须是有限长度 ASCII 十进制字符串；
- 允许形式由合同明确，例如 0、0.1、12.345678；
- 拒绝 +、-、空白、逗号、货币符号、科学计数法、NaN、Infinity；
- 小数超过 6 位时：
  - 供应商报告金额不得静默改变，应按合同拒绝或采用明确、可测试的安全舍入；
  - 本地估算统一向上取整到 micro-USD；
- 转换使用字符串分解和 bigint；
- 写入 SQLite 前验证在 INTEGER 安全范围；
- 从 SQLite 读取后验证非负；
- 所有加减乘除使用整数或有理数；
- UI 格式化不反向参与账本计算。

现有 settings 中：

- warning 8000 cents = 80 USD；
- hard limit 10000 cents = 100 USD。

转换必须通过精确整数关系完成。不得先转 Number 美元再乘。


十七、版本化价格表
------------------

用户价格表是可选配置，不是供应商价格事实。

价格表至少按以下维度作用：

- providerConfigFingerprint；
- modelId；
- operationKind；
- protocolMode，可空；
- effective billing period 或 createdAt；
- immutable version；
- currency，V1 只允许 USD；
- usage semantics version。

可配置费率：

- 每百万 input tokens；
- 每百万 output tokens；
- 每百万 cached input tokens；
- 每百万 cache write tokens；
- 每张图片或图片单位；
- 每次图片生成；
- 每次 Web Search；
- 每次 tool unit；
- 每次普通调用，可空。

所有费率使用十进制字符串保存并编译为精确有理数/整数规则。

必须明确：

- inputTokens 是否包含 cachedInputTokens；
- cachedInputTokens 的独立费率；
- 缺失某个费率时对应部分不可计算；
- 任何组成部分不可计算，则总金额不得伪装为完整；
- 可以保存“已知部分金额”，但 UI 必须显示 partial；
- 不自动从互联网加载价格；
- 不硬编码官方 OpenAI 价格；
- 不根据模型名称猜价格；
- 不根据旧价格版本回算新账；
- 修改价格创建新版本；
- 历史 model_run 和 cost_ledger 固定引用当时版本；
- 删除价格版本只能停用，不能破坏历史引用；
- 当前版本切换使用 expected revision。


十八、成本状态与追加式账本
--------------------------

cost state/source 至少区分：

- PROVIDER_REPORTED_USD；
- USER_PRICE_TABLE_ESTIMATE；
- UNPRICED_USAGE；
- UNKNOWN_POSSIBLY_INCURRED；
- NOT_INCURRED。

语义：

- 本地 cache hit：NOT_INCURRED，不新增 cost_ledger；
- 发送前被 capability/budget/validation 阻止：NOT_INCURRED，不新增 cost_ledger；
- Provider 明确报告合法 USD：PROVIDER_REPORTED_USD；
- 未报告费用但 usage 与完整用户价格表可计算：USER_PRICE_TABLE_ESTIMATE；
- 有 usage 但价格表缺失或不完整：UNPRICED_USAGE，amount NULL；
- 请求可能已发送但无确定 usage/cost：UNKNOWN_POSSIBLY_INCURRED，amount NULL；
- response 验证失败但请求已执行：仍记录可得 usage/cost，不缓存结果。

cost_ledger 必须：

- append-only；
- 每次外部 execution 只有一个不可重复的 settlement identity；
- 与 execution_id 唯一关联；
- 幂等重放不重复记账；
- amount_microusd 可空；
- unknown 绝不写 0；
- 记录 source；
- 记录 provider/model/operation 的有限身份；
- 记录 price schedule version，可空；
- 记录 billing month；
- 记录 usage 摘要；
- 记录 createdAt；
- 不允许 update 金额来掩盖历史；
- 如需更正，使用显式 adjustment entry、原 entry 引用和理由枚举；
- V1 UI 不必开放任意 adjustment；
- 不保存 prompt/output/credential/raw response。

如果供应商合法报告 USD：

- provider-reported 为账本主金额；
- 用户价格表估算可作为 comparison metadata；
- comparison 不重复计入总支出；
- UI 明确标“供应商报告”和“本地估算”。


十九、预算周期、预警和硬停止
--------------------------

计费月必须确定且跨机器稳定：

- V1 使用 UTC 的 YYYY-MM；
- UI 明确显示“按 UTC 月统计”；
- fake clock 可测试；
- 不根据 Windows 本机区域或夏令时改变归属；
- 未来如支持用户计费时区必须单独迁移，不在本 Issue 隐式加入。

预算聚合至少区分：

- provider-reported known spend；
- local estimated known spend；
- outstanding reservations；
- uncertain committed reservations；
- unknown-cost call count；
- unit usage；
- local cache hits。

预警：

- known committed total >= warning threshold 时触发；
- 默认 warning 为 80 USD；
- 等于 80 时必须触发；
- 不把 unknown 当 0；
- 若存在 unknown 调用，即使 known 未到 80，也显示独立未知费用警告。

硬停止：

- 新请求的 conservative reservation 加入后可能超过 hard limit，则发送前阻止；
- 默认 hard limit 为 100 USD；
- 等于或超过 100 后阻止新的非必要外部调用；
- 并发请求通过 SQLite 原子预留，不能各自看到旧余额后共同越界；
- 当前 Issue 没有 essential 外部调用 allowlist；
- 包括 capability probe 在内的所有当前外部 Provider 调用均为 NONESSENTIAL；

二十、预算预留与并发结算
------------------------

已知价格时，请求前计算 conservative max reservation：

- 已知输入 tokens 或安全上限；
- allowed max output tokens；
- 最大图片数量/尺寸单位；
- 最大图片生成次数；
- 最大 Web Search 次数；
- 最大 tool unit；
- 每次调用固定费率；
- 所有适用组成部分的向上取整 micro-USD。

若无法为某个可收费组成部分给出有限上限，不能创建虚假的美元预留；转入无价格单位政策。

原子流程：

1. BEGIN IMMEDIATE 或现有重要写事务；
2. 聚合当月 known ledger；
3. 聚合 ACTIVE/UNCERTAIN reservation；
4. 校验 warning/hard 和 per-week/per-task policy；
5. 校验 unit policies；
6. 创建唯一 reservation；
7. commit；
8. 事务外调用 Provider；
9. 终态短事务结算。

reservation 状态至少包括：

- ACTIVE；
- SETTLED；
- RELEASED_BEFORE_SEND；
- UNCERTAIN_COMMITTED；
- EXPIRED_SAFE；
- CANCELLED_BEFORE_SEND。

规则：

- 只有能证明未发送时才能释放；
- 已发送且响应确定时用实际/估算金额结算，释放差额；
- actual > reserved 时仍记录 actual，并阻止后续调用；
- timeout-after-send、connection-lost-after-send 或 crash-after-send 转 UNCERTAIN_COMMITTED；
- UNCERTAIN_COMMITTED 在计费周期内继续占用原 reservation；
- 不因应用重启自动释放 uncertain；
- 重启恢复只释放有证明的 pre-send reservation；
- 所有转换 expected revision；
- 相同 executionId 不能有多个 active reservation。
