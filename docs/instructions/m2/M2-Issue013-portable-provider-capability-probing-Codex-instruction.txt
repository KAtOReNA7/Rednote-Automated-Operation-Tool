七、能力矩阵合同
----------------

沿用 Issue 012：

CapabilityState：

- UNKNOWN
- SUPPORTED
- UNSUPPORTED

至少覆盖：

- text
- structuredJson
- toolCalling
- webSearch
- imageGeneration
- vision
- usage
- batch
- streaming

附加可空观测：

- maxContextTokens
- rateLimitRequests
- rateLimitTokens
- rateLimitRemainingRequests
- rateLimitRemainingTokens
- rateLimitResetAt

每一项能力结果至少包含：

- capability；
- state；
- providerConfigFingerprint；
- settingsRevision；
- modelSlot；
- modelId；
- protocolMode，可空；
- evidenceCode；
- reasonCode，可空；
- observedAt；
- source=PROBED/METADATA/NOT_PROBED；
- runId；
- confidence=CONFIRMED/INCONCLUSIVE；
- stale；
- finite safe details。

未实际探测或只有 NOT_PROBED 证据时，observedAt 必须为 null，不能伪造当前时间。

modelSlot 使用有限枚举：

- PROVIDER
- RESEARCH
- WRITING
- REVIEW
- IMAGE

相同 modelId 可以去重实际请求，但必须把结果映射回所有使用该模型的 slot。

CapabilityState 规则：

- 没有运行探测时为 UNKNOWN；
- 用户跳过某项时为 UNKNOWN；
- 网络、DNS、TLS、timeout、429、401、403 或 ambiguous outcome 不等于 UNSUPPORTED；
- 只有成功的正向证据才能标记 SUPPORTED；
- 只有明确、能力特定且可信的负向协议证据才能标记 UNSUPPORTED；
- 无法区分“不支持”和“中转站错误”时保持 UNKNOWN；
- 不能根据模型名、域名、HTTP 状态单独推断；
- 不能把 UNKNOWN 当作 SUPPORTED；
- 不能把一次失败永久写成不支持。


八、能力矩阵作用域与失效
------------------------

能力不是 Provider 全局布尔值。作用域至少包含：

- 规范化后的 Provider 配置指纹；
- settings revision，作为计划并发与历史来源记录；
- credentialBindingVersion，作为不含秘密的凭据生命周期版本；
- model slot；
- model ID；
- protocol mode；
- capability；
- provider contract version。

Provider 配置指纹：

- 由规范化协议、Base URL、模型映射和合同版本组成；
- 不包含 credential、ciphertext、用户路径、用户名或机器信息；
- 使用稳定规范序列化后计算；
- 同一语义配置跨电脑得到相同结果；
- 不是文件 SHA-256；
- 不是 Git 或开工门禁；
- 不在 UI 显示完整值。

credentialBindingVersion：

- 只来自 CredentialStore 已有的非秘密 revision/updated metadata，或新增的单调非秘密版本；
- 不包含 credential 内容、长度、前后缀、hash、ciphertext 或平台密钥；
- credential set/replace/clear/reauth 后必须改变；
- 只用于判断能力证据是否仍绑定当前凭据生命周期；
- 不通过 renderer 传入；
- 不在 UI 显示原始值。

以下变化使旧矩阵 stale：

- Base URL 变化；
- provider protocol 变化；
- 任一相关 model ID 变化；
- provider contract version 变化；
- credentialBindingVersion 变化。

以下变化不应单独改变配置指纹：

- 仓库路径；
- Windows 用户名；
- Git HEAD；
- LF/CRLF；
- ProjectDataRoot 绝对位置；
- UI 主题；
- 账号简介；
- 审批预算；
- credential 的密文 envelope 路径，前提是 credentialBindingVersion 未改变。

credential 被替换、清除或重新认证后可以保留历史矩阵，但旧矩阵必须 stale，UI 要求重新
探测；不得把历史矩阵当作认证或权限仍有效的证明。

settingsRevision 用于 preview/start 的 optimistic concurrency。探测完成后，如果只修改账号
简介、预算或其他与 Provider 无关设置，settingsRevision 即使改变，也不能单独使能力矩阵
stale；矩阵有效性由 Provider 配置指纹、credentialBindingVersion 和合同版本共同决定。

- version：6
- semantic name：provider_capability_probing

不得修改 migration v1—v5 的 version、name、SQL 语义或历史记录。

建议新增 STRICT 表：

1. provider_capability_probe_runs
2. provider_capability_entries

provider_capability_probe_runs 至少包含：

- id；
- provider_config_fingerprint；
- settings_revision；
- credential_binding_version；
- profile=CORE/FULL/CUSTOM；
- status=PLANNED/RUNNING/SUCCEEDED/PARTIAL/FAILED/CANCELLED/INTERRUPTED；
- plan_hash；
- planned_steps；
- attempted_steps；
- external_request_count；
- supported_count；
- unsupported_count；
- unknown_count；
- failure_code，可空；
- created_at；
- started_at，可空；
- completed_at，可空；
- updated_at；
- revision。

provider_capability_entries 至少包含：

- id；
- run_id 外键；
- provider_config_fingerprint；
- settings_revision；
- credential_binding_version；
- model_slot；
- model_id；
- capability；

- state；
- evidence_code；
- reason_code，可空；
- confidence；
- source；
- safe_metadata_json；
- observed_at；
- created_at。

约束：

- STRICT；
- 主键、外键、唯一约束和显式索引；
- 每个 run/model slot/model/capability/protocol mode 最多一行；
- 数量和时间字段有界；
- JSON 只允许有限安全结构；
- 状态、能力、slot、协议和 evidence 使用 Core/Provider 合同枚举；
- 不保存 prompt、response、tool output、搜索结果、图片、Authorization、credential、完整
  headers、vendor error body、stack 或绝对路径；
- 不修改 model_runs 和 cost_ledger；
- 不虚构费用；
- 不把 probe run 当作 model run。

持久化语义：

- plan 可先保存为 PLANNED；
- 开始时 expected revision 转 RUNNING；
- 每个 step 完成后以短事务写入有限结果；
- 网络调用期间不持有 SQLite 事务；
- 一个 run 的 external_request_count 必须和 transport 实际发送计数一致；
- 完成时一次事务核对计数并转最终状态；
- RUNNING 状态在应用重启后转 INTERRUPTED；
- INTERRUPTED/CANCELLED 不自动恢复或重发；
- 旧有效矩阵保持可查；
- 当前配置只读取与当前指纹和 credentialBindingVersion 匹配的最新 SUCCEEDED 矩阵；
- PARTIAL/FAILED/CANCELLED/INTERRUPTED 只作历史和诊断，不替换当前矩阵；
- 不把失败 run 的未完成条目覆盖为 UNSUPPORTED。

- 迁移前自动备份；

- migration 与 schema_migrations 记录同一事务；
- 失败完整回滚；
- v5 用户数据、设置、队列、本地 API、Provider 数据保持；
- backup 可独立打开；
- foreign_key_check 和 quick_check 通过；
- 新表外键有首列索引；
- 不通过删除或重建用户数据库处理失败。

迁移校验继续使用已实现的 canonical line-ending 规则。不得在本指令或代码中硬编码旧电脑
算出的 migration checksum。报告可以说明 v6 的规范化校验已验证，但不得把某个十六进制
值设为后续电脑的开工条件。


十、探测计划与显式确认
----------------------

任何真实探测前必须先生成不可变 ProbePlan。

ProbePlan 至少包含：

- planId；
- planHash；
- providerConfigFingerprint；
- settingsRevision；
- credentialBindingVersion；
- profile；
- selected model slots；
- selected capabilities；
- protocol modes；
- ordered steps；
- exact maximum external request count；
- includesWebSearch；
- includesImageGeneration；
- includesBatchMetadataProbe；
- mayIncurCharges=true；
- costEstimate=null；
- expiresAt；
- singleUse=true。

不得声称可以准确估算费用，因为 Issue 014 尚未实现价格表和成本账本。

profile：

CORE：

- configured model metadata；
- text protocol；
- structured JSON；
- usage observation；
- vision；
- 不包含 web search、image generation 或 Batch；
- 工具调用可由用户选择，默认关闭。

FULL：

- CORE 全部；
- tool calling；
- web search；
- image generation；
- Batch 无副作用元数据探测；
- 所有支持的显式协议模式；
- 请求数仍必须有硬上限。

CUSTOM：

- 用户从有限能力列表选择；
- 至少包含一个能力；
- 不能自定义 prompt、endpoint、header 或 body。

计划器必须：

- 对相同 modelId 去重；
- 在 UI 确认前给出精确请求上限；
- 默认串行；
- 最大并发固定为 1；
- 单次 run 的计划请求硬上限为 32；
- 每个逻辑 step 最多一次外部尝试；
- 不安排隐式 repair；
- 不安排隐藏 fallback；
- 不安排创建 Batch；
- 不安排上传文件；
- 不安排搜索结果抓取；
- 不安排用户内容。

真实 start 采用 preview/commit 两阶段：

1. renderer 请求 preview，不携带 Base URL、modelId、credential 或 prompt；
2. main 从当前设置重建计划；
3. main 返回有限预览和一次性 start token；
4. 用户勾选“我知道探测会向中转站发送请求并可能产生费用”；
5. renderer 提交 token、planHash、expected settingsRevision 和 confirmed=true；
6. main 校验窗口、sender、TTL、single-use、planHash、revision 和
   credentialBindingVersion；
7. main 再次从设置重建并比较；
8. 完全一致后才开始。

token：

- 仅内存；
- CSPRNG；
- TTL 最多 5 分钟；
- 单次；
- 绑定 senderFrame 和 BrowserWindow；
- 设置变化、窗口关闭、app shutdown 或取消后失效；
- 不进入 SQLite、日志、诊断或报告。


十一、探测执行器
----------------

实现 CapabilityProbeService/Runner：

- 同一应用同时最多一个真实 run；
- 串行执行；
- 每步独立 AbortController；
- run 级总 deadline；
- step 级 timeout；
- 用户取消立即停止安排后续步骤；
- 对当前请求调用 abort；
- 等待资源释放；
- 写入 CANCELLED；
- 不自动恢复；
- 不自动重试；
- 不在失败后自动换 endpoint；
- 不在能力探测之外调用 Provider。

run 状态机：

PLANNED
  -> RUNNING
  -> SUCCEEDED | PARTIAL | FAILED | CANCELLED | INTERRUPTED

禁止：

- 从终态返回 RUNNING；
- 同一 plan 二次 start；
- stale revision start；
- app startup 自动 start；
- 数据库迁移后自动 start；
- settings 保存后自动 start；
- 定时探测；
- JobQueue 崩溃恢复后自动探测。

若应用崩溃：

- 下次启动将遗留 RUNNING 标记 INTERRUPTED；
- 不重新发送任何 step；
- 保留已完成有限证据；
- UI 允许用户生成新计划；
- 不复用旧 start token。


十二、探测 transport 安全
-------------------------

可以扩展 Issue 012 HttpTransport 或新增专用 CapabilityProbeTransport，但不得放宽普通
Provider 调用边界。

允许的探测 endpoint 只来自固定枚举：

- /models
- /models/{configuredModelId}
- /responses
- /chat/completions
- /images/generations
- /batches 的无副作用元数据方法

Base URL 合并必须保留合法 base path。

configuredModelId 如果进入 path，只能作为一个经过严格 percent-encoding 的 path segment，
不得把 `/`、`..`、query、fragment 或控制字符解释为路径。若中转站的模型 ID 不能安全映射
为单 segment，则只使用 /models 列表在内存中精确筛选，或保持 metadata UNKNOWN；不得拼接
任意路径。

要求：

- HTTPS，或 Issue 010 允许的 loopback HTTP；
- redirect=error；
- credentials=omit；
- 不使用 Cookie；
- 不读取系统代理环境配置；
- Authorization 只在 main 的最后 transport 层注入；
- 不能由 renderer/job/local API 提供 header；
- Host/Origin 不跨重定向；
- request/response header 和 body 有上限；
- 响应流式计数；
- timeout 和 AbortSignal；
- 连接、body、timer 完整释放；
- 只记录有限状态和计数；
- 不记录 raw request/response。

GET/OPTIONS/HEAD 只可用于固定元数据探测。普通 Issue 012 Provider 仍保持既有 POST 和受控
endpoint 规则。

测试 transport：

- 只连接 127.0.0.1；
- 使用 OS 随机端口；
- 对任何非 loopback 地址 fail closed；
- 外部连接计数必须为 0。


十三、文本与协议模式探测
------------------------

对每个去重后的 text model，可以显式探测：

- RESPONSES；
- CHAT_COMPLETIONS。

不得根据模型名选择。

每个 mode 使用固定、最小、非业务 prompt：

- 不包含用户书名、作品、账号、设置或个人信息；
- 要求返回固定短标记；
- output token 上限保持最小；
- temperature 等参数只使用合同允许的保守值；
- store=false；若中转站不接受该参数，不能静默删除后重试。

SUPPORTED：

- HTTP 与 codec 成功；
- 响应结构合法；
- 返回预期固定标记；
- 没有 refusal；
- 没有 ambiguous outcome。

UNSUPPORTED：

- 中转站返回明确、协议特定的 endpoint/model/mode unsupported 证据；
- 分类器能与认证、限流、配额、请求错误区分。

UNKNOWN：

- 401/403；
- 429；
- timeout；
- 网络/TLS/DNS；
- 5xx；
- malformed body；
- generic 404 无法确认；
- response 成功但没有预期标记；
- ambiguous disconnect。

协议模式结果必须分别保存，不允许“一个成功就声称全部模式支持”。


十四、结构化 JSON 探测
----------------------

对已证明 text mode 可工作的模型，使用固定极小 strict schema：

- object；
- additionalProperties=false；
- 一个固定 boolean；
- 一个固定 enum 字符串；
- schemaId/version 固定为能力探测合同；
- runtime validator 必须再次验证。

Responses 和 Chat Completions 使用各自 codec 的显式 Structured Outputs 形状。

SUPPORTED：

- provider 接受 schema；
- 返回合法 JSON；
- runtime schema 验证通过；
- 固定值符合预期。

不得仅因为“返回了看起来像 JSON 的文本”标记支持。

明确 unsupported structured output 可标 UNSUPPORTED。

invalid JSON、schema mismatch、refusal、静默忽略 schema 或 generic error 保持 UNKNOWN，并
记录有限 reason。

不发送第二次 JSON repair 请求。


十五、工具调用探测
------------------

工具探测只声明一个无副作用 synthetic function：

- 固定名称；
- strict schema；
- 只接受固定 enum 参数；
- prompt 要求调用该函数；
- 不提供任何真实业务工具；
- 不执行返回的 tool call；
- 不提交 tool result；
- 不产生第二轮模型调用。

SUPPORTED：

- provider 返回可由对应 codec 解析的 tool call；
- 工具名和参数通过严格验证；
- 参数等于固定 synthetic 值。

如果只返回普通文本、伪造 JSON 或未知工具，不标记支持。

任何返回的 tool call 只在内存验证，随后丢弃；不进入日志、SQLite、audit、diagnostic 或
snapshot。


十六、联网搜索探测
------------------

联网搜索只在用户选择 FULL 或 CUSTOM 且明确确认后进入真实计划。

要求：

- 使用 Responses 的受控 web_search tool 形状；
- 可以在兼容性合同中保留 legacy 名称，但必须作为独立显式 probe mode；
- 固定、非敏感、低复杂度查询；
- 查询目标使用稳定公开标准页面；
- 不使用用户业务主题；
- 不保存网页正文；
- 不抓取结果 URL；
- 不把搜索结果送入 SearchProvider；
- 不创建来源、claims、clips 或 research dossier。

SUPPORTED 必须有强正向证据：

- 响应包含可识别的 web_search_call completed 事件，或合同认可的等价工具证据；
- 至少有安全解析的来源/citation 元数据；
- 不是只凭模型文本声称“我搜索了”。

普通文本答案、模型记忆答案、虚构 URL 或无工具证据时保持 UNKNOWN。

只保存：

- 是否出现工具事件；
- 来源计数；
- citation 计数；
- 安全 evidence code；
- 不保存 URL、标题、snippet 或正文。

不得把本轮联网探测的结果当作任何图书事实来源。


十七、图片理解探测
------------------

Vision 探测使用代码内生成的极小 synthetic image：

- 运行时内存生成；
- 不从磁盘读取用户图片；
- 不包含书封、人物、文字或个人信息；
- 固定纯色/简单几何；
- MIME 与 magic bytes 合法；
- 大小受 Issue 012 上限约束；
- 测试结束释放；
- 不写 assets 或文件仓库。

prompt 要求返回有限 enum，例如识别固定颜色或形状。

SUPPORTED：

- 对应 mode 接受 image input；
- 返回合法文本；
- 结果匹配固定 enum；
- 没有 refusal。

成功返回但答案错误、忽略图片或只复述 prompt 时保持 UNKNOWN，不标记 UNSUPPORTED。


十八、图片生成探测
------------------

图片生成属于可能费用较高能力：

- CORE 默认不包含；
- FULL/CUSTOM 必须在预览中单独标注；
- 用户明确确认后最多一次请求；
- count=1；
- 使用产品合同支持的最低保守质量/尺寸 hint；
- prompt 固定为简单 synthetic 图形；
- 不使用用户内容。

SUPPORTED：

- Images endpoint 成功；
- codec 返回受支持的 inline image bytes；
- MIME、magic bytes、单张/总大小验证通过。

如果仅返回产品当前不支持的任意远程 URL：

- 不下载；
- 不跟随；
- 不标记为产品可用的 imageGeneration；
- 使用安全 reason=OUTPUT_VARIANT_UNSUPPORTED。

真实探测所得图片：

- 只在内存验证；
- 不显示给用户；
- 不保存；
- 不写 ProjectDataRoot、assets、日志、diagnostic 或测试 artifact；
- 验证后立即解除引用。


十九、usage、上下文与速率观测
----------------------------

usage：

- 不单独增加付费请求；
- 从其他成功 probe 的返回中观察；
- 至少一个成功响应包含可验证 usage 才可标 SUPPORTED；
- 所有成功响应均缺失 usage 时保持 UNKNOWN，除非上游明确声明不支持；
- malformed usage 保持 UNKNOWN，并记录稳定 reason；
- 不估算 token；
- 不把缺失写 0；
- 不计算美元；
- 不写 model_runs 或 cost_ledger。

maxContextTokens：

- 只从明确、可信、与 configured model 精确对应的元数据读取；
- 不通过逐步扩大 prompt 测上限；
- 不发送大输入；
- 缺失为 null；
- 不根据模型名或官方同名模型推断第三方中转站值。

rate limits：

- 只读取 allowlist 的规范化响应 headers 或明确元数据；
- 不主动打到限流；
- 不并发压测；
- 不估算；
- 不持久化完整 headers；
- 非负安全整数或合法时间才接受；
- 缺失保持 null；
- 不把单次 429 当作固定供应商速率。


二十、Batch 无副作用探测
------------------------

Batch 不是 V1 依赖。探测不得创建真实 Batch。

禁止：

- 上传 JSONL；
- 创建 file；
- 提交 input_file_id；
- POST 一个可能被接受的 Batch 创建请求；
- 查询或列出用户已有 Batch；
- 读取 Batch 内容；
- 取消用户 Batch；
- 依赖 Batch 完成后台队列任务。

允许：

- 固定 endpoint 的 OPTIONS/HEAD 等无副作用元数据探测；
- 明确 Provider capability metadata；
- loopback fixture 中模拟 SUPPORTED/UNSUPPORTED。

分类：

- 明确、可信的 capability metadata 可标 SUPPORTED；
- 明确 endpoint unsupported 可标 UNSUPPORTED；
- 2xx 但无能力语义、405、generic 404、认证/限流/网络问题均保持 UNKNOWN。

无论 Batch 为 UNKNOWN 或 UNSUPPORTED：

- Issue 009 本地持久队列必须继续运行；
- 不改变 jobs 状态机；
- 不降低 queue 测试；
- 不引入远程队列。


二十一、保守分类器与稳定错误
----------------------------

实现纯函数 CapabilityProbeClassifier。

输入只包括：

- probe kind；
- protocol mode；
- normalized transport outcome；
- normalized provider error；
- validated finite evidence；
- metadata presence。

输出：

- state；
- confidence；
- evidenceCode；
- reasonCode；
- safe metadata；
- shouldContinueRun；
- mustStopRun。

不得把 vendor 原始 message 作为分类条件的唯一依据。可使用有限、经过测试的结构化 code
和状态组合。

至少覆盖稳定 reason：

- NOT_PROBED
- USER_SKIPPED
- CONFIG_STALE
- AUTHENTICATION_REJECTED
- PERMISSION_REJECTED
- RATE_LIMITED
- QUOTA_UNAVAILABLE
- NETWORK_UNREACHABLE
- TLS_FAILURE
- TIMEOUT
- ABORTED
- ENDPOINT_EXPLICITLY_UNSUPPORTED
- MODEL_EXPLICITLY_UNSUPPORTED
- PROTOCOL_EXPLICITLY_UNSUPPORTED
- INVALID_CONTENT_TYPE
- INVALID_RESPONSE
- INVALID_JSON
- SCHEMA_MISMATCH
- TOOL_NOT_OBSERVED
- SEARCH_NOT_OBSERVED
- VISION_INCONCLUSIVE
- OUTPUT_VARIANT_UNSUPPORTED
- USAGE_NOT_REPORTED
- METADATA_NOT_REPORTED
- AMBIGUOUS_OUTCOME
- INTERNAL_ERROR

全局停止规则：

- 401/403：停止余下真实 probe，剩余项 UNKNOWN；
- credential unavailable/corrupt：开始前失败，外部请求 0；
- config stale：开始前失败，外部请求 0；
- 429：停止余下步骤，不自动等待或重试；
- 用户取消：停止；
- app shutdown：中断；
- 同一 Provider 连续 3 个网络/5xx 失败：停止，避免无意义请求；
- 任何计划计数不一致：停止并 FAILED。

单项 unsupported 不阻止探测其他独立能力，除非基础 text mode 均不可用。


二十二、Capability Guard
------------------------

实现供后续业务调用的 CapabilityGuard/Resolver。

输入：

- 当前 provider config fingerprint；
- settings revision，仅作历史来源与并发信息；
- 当前 credentialBindingVersion；
- model slot；
- capability；
- protocol mode；
- 当前矩阵。

规则：

- SUPPORTED 且矩阵不 stale 才允许；
- UNKNOWN 拒绝并返回 PROVIDER_CAPABILITY_UNKNOWN；
- UNSUPPORTED 拒绝并返回 PROVIDER_CAPABILITY_UNSUPPORTED；
- stale 拒绝并返回 PROVIDER_CAPABILITY_STALE；
- 不能仅因与 Provider 无关的 settingsRevision 变化拒绝；
- model/mode 不匹配拒绝；
- 不自动探测；
- 不自动 fallback；
- 不自动换模型；
- 不调用 UI；
- 不读取 credential；
- 不修改矩阵。

本轮没有研究、写作或图片业务调用，Guard 通过单元/集成测试证明，不注册真实业务
JobHandler。
