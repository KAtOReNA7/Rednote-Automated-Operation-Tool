四、Search / Fetch / Catalog / Evidence 四层边界
------------------------------------------------

四层不可跨越：

1. Search：只发现 `LEAD_ONLY / UNVERIFIED / NOT_A_FACT` 候选；
2. Fetch：只生成 `FETCHED_NOT_EVIDENCE / UNVERIFIED / NOT_A_FACT` 文档；
3. Catalog：只建立带 provenance 的未验证书目实体与关系；
4. Evidence：Issue 019 才能创建 Source、Claim、Evidence、Conflict 和 FactEvaluation。

创建 Source 不等于来源内容为真。
创建 Claim 不等于 Claim 可公开使用。
中文摘要不等于证据。
模型输出只可生成候选 Claim，不能直接得到 `VERIFIED`。

TypeScript 合同、SQLite CHECK、架构测试和 UI 文案必须共同冻结这些区别。


五、Source V1
-------------

定义版本化 `SourceV1`、`SourceRevisionV1` 和严格 runtime validator。

允许的正式输入：

- 已持久化且成功完成的 Issue 016 FetchDocument；
- 由 Issue 017 BrowserClip 形成的市场/讨论上下文，但默认只能是 `CONTEXT_ONLY`；
- 合成 fixture。

SearchCandidate 只能作为来源发现 lineage，不能直接创建 Source。

Source 至少包含：

- sourceId、currentRevisionId、originKind、originRecordId；
- canonical URL identity/hash 与有限 display host；
- title、publisher/site、language；
- source authority kind；
- evidence use policy；
- independence group，可空；
- immutable content hash 与受控 snapshot path identity；
- retrieved/published time 及精度；
- revision、status、createdAt、updatedAt；
- provenance 与 bounded warnings。

来源权威类型至少支持：

- `OFFICIAL_PRIMARY`
- `INDEPENDENT_SECONDARY`
- `DISCUSSION_CONTEXT`
- `UNKNOWN`

证据用途至少支持：

- `KEY_FACT_ELIGIBLE`
- `SUPPORTING_ONLY`
- `CONTEXT_ONLY`
- `NOT_CLASSIFIED`

来源分类必须由用户确认或明确 fixture 指定。
不得仅按域名、TLD、搜索排名、页面自称或模型判断自动升级权威级别。

Source revision：

- 内容 hash 变化创建新 revision，不覆盖旧 revision；
- 旧 Evidence 继续绑定旧 revision；
- 新 revision 触发 `STALE_REVIEW_REQUIRED`，不静默继承验证结论；
- unavailable/retracted/superseded 状态保留历史，不物理删除；
- 同一 origin/revision 重放幂等。


六、独立性与来源谱系
--------------------

“两个来源”必须是真正独立来源，不能只按两个 URL 或两个域名计数。

定义版本化 independence/lineage：

- organization/owner identity，可空；
- upstream source identity，可空；
- syndication/reprint/mirror relation；
- shared content hash / near-identical content hint；
- 用户确认的 independence group；
- decision revision 与 audit。

冻结规则：

- 同一公告的转载、镜像、RSS 副本、同集团同稿和引用同一上游稿件不得计作两个独立来源；
- 不同 URL、子域名或站点品牌不自动等于独立；
- 相同 content hash 必须视为同一 lineage；
- 自动算法只能产生 `DEPENDENCY_SUSPECTED`，不能把 UNKNOWN 自动升级为 INDEPENDENT；
- 用户可合并、拆分 independence group，需 preview、expected revision、确认 token 和 audit。


七、AtomicClaim V1
------------------

Claim 必须是单一主语、单一谓词、单一值与明确 scope 的原子声明。

Subject 只允许引用现有：

- Work
- Expression
- Edition
- Person/Organization Agent
- PublicationRelationship

不得使用无法由外键或受控 subject registry 验证的任意 polymorphic ID。

Claim 至少包含：

- claimId、subjectRef、predicateId/predicateVersion；
- typed canonical value；
- scope：language、territory、format、valid/effective time；
- keyFact boolean；
- claimant/sourceRevision identity；
- semantic fingerprint；
- status、revision、createdAt；
- extraction run/manual entry provenance。

Typed value 至少支持：

- `TEXT`
- `INTEGER`
- `DECIMAL_TEXT`
- `DATE_WITH_PRECISION`
- `IDENTIFIER`
- `ENUM`
- `ENTITY_REF`
- `BOOLEAN`

要求：

- canonical JSON 确定性；
- 不使用 SQLite REAL 表示精确值；
- UNKNOWN 保持 NULL/UNKNOWN，不伪造空字符串、零或日期；
- 日期区分 year/month/day precision；
- 同 predicate 的 value schema 固定版本化；
- 额外字段、超长值、非法 scope 和不匹配 value type 被拒绝；
- 同语义 Claim 重放幂等，新值形成新 Claim/版本，不覆盖历史。

建立有限 Predicate Registry。至少覆盖书目关键事实：

- canonical/original/translated title；
- author/translator/publisher/imprint；
- publication date；
- ISBN / platform identifier；
- language/territory/format；
- award nomination/win；
- series membership/order；
- publication/licensing relationship。

不得允许任意用户字符串直接成为可执行 predicate。


八、EvidenceLocator V1
----------------------

每条证据必须绑定一个不可变 SourceRevision。

Evidence 至少包含：

- evidenceId、claimId、sourceRevisionId；
- relation：`SUPPORTS / CONTRADICTS / QUALIFIES`；
- locator kind；
- paragraph/block index 或受控 char range；
- bounded exact excerpt；
- excerpt hash；
- source content hash；
- source language；
- Chinese summary，可空；
- summary origin：`MANUAL / MODEL_CANDIDATE / NONE`；
- verification status、revision、createdAt。

运行时必须重新验证：

- excerpt 在绑定的净化文本 revision 中精确存在；
- range、block、hash 和 content hash 一致；
- excerpt 长度有限；
- 不允许 locator 指向 Search snippet、未净化 HTML、截图 OCR、模型回答或其他 revision；
- Source 更新后旧 locator 不被重定向到新文本。

正文不复制进 Claim、Job、audit、日志、诊断或普通报告。
renderer 只按需取得有界、分页、纯文本片段，不接收整份 snapshot 或 HTML。

中文摘要：

- 日文/英文来源允许生成中文摘要；
- 摘要必须绑定原 evidence，不能替换原文 excerpt；
- 摘要不得新增原文不存在的事实；
- 没有原文精确定位时拒绝保存模型摘要；
- UI 必须明确显示“原文证据”和“中文摘要”。


九、证据政策与 FactEvaluation
-----------------------------

定义版本化 `FactPolicyV1` 和确定性评估器。

关键事实成为 `VERIFIED` 必须满足：

- 一个 `OFFICIAL_PRIMARY + KEY_FACT_ELIGIBLE` 的支持证据；
  或
- 两个已确认相互独立的
  `INDEPENDENT_SECONDARY + KEY_FACT_ELIGIBLE` 支持证据；
- 且不存在未解决的 material contradiction；
- 所有 EvidenceLocator 均对当前 SourceRevision 有效。

明确规则：

- `DISCUSSION_CONTEXT` 永远不能单独验证关键事实；
- 两个 dependent/syndicated 来源只计一个；
- UNKNOWN independence 不计作两份独立证据；
- `SUPPORTING_ONLY` 可展示但不满足关键事实门槛；
- 缺失 usage、模型置信度或来源数量不得猜测；
- 来源分类变化、revision 更新、撤回或 lineage 变化必须重算。

FactEvaluation 状态：

- `NOT_EVALUATED`
- `INSUFFICIENT`
- `SUPPORTED_NOT_VERIFIED`
- `VERIFIED`
- `CONFLICTED`
- `FACT_BLOCKED`
- `STALE_REVIEW_REQUIRED`
- `REJECTED`

Evaluation 必须保存 policy version、输入 Claim/Evidence/Source revision 集合 hash、
independence snapshot、原因码和 evaluatedAt。
同输入重算幂等；政策版本变化生成新 evaluation，不覆盖旧结果。


十、冲突检测与解决
------------------

冲突槽由 subject + predicate + normalized scope + policy version 定义。

只有语义不可同时成立的 material value 才形成冲突：

- UNKNOWN 与已知值不是冲突；
- date precision 不同需先判断兼容；
- 多值 predicate 按 registry 规则处理；
- scope 不同的语言、地区、版本或时间不应误判；
- 单纯标题 alias 不应成为冲突。

Conflict 状态：

- `OPEN`
- `FACT_BLOCKED`
- `RESOLVED_ACCEPT`
- `RESOLVED_MULTIVALUE`
- `RESOLVED_SCOPE_SPLIT`
- `DISMISSED_DEPENDENT_SOURCE`
- `SUPERSEDED`
- `REOPENED`

任何关键事实存在未解决 material conflict 时，当前 evaluation 必须为 `FACT_BLOCKED`。
Issue 019 只提供可查询的 FactGuard/Readiness，不修改草稿、审批、排期或发布包。

人工解决必须具有：

- affected Claim/Evidence/Source/Entity preview；
- before/after FactEvaluation；
- expected revision；
- window-bound、短期、单次确认 token；
- 原子事务；
- append-only decision/audit；
- undo/reopen；
- 并发冲突检测；
- 必填 reason，不接受静默覆盖。


十一、提取、翻译与模型边界
--------------------------

定义 provider-neutral `ClaimExtractionV1` 与 `EvidenceSummaryV1`，复用 Issues 012—014：

- 只走 ModelExecutionService；
- structured JSON capability 必须为当前、非 stale、SUPPORTED；
- 明确 preview、预算结果、用户确认；
- 缓存、usage、model_runs、reservation 和 cost ledger 保持原语义；
- credential 只在 main transport 最终阶段解析；
- after-send 不确定状态不得自动重试、repair、fallback 或换模型。

本 Issue 的测试和验收只使用 Scripted Mock，真实外部请求与费用为 0。

模型请求只发送：

- 当前明确选择的有界纯文本片段；
- 目标语言；
- 有限 Predicate Registry；
- strict output schema；
- 不包含 credential、URL query、用户备注、整库数据或无关正文。

来源文本一律视为不可信数据：

- 页面中的 prompt injection 不得改变任务、工具、政策或输出 schema；
- 模型只能提出 candidate Claim/Evidence；
- 运行时必须验证 excerpt、locator、subject、predicate 和 typed value；
- 没有精确证据的“模型常识”全部拒绝；
- 模型 confidence 不参与 FactPolicy。

手工录入路径必须可用；未配置模型时 UI 显示真实状态，不伪装为不可用系统整体失败。


十二、计划、队列与恢复
----------------------

定义版本化 SourceProcessingPlan：

- 只接收已持久化 Source/Revision ID；
- 声明步骤：classify、extract、summarize、reconcile；
- 精确模型请求上限、片段字节、Claim 数、Evidence 数、运行时间和预计本地写入；
- 显示预算结论，未知费用保持 UNKNOWN；
- preview hash、过期时间、sender/window/config 绑定确认；
- 默认不自动确认。

建议的有限 handler（可按现有架构合并，但必须保持语义）：

- `SOURCE_INGEST_V1`：纯本地、无外部请求；
- `CLAIM_EXTRACTION_V1`：可选模型执行；
- `FACT_RECONCILE_V1`：纯本地、确定性。

要求：

- 不自动由 Search/Fetch/Clip enqueue；
- payload 只保存 ID、计划/版本/hash 和有限计数；
- executionId 幂等；
- lease、heartbeat、暂停、取消、shutdown 和重启恢复；
- 外部调用期间不持有 DB 长事务；
- 相同 executionId 不重复模型请求、预算、Claim、Evidence 或 Evaluation；
- pre-send/after-send/ambiguous 状态符合 AGENTS；
- result 不含正文、excerpt、summary、raw response、路径或 secret。
