六、三级书目模型
----------------

三级对象必须显式分离：

1. Work：抽象作品
   - 同一故事或文本作品的核心身份；
   - 不因译名、语言、出版社、载体、再版、分册或 ISBN 改变；
   - 现有 `books` 语义升级为 Work，既有 ID 和引用必须保留。

2. Expression：作品的语言或文本表达
   - 原文、特定译文、修订文本、改编文本或网络连载文本；
   - 同一翻译的不同再版通常属于同一 Expression；
   - 不同译者或实质不同文本必须可分开。

3. Edition：具体出版或平台版本
   - 特定出版社/品牌、日期、载体、版次、装帧、分册、ISBN 或平台作品 ID；
   - 纸书、电子书、有声书、网络连载、合集收录和再版均可表示；
   - 一个 Edition 必须属于一个 Expression，并可经 Expression 回溯 Work。

`BibliographicObservation` 是不可变的发现输入与 provenance，不属于三级实体。
Observation 可以未能关联任何实体，也可以进入人工复核；不得为了填满书库强制创建 Work。

升级现有 `book_editions` 时不得留下 `book_id` 与 `expression_id` 两套可能不一致的真相来源。
根据实际 Schema 选择安全重建或兼容迁移，并在 ADR 说明。


七、书目观察合同
----------------

定义版本化、严格校验的 `BibliographicObservationV1`，至少包含：

- observationId、originKind、originRecordId；
- observedAt；
- display title、original-title hint、language/script hints；
- contributor name hints；
- publisher/imprint/platform hints；
- publication-date/year hint；
- bounded identifier hints；
- work-type/format/series hints；
- source candidate/document/clip identity；
- field-level provenance；
- `truthStatus = UNVERIFIED`；
- `factStatus = NOT_A_FACT`；
- normalization version；
- bounded warnings。

要求：

- exact-object、数组/字符串/深度/总序列化大小均有限；
- 原始值与规范值分离，原始值不可被规范化覆盖；
- 不复制整页正文、完整 snippet、用户备注、截图字节、token、URL query 或绝对路径；
- Queue payload 只保存 Observation/Run/Plan ID 和有限版本身份；
- 同一 origin identity 重放幂等；
- 同一来源更新形成新 revision/observation，不静默改写历史观察；
- 任何派生字段都标明算法版本和输入 Observation。

SearchCandidate 只能提供发现线索；FetchDocument 或用户明确输入可以提供字段候选，
但在 Issue 019 前仍是未验证书目观察。


八、作者、机构与出版/授权关系
-----------------------------

书目模型必须反映真实出版业务中的多方关系，不再假设“一本书只有一个 author_id 和 publisher 字符串”。

建立统一 Agent 或等价的规范模型：

- Person：作者、合著者、译者、编者、改编者；
- Organization：出版社、出版品牌/imprint、发行方、数字平台、代理机构及其他书目相关机构；
- 原名、译名、笔名、旧名和机构别名必须独立保存。

至少支持下列关系作用域：

- Work：AUTHOR、COAUTHOR、ORIGINAL_CREATOR；
- Expression：TRANSLATOR、ADAPTER、EDITOR；
- Edition：PUBLISHER、IMPRINT、DISTRIBUTOR、PLATFORM；
- Publication relationship：
  RIGHTS_PARTY、LICENSOR、LICENSEE、AGENCY。

出版/授权关系是“待核验的业务关系记录”，不是法律结论，也不是版权风险字段。
关系应支持方向、主体/客体、适用 Work/Expression/Edition、语言、地区、载体、有效期和 provenance；
未知项保持 NULL/UNKNOWN，不得猜测。

Issue 018 只允许：

- `OBSERVED_UNVERIFIED`
- `USER_CONFIRMED`
- `EVIDENCE_PENDING`

不得伪造 `EVIDENCE_CONFIRMED`；该状态只能由后续 Issue 019 的证据链产生。
任何关系值的增加、删除或变化都不得改变门禁、评分、审批、优先级、排期或导出资格。


九、标识符与规范化
------------------

规范化必须版本化、确定性、可重算且保留原值：

- Unicode NFKC、空白、宽窄字符、大小写和标点处理；
- 中文、日文、拉丁文字及组合字符；
- 标题主标题/副标题、卷次、系列名和版次分开；
- 人名顺序、笔名和罗马字只作为 alias，不凭转换结果断言同一人；
- 机构品牌与法人/母公司不自动视为同一实体。

标识符至少支持：

- ISBN-10 与 ISBN-13：去格式、校验 check digit、可规范转换；
- scoped platform work ID；
- scoped publisher/catalog ID；
- 其他标识符必须带 namespace，不接受无来源的全局字符串。

冻结规则：

- 无效 ISBN 不进入 canonical identifier，但原始 hint 和错误原因可保留；
- ISBN 只关联 Edition；
- 同一合法 ISBN 出现冲突元数据时创建冲突 case，不自动覆盖或合并；
- 网络作品没有 ISBN 是正常状态；
- 标题、作者、年份缺失不得伪造成空字符串或占位事实。


十、实体解析与可逆决策
----------------------

实体解析采用保守、可解释的规则，不调用模型。

每次候选比较返回有限 feature vector、规则版本和 outcome：

- `EXACT_LINK`
- `PROBABLE_REVIEW`
- `DISTINCT`
- `CONFLICT`
- `INSUFFICIENT`

自动 `EXACT_LINK` 只允许由同类型强标识符及兼容上下文支持；
任何冲突、仅标题相似、仅作者相似或跨实体层级匹配都必须进入人工复核。

必须覆盖：

- 同一 Work 的原名、日文/英文/中文译名；
- 同一 Expression 的平装、精装、电子版和再版；
- 不同译者形成不同 Expression；
- 同名不同书；
- 同名或笔名作者；
- 合集与单篇、分册与合订本、系列与单卷；
- 网络连载与实体出版；
- 无 ISBN、错误 ISBN、重复 ISBN 和冲突 ISBN；
- 出版品牌、出版社、平台和授权链的不同层级。

人工操作必须提供：

- merge/split/undo 预览；
- 受影响的 Work、Expression、Edition、Observation、关系和下游引用计数；
- expected revision；
- 短期、单次、window-bound 确认 token；
- 原子事务；
- append-only decision/audit；
- canonical survivor 与 alias 选择；
- 并发修改检测；
- 可逆 lineage，不硬删除 provenance。

已被合并实体的旧 ID 必须可解析到 survivor；撤销后恢复原关联。
下游引用不可被静默丢失或指向错误层级。


十一、DiscoveryPlan 与“无固定 50”验收

定义版本化 `DiscoveryPortfolioProfileV1`、`DiscoveryPlanV1` 和 `DiscoveryRunV1`。

计划至少声明：

- 运行目的：`PILOT_CONTENT / MARKET_MAP / CUSTOM`；

- 每层目标、优先级、允许来源类型和缺口策略；
- 最大 Observation、候选比较、DB 写入、运行时长和本地并发；
- 可消费的已持久化输入范围；
- normalization/entity-resolution 版本；
- preview hash、过期时间和用户确认；
- 预计本地工作量；外部请求数固定为 0。

默认 strata 至少能表达：

- 日本推理；
- 欧美推理；
- 中文出版推理；
- 中文网络悬疑；
- 原创/翻译；
- 纸书/电子/网络连载；
- 有强标识符/无 ISBN；
- 新书/存量书，时间未知时单列 UNKNOWN。

不得把“热门/冷门”从搜索排名或主观印象直接写成事实；热度数据属于后续有来源的分析。

Run 状态：

`DRAFT → PREVIEWED → CONFIRMED → RUNNING → AWAITING_REVIEW →
COMPLETED | COMPLETED_WITH_GAPS | CANCELLED | FAILED | INTERRUPTED`

完成不取决于一个全局固定书数。Coverage report 必须显示：

- 每个 stratum 的计划、观察、Work/Expression/Edition 数和短缺；

- provenance 完整度；
- 去重前后基数；
- 明确的 gap reason；
- 该报告是 fixture、synthetic 还是真实用户运行。

fixture/synthetic 结果必须醒目标记，不能显示为“真实行业书库已完成”。

不得使用 `dangerouslySetInnerHTML`。
