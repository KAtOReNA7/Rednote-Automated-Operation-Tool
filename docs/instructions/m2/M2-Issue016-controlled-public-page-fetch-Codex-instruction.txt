M2 Issue 016：定向公开页面抓取与文本抽取——精简增量开发指令
================================================================

本文件是 Issue 016 的唯一增量指令；如存在其他 Issue 016 草稿，以本文件为准。

完整遵守仓库根级及作用域内 AGENTS.md，尤其是
`<!-- CODEX_COMMON_RULES: v1 -->` 公共规则块。本文件不重复公共门禁。

推荐模型：GPT-5.6 Sol
推荐推理强度：High；SSRF、DNS、重定向、HTML 净化、恢复和 migration 使用 XHigh
目标提交信息：feat(fetch): add controlled public page extraction


一、授权目标
------------

只实现 Roadmap Issue 016：

- 对研究流程明确选中的单个公开页面执行受控抓取；
- 从 Issue 015 的 SearchCandidate 建立不可跨越的 Fetch 计划；
- 校验 URL、DNS、连接目标、重定向、robots、MIME、编码和大小；
- 对 HTML 做惰性解析、净化和确定性正文抽取；
- 保存必要的离线净化快照与纯文本，不保存原始响应；
- 以内容哈希去重，记录 FetchRun、文档、robots、重定向和限速状态；
- 增加 `FETCH_PUBLIC_PAGE_V1` 队列处理器，但不自动入队；
- 增加 migration v9、专项测试、文档和 100 项增量验收映射。

完成后停止，不进入 Issue 017、018、019。


二、Issue 特有语义基线
---------------------

编码前以当前仓库实际实现确认：

- Issue 015 SearchProvider V1、migration v8、SearchRun、SearchCandidate、持久限速和
  `SEARCH_EXECUTE_V1` 完整；
- SearchCandidate 四项语义仍固定为
  `LEAD_ONLY / NOT_FETCHED / UNVERIFIED / NOT_A_FACT`；
- `SOURCE_SNAPSHOT` 与 `sources/snapshots/` 内容寻址仓库可用；
- Queue 仍为 at-least-once，外部请求具备保守的 before/after-send 语义；
- 产品中尚不存在页面 Fetch 服务、HTML parser/sanitizer 或 Fetch Job；
- `sources`、`claims`、`claim_evidence` 和研究档案仍属于后续 Issue。

Issue 015 的候选合同和历史 migration 不得修改。Fetch 成功通过新表表达，不把
`search_result_candidates.fetchState` 从 `NOT_FETCHED` 改为其他值。


三、本 Issue 明确不做
--------------------

- 不运行搜索、不选择候选、不自动入队；
- 不全站遍历，不读 sitemap、RSS、Atom、站内链接队列或下一页；
- 不抓取页面中的图片、CSS、字体、脚本、iframe、视频、附件或 favicon；
- 不支持 PDF、Office、电子书、ZIP、图片 OCR 或媒体转码；
- 不执行 JavaScript，不使用 Electron renderer、webview、Playwright 或无头浏览器抓页；
- 不登录，不保存或发送 Cookie，不处理账号会话；
- 不绕过登录、付费墙、验证码、WAF、robots 或其他访问控制；
- 不提供代理、自定义 DNS、自定义 Host、自定义 header、任意 method 或任意 HTTP 模板；
- 不创建或更新 `sources`、`claims`、`claim_evidence`、`books`、`clips`、
  `research_dossiers`；
- 不把标题、正文、搜索摘要或抽取文本升级为事实或证据；
- 不调用模型做摘要、翻译、分类、事实抽取或隐私识别；
- 不进入 BrowserClip、书目发现、来源分级或事实冲突处理；
- 不增加真实网络验收、真实站点 fixture 或生产后台抓取开关。


四、Search / Fetch / Evidence 边界
--------------------------------

建立 Electron 无关的 `packages/fetch`，依赖方向不得形成循环。

输入只能绑定一个已持久化 SearchCandidate：

- candidate 必须存在；
- URL 与 URL hash 必须和 FetchRequest/FetchPlan 精确匹配；
- candidate 必须保持四个 Issue 015 冻结状态；
- provider provenance 只能读取，不能改写；
- ManualUrl 也必须先成为 SearchCandidate，不能绕过 Search 合同直接传任意 URL。

Fetch 成功只产生：

- FetchRun；
- FetchedDocument；
- 离线净化 HTML；
- 确定性抽取纯文本；
- 有限响应与策略元数据。

Fetch 输出状态固定：

- `evidenceEligibility = FETCHED_NOT_EVIDENCE`
- `truthStatus = UNVERIFIED`
- `factStatus = NOT_A_FACT`

Issue 019 前不得创建 Source、Claim、证据摘录、置信度或冲突结论。


五、ControlledFetch V1 合同
--------------------------

定义显式版本化、严格 runtime validation 的：

- `FetchRequestV1`
- `FetchPlanV1`
- `FetchProfileV1`
- `FetchRunV1`
- `FetchOutcomeV1`
- `FetchedDocumentV1`
- `RedirectHopV1`
- `RobotsDecisionV1`
- `FetchStableErrorV1`

所有对象 exact-object 校验，额外字段拒绝；数组、字符串、对象深度和序列化字节有硬上限。

`FetchRequestV1` 至少包含：

- contractVersion；
- executionId；
- searchCandidateId；
- expectedCanonicalUrlHash；
- selectionKind：`USER_SELECTED / RESEARCH_PLAN_SELECTED / FIXTURE_SELECTED`；
- selectionReasonCode；
- fetchProfileId/profileRevision；
- requestedAt；
- jobId，可空。

本轮产品 composition 不产生 `RESEARCH_PLAN_SELECTED`；该枚举只冻结未来合同。
测试只使用 `FIXTURE_SELECTED`。不得接受 raw URL、header、Cookie、credential、proxy 或脚本。

`FetchPlanV1` 至少绑定：

- request semantic hash；
- candidate ID、canonical URL hash、origin；
- profile snapshot/revision；
- robots、redirect、DNS、MIME、charset 和 privacy policy versions；
- rate-policy identity；
- raw/decoded/DOM/sanitized/text 大小上限；
- connect/header/body/total timeout；
- 最大 redirect 和最大外部请求数；
- storage estimate；
- expiry。

plan 过期或任一绑定变化时，发送前返回 `FETCH_PLAN_STALE`。


六、Fetch 状态与确定性
---------------------

有限状态至少覆盖：

- `PLANNED`
- `ROBOTS_CHECKING`
- `ROBOTS_BLOCKED`
- `RATE_LIMITED_BEFORE_SEND`
- `FETCHING`
- `RECEIVED`
- `SANITIZING`
- `EXTRACTING`
- `PERSISTING`
- `SUCCEEDED`
- `REJECTED`
- `CANCELLED_BEFORE_SEND`
- `CANCELLED_AFTER_SEND`
- `FAILED_BEFORE_SEND`
- `FAILED_AFTER_SEND`
- `AMBIGUOUS`

`externalRequestCount` 精确包含 robots 和页面/redirect 请求。

每个 execution 只允许一个页面获取 attempt；robots 检查是独立的策略请求。
V1 自动 retry 固定为 `NONE`。任何 after-send 终态不明都进入 `AMBIGUOUS`，不得自动重发。

同一 executionId：

- 相同 request 返回既有终态；
- 不得重复网络、写文件或建文档；
- request hash 不同则 `FETCH_EXECUTION_CONFLICT`。


七、URL、DNS、SSRF 与连接固定
----------------------------

复用 Issue 015 的 HTTP/HTTPS canonical URL 语义，但 Fetch 必须增加网络目标验证。

产品网络策略：

- 只允许 `http:` 和 `https:`；
- 拒绝 userinfo、fragment、非法 percent encoding、控制字符和混淆空白；
- query 出现 token、session、auth、password、key、signature 等凭据型字段时拒绝，
  不记录原值，也不通过静默删除参数改变请求语义；
- 拒绝 localhost、`.localhost`、`.local`、单标签 host 和 IP zone identifier；
- 拒绝 IP literal 指向非公网地址；
- 每次请求和每次 redirect 都重新执行 host、DNS 与地址策略；
- A/AAAA 结果只要包含任一非公网地址即 fail closed；
- 只从验证通过的地址集合选择一个地址并固定到 socket；
- TLS SNI 与 HTTP Host 保持原始规范 host；
- 连接后核对 remote address 与固定地址；
- 不信任代理环境变量、PAC、系统代理、Alt-Svc 或代理 header；
- HTTPS 必须验证证书和主机名，不允许关闭 TLS 校验。

拒绝 IPv4/IPv6 的 unspecified、loopback、private、shared、link-local、multicast、
documentation、benchmark、reserved、IPv4-mapped private 等非公网范围。

DNS resolver、connector、clock 和 network transport 必须可注入，以便测试 DNS rebinding、
多地址和连接固定；产品 composition 只能安装严格实现。

loopback 仅可用于测试 transport。架构测试必须证明测试放宽策略未进入产品 composition。


八、HTTP 方法、重定向与请求边界
------------------------------

页面请求只使用 GET：

- 不先发 HEAD；
- 不发送 Cookie、Authorization、Proxy-Authorization、Referer 或 Origin；
- 不接受用户自定义请求 header；
- 使用固定、诚实、版本化 User-Agent，不伪装浏览器；
- 只声明有限 HTML/text Accept；
- 不读取或持久化 Set-Cookie；
- 不复用带认证状态的连接池。

默认 redirect 策略：

- 最多 3 跳；
- 每跳完整执行 URL/DNS/SSRF/MIME 前置验证；
- 禁止 HTTPS 降级；
- 允许同 host 的路径跳转与 HTTP→HTTPS；
- 跨 host 默认拒绝；
- 不把 Location 中的 userinfo、fragment 或非法 URL 传入下一跳；
- 每跳只保存有限状态码、host、URL hash 和策略结果，不保存 header。

出现跨 host redirect 时返回稳定结果，由后续人工/研究计划把目标作为新 SearchCandidate；
不得静默跟随或自动 fallback。


九、robots、访问控制与频率
------------------------

实现保守的 RFC 9309 robots 子集，并在合同中记录解析版本：

- 只请求同 origin `/robots.txt`；
- robots redirect 最多 1 跳且仍限同 host/HTTP→HTTPS；
- body、时间、MIME 和编码有更小独立上限；
- 精确处理适用 User-Agent group、Allow、Disallow、`*`、`$` 和最长匹配；
- 支持有界 Crawl-delay；
- 404/410 表示无规则；
- 401/403 表示禁止；
- 429、5xx、超时、超限、无法解析或冲突时为 `ROBOTS_UNKNOWN` 并阻止页面请求；
- robots 结果按 origin、User-Agent、policy version 和过期时间持久缓存；
- 不保存 robots 原文，只保存 body hash、有限解析结果和时间。

页面响应出现 401、403、407、429，或被有限规则识别为登录、付费、验证码/WAF challenge 时：

- 停止；
- 不提交表单；
- 不执行 JS；
- 不切换 User-Agent、IP、代理或 Provider；
- 不自动 retry。

新增 Fetch 专用持久化 origin rate policy/state：

- 全局并发有界；
- 每 origin 并发默认 1；
- min interval、window 和 timeout 显式版本化；
- robots 与页面请求都计入；
- 重启不清空窗口；
- Retry-After 只更新 `nextAllowedAt`，不 sleep/retry。


十、响应、MIME、压缩和字符编码
-----------------------------

只接受：

- `text/html`
- `application/xhtml+xml`
- `text/plain`

拒绝缺失或矛盾的 MIME、multipart、XML 非 XHTML、JSON、PDF、图片、音视频、压缩档案、
可执行内容和附件下载。

要求流式执行并同时限制：

- header 数量与总字节；
- Content-Length；
- raw wire bytes；
- decoded bytes；
- 压缩比；
- DOM node/depth；
- sanitized HTML bytes；
- extracted text bytes；
- total duration。

支持的 Content-Encoding 和 charset 必须是代码 allowlist。编码按 BOM、HTTP charset 和有限
HTML meta 的明确优先级解析；冲突、未知编码或 fatal decode 失败时停止，不猜测。

至少覆盖 UTF-8、中文和日文常见编码的 fixture，但不得调用模型修复乱码。

MIME 与前置字节明显冲突时 fail closed。不得因扩展名或上游标题推断 MIME。


十一、HTML 净化与正文抽取
------------------------

使用惰性、不会执行脚本的标准 HTML parser；选择及理由写入 ADR。

禁止使用真实 BrowserWindow、renderer、webview、Playwright 或 JSDOM 加载远程页面。

净化输出采用极小 allowlist：

- 仅保留正文语义所需的 heading、paragraph、list、blockquote、table、time 和简单 inline tag；
- 删除 script、style、noscript、template、iframe、object、embed、form、input、button、
  select、textarea、canvas、svg、math、audio、video、source、picture；
- 删除 event handler、style、class、id、src、srcset、href、action、formaction、meta refresh、
  base 和其他可发起导航/加载/执行的属性；
- 不保留 CSS、data URL、blob URL、remote resource 或 HTML comment；
- 序列化必须确定、UTF-8、离线、不可执行。

正文抽取必须确定且不使用模型：

- 优先 main/article 与明确正文结构；
- 排除导航、页头页尾、侧栏、推荐、广告、评论、登录、分享和 Cookie banner；
- 保留标题、byline、发布时间、段落、标题层级、列表、引用和表格文本；
- 规范 Unicode、空白和换行；
- 不生成摘要、不改写、不翻译、不判断事实；
- 抽取不足返回有限状态，不用整页 DOM 兜底伪装正文。

净化 HTML 与纯文本必须由独立 validator 再次检查，保证不存在 active content、远程资源引用、
脚本协议、NUL 或超限结构。


十二、最小化无关个人信息
----------------------

V1 采用确定性最小化，不使用模型或 NER：

- 不保存完整 DOM、header、Cookie、表单值、脚本状态或追踪标识；
- 排除评论区、用户列表、登录区、社交 widget 和联系表单；
- 对抽取文本中的明显邮箱、电话号码和精确地址型 contact block 做版本化替换；
- 不从 URL query 保存 token、session、email 或其他 credential-like 值；
- 只记录各类 redaction count，不保存被删除的原值；
- 无法确认正文边界或页面以用户生成内容为主时，标为
  `PRIVACY_REVIEW_REQUIRED`，不保存正文快照。

人名、作者名和作品名不因名称本身自动删除；V1 不做人物身份推断。


十三、文件、哈希与去重
---------------------

不保存原始响应 body。

成功文档只保存：

1. 净化后的离线 HTML；
2. 确定性抽取纯文本。

两者均通过现有 `SOURCE_SNAPSHOT` 内容寻址仓库写入 `sources/snapshots/`，数据库只保存
`ManagedRelativePath`。

至少记录：

- raw body hash，仅用于一致性和审计；
- 最终规范 URL 与 URL hash；URL 必须通过同一凭据型 query 拒绝规则，且不得进入 UI、日志或错误；
- sanitizer/extractor/profile version；
- sanitized HTML hash/bytes/path；
- extracted text hash/bytes/path；
- normalized document content hash；
- language/charset hint，保持未验证；
- privacy redaction counts；
- createdAt。

同一 normalized document content hash 与处理版本复用一个 FetchedDocument；不同 FetchRun
保留各自 provenance。文件先不可变发布、数据库后关联；数据库失败产生可检测 orphan，
不得删除可能共享的内容寻址文件。

不得把快照路径写入 `sources.local_snapshot_path`，因为 Issue 019 前不创建 Source。


十四、migration v9 与仓储
------------------------

只追加当前连续 migration，建议名称：

`controlled_public_page_fetch`

新增 STRICT 语义：

- `fetch_profiles`
- `fetch_origin_rate_states`
- `fetch_robots_cache`
- `fetch_runs`
- `fetch_redirect_hops`
- `fetched_documents`

关键约束：

- executionId 唯一；
- FetchRun 必须引用既有 search candidate；
- request/plan/candidate URL hash 一致；
- FetchRun 只允许保存校验后的最终规范 URL，不保存 redirect header 或未经校验的 Location；
- document 两个路径必须属于 `sources/snapshots/`；
- 三项 Fetch 输出状态由 CHECK 固定为
  `FETCHED_NOT_EVIDENCE / UNVERIFIED / NOT_A_FACT`；
- raw body、raw header、Cookie、credential、完整 robots、完整 DOM 不落库；
- `sources/claims/books/clips` 不因 Fetch 改变；
- origin/rate/status/time/content hash 有索引；
- redirect hop 次数和顺序有限；
- revision、时间和删除策略明确。

升级、回滚、备份、换行规范化和历史 migration 保护直接遵守 AGENTS.md。


十五、Queue、取消与崩溃恢复
--------------------------

新增 Job type：

`FETCH_PUBLIC_PAGE_V1`

payload 只保存：

- executionId；
- searchCandidateId；
- expected URL hash；
- selection kind/reason code；
- fetch profile/revision；
- plan identity；
- jobId。

result 只保存：

- fetchRunId；
- documentId，可空；
- terminal status；
- bytes/counts；
- stable error。

不得保存 URL 正文、页面正文、净化 HTML、纯文本、header、robots 原文或绝对路径。

执行顺序：

1. validate + semantic hash；
2. executionId 幂等检查；
3. 读取并绑定 candidate；
4. plan/profile/rate policy 检查；
5. robots cache 或 robots 请求；
6. origin rate reservation；
7. 事务外单次页面请求及有限 redirect；
8. MIME/size/charset 验证；
9. 内存中惰性 parse、sanitize、extract、privacy minimize；
10. 内容寻址文件发布；
11. 短事务保存 document/run/hops/rate settlement；
12. 完成 Job。

网络期间不得持有数据库事务。取消必须区分 before/after-send。崩溃恢复只恢复可证明
pre-send 的运行；收到响应但尚未持久化的未知情况保持 `AMBIGUOUS`，不自动重抓。

本轮只注册 handler，不启动生产自动入队来源。


十六、Issue 特有 UI 与 IPC
-------------------------

设置页只增加有限 Fetch 状态：

- Fetch V1 是否 ready；
- profile/revision；
- robots/rate/redirect/MIME/size policy 摘要；
- 全局与 per-origin 有界设置；
- ProjectDataRoot/storage readiness。

任务中心只显示：

- run stage/status；
- candidate ID；
- origin 的有限 display host；
- response MIME/charset；
- bytes、redirect、redaction 和 external request counts；
- document 是否已保存；
- stable error。

不得显示或提供：

- 页面正文、原始/净化 HTML；
-完整 URL/query；
- raw header、Cookie、DNS 地址或内部路径；
- 任意 URL 抓取框；
- 自动抓取/遍历按钮；
- proxy、header、User-Agent、robots override、TLS override；
- Issue 017/018/019 功能。

IPC 仅增加上述只读状态与有限 policy 配置所需窄方法；不增加执行 Fetch 的 renderer IPC。
