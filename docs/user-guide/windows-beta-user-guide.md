# Rednote Studio Windows 内部 Beta 用户指南

本文用于 `0.1.0-beta.1` Release Candidate 的离线人工验收。它不是正式发布声明。

## 1. 支持范围与重要边界

- 支持 Windows 10/11 x64，每用户安装，不要求管理员权限。
- 候选安装器未签名，仅供内部 beta 验收。Windows 可能显示 SmartScreen 或来源警告。
- 软件没有自动更新、后台下载或遥测上传；所有升级都由用户手动运行完整安装器。
- 不登录或操作真实小红书平台，不自动发布、评论或私信。
- 本轮只使用合成内容，不配置真实 Provider 凭据，不调用模型或业务 API。
- GitHub 只用于用户主动下载候选资产；安装后的核心本地工作流可以保持离线。

## 2. 下载并先验证候选包

从 Draft Release 下载以下两个文件，放在同一空目录：

- `RednoteStudio-0.1.0-beta.1-r10e-rc.zip`
- `RednoteStudio-0.1.0-beta.1-r10e-rc.zip.sha256`

在 PowerShell 中进入该目录，运行：

```powershell
$actual = (Get-FileHash -Algorithm SHA256 -LiteralPath '.\RednoteStudio-0.1.0-beta.1-r10e-rc.zip').Hash.ToLowerInvariant()
$record = (Get-Content -LiteralPath '.\RednoteStudio-0.1.0-beta.1-r10e-rc.zip.sha256' -Raw).Trim().Split(' ')
if ($record.Count -ne 3 -or $record[0] -ne 'RednoteStudio-0.1.0-beta.1-r10e-rc.zip' -or $record[2] -ne $actual) { throw '候选 ZIP 校验失败，请停止。' }
```

校验成功后再解压。不要在校验失败时尝试安装，也不要从其他渠道补齐缺失文件。

解压后，包内 `SHA256SUMS.txt` 覆盖除自身之外的每个普通文件。逐项核对文件大小、SHA-256
和相对路径；任何漏项、增项或字节变化都必须判为失败。`PROVENANCE.json` 应显示同一候选版本、
精确来源提交、来源 tree、工具链和 CI run 身份。

## 3. 未签名与 SmartScreen

这是未签名内部 beta，系统警告是已知限制。不要关闭 SmartScreen、修改组策略、安装未知证书或
使用脚本绕过系统安全策略。只有在 ZIP 与安装器 SHA-256 均和本次 Draft Release 记录一致时，
才可由测试人员在 Windows 界面中明确选择继续；无法确认来源时立即停止。

## 4. 干净安装与首次启动

1. 使用干净虚拟机快照，或新建的本地测试用户；确认系统为 x64。
2. 断开网络，并记录断网方式。不要以防火墙提示或 CI 结果代替实际离线状态。
3. 打开 `candidate/`，再次核对安装器与该目录 `SHA256SUMS.txt`。
4. 运行 `RednoteStudio-0.1.0-beta.1-win-x64-setup.exe`，不要使用管理员身份。
5. 安装应为每用户、单击式安装，不自动启动应用。安装完成后从开始菜单启动。
6. 确认应用进入 Rednote Studio V2、本地数据根初始化成功，并且没有更新下载或外部业务请求。

项目数据、备份和诊断使用应用管理的本地工作区。卸载程序默认只删除应用和快捷方式，不删除
项目数据、备份、诊断或系统凭据存储；这是一项产品语义，不是物理介质级删除或留存证明。

## 5. 只用合成内容验证关键本地工作流

全程使用明显标注为“UAT 合成样本”的虚构名称与文本，不粘贴真实作品正文、真实用户互动、
真实账号信息或 Provider 凭据。不要点击任何会发起模型请求的确认操作。

依次检查：

1. **账号与文风**：保存合成账号名、受众和文风，关闭并重新打开后仍可读取。
2. **本周计划**：查看本地候选，调整合成条目的日期时间、锁定并再次读取。
3. **内容包**：使用已有合成/演示条目检查六字段内容包、版本、人工批准与本地导出；不含置顶评论。
4. **互动**：粘贴一条合成评论和一条合成私信，关联本地内容，编辑建议并只记录人工发送事实；
   不在真实平台发送。
5. **数据复盘**：为合成已批准内容录入非负整数指标，检查汇总和确定性策略说明。
6. **书库**：只读浏览本地 Catalog，不导入、编辑、合并或拆分目录事实。

如果某项必须依赖真实 Provider 或真实平台才能继续，本轮应记为 FAIL 并停止该项，不得扩大验收范围。

## 6. beta.0 → beta.1 手动升级

`upgrade-fixture/TEST-ONLY-beta.0/` 只用于升级测试，其中每个文件都显著标记 `TEST-ONLY`。

1. 在干净快照中先运行 `TEST-ONLY-RednoteStudio-0.1.0-beta.0-win-x64-setup.exe`。
2. 启动 beta.0，建立少量“UAT 合成样本”，保存后退出应用。
3. 手动运行 `candidate/` 中 beta.1 安装器。
4. beta.1 应覆盖应用版本，但保留合成数据；启动后确认版本与数据均正确。
5. 不允许使用 beta.0 安装器覆盖成功升级后的 beta.1；降级请求应安全失败。

测试 fixture 不是候选版本，不得转交给普通用户，也不得单独发布。

## 7. 运行中阻断与损坏升级

- 应用运行时执行 beta.1 升级，安装器应以非零结果阻断；关闭应用后才允许升级。
- 应用运行时执行卸载，卸载器应阻断；关闭应用后才允许卸载。
- 只对安装器的单独副本制造损坏，绝不修改原候选文件。运行损坏副本应安全失败，已安装版本和
  合成数据应保持可用。测试后删除损坏副本。

任何 timeout、进程崩溃或状态不明都不能当作“已阻断”；记录失败码和截图后停止。

## 8. 卸载保留数据与重装

1. 关闭应用后，从系统应用列表卸载。
2. 确认应用目录、卸载注册信息和开始菜单快捷方式移除。
3. 确认项目数据仍由应用的数据根语义保留。
4. 重新运行同一 beta.1 候选安装器，启动后读取此前合成数据。

最终清理时仍按相同步骤卸载。保留的数据、备份和诊断由用户按应用内预览和精确目标管理；
不要把普通文件删除描述为物理介质不可恢复。

## 9. 受控备份与恢复

1. 在设置中预览备份范围，选择本地受控目标目录并明确确认。
2. 记录备份 manifest、版本和完整性结果，不发送备份文件。
3. 仅在同一 `0.1.0-beta.1` 或产品明确声明兼容的版本执行恢复预检。
4. 降级、未知版本、完整性失败、活动 lease 或保护副本无法建立时，恢复必须拒绝或进入失败闭锁。
5. 同版本恢复成功后，重新读取合成数据并检查未出现静默覆盖或凭据外泄。

不支持就地降级。无法证明兼容或回滚安全时，停止并保留现有数据与备份。

## 10. 本地诊断包

1. 在设置中先查看诊断预览和固定允许列表。
2. 由用户选择导出目录并明确确认。
3. 导出结果应为只含 `manifest.json` 和 `diagnostic.json` 的脱敏 ZIP。
4. 检查其中没有凭据、正文、完整 prompt/response、绝对路径或真实用户数据。
5. 诊断包绝不自动上传；保留、转交和删除均由用户决定。

## 11. 离线交接

分别保存并核对：候选 ZIP、外层 `.sha256`、`PROVENANCE.json`、本次已填写的 UAT 记录，以及
用户自行创建的数据备份。候选包与用户数据备份不得混装。接收人应重新校验外层 ZIP 和包内闭集，
不能只相信文件名或聊天中的摘要。

## 12. 回滚与失败出口

- 失败升级应保留旧版本；先保留证据和数据，不重复运行安装器碰运气。
- 成功升级后不支持用旧安装器就地覆盖新版本。
- 恢复只允许同版本或明确兼容版本；未知、降级或完整性不可证实时停止。
- 若应用、卸载器或恢复流程处于未知状态，先退出进程并保留数据，不手工删除受控数据根。
- 若 Win10 或 Win11 任一平台出现失败，该平台最终结论必须为 FAIL，不能用另一平台或 CI 代替。

## 13. 当前明确 UNKNOWN

- 安装器未签名，公开发行所需代码签名尚未决定。
- 物理断电、存储介质级持久性与物理删除不可由本候选证明。
- whole-backup 的签名真实性不是当前保证；本轮验证的是受控 manifest/hash 合同。
- Windows 10/11 之外的系统、架构和兼容环境未验证。

完成后将实际结果填写到 `WINDOWS-10-11-UAT.md`。不要修改 Draft Release 资产来补写结果；
将填写后的副本作为人工证据交回，由后续最终命令决定修复或正式发布。
