# ADR 0009：显式、可移植的供应商能力探测

- 状态：Accepted
- 日期：2026-07-28
- 适用范围：M2 Issue 013

## 背景

OpenAI-compatible 中转站可能只实现协议子集，HTTP 成功也不等于语义能力成立。把一次网络异常解释为“不支持”会形成持久误判；在启动、保存设置或任务执行时自动探测又会带来费用、隐私和不可预测的外部副作用。

## 决策

能力探测必须由用户在设置页显式 preview、确认和 start。main 进程从当前设置构建有限、不可变、最多 32 请求的计划，使用单次短期 token 防止 renderer 篡改或在配置变化后启动旧计划。runner 串行执行且不重试、不修复、不回退。

结论使用三态：

- `SUPPORTED` 只来自强正向语义证据；
- `UNSUPPORTED` 只来自能力或协议明确拒绝；
- 其他一切结果均为 `UNKNOWN`。

结果按非秘密配置指纹、设置 revision、凭据绑定版本、模型槽位、模型 ID、协议模式、能力和合同版本持久化。只有最新、当前、完整成功的运行可以成为当前矩阵。CapabilityGuard 只接受当前非 stale 的 `SUPPORTED`。

## 安全和可移植性

真实请求只能在用户显式确认后由 main 进程发起；renderer 永远不接收凭据、完整 Base URL、模型 ID、prompt、header 或原始响应。HTTP 只允许 HTTPS 或 loopback，固定端点、禁止 redirect、cookie 和任意请求定制。Batch 仅做 metadata 探测。图片 URL 不下载，搜索 URL/文本不保存。

开发、测试、source smoke 和 packaged smoke 只连接 `127.0.0.1` 随机端口 fixture，使用随机合成无效凭据和隔离数据目录。临时目录与缓存从仓库所在卷动态派生，不写死盘符，不执行全局清理。

## 后果

用户可能看到较多 `UNKNOWN`，但不会因为弱证据而获得虚假的“不支持”结论。探测请求可能产生第三方费用，因此 UI 必须显示请求上限且费用估算为未知。配置或凭据生命周期变化会让旧结果 stale，用户需要再次显式探测。
