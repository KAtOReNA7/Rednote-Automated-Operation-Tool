# R10 发布准备范围合同

**文档状态：已批准的范围合同**
**批准日期：2026-08-19**
**适用范围：R10A—R10E 发布准备；不授权新业务能力、正式发布或自动进入后续阶段。**

## 1. 事实与证据边界

- R08 的 N1—N7 视觉实现已通过用户验收并合并到 `main`。
- R09 的只读 Catalog 已完成用户验收并合并到 `main`；其精确开发提交为
  `e0e106b0ce4ccb71baab94fb877e6dff74df3ce2`，merge commit 为
  `326c8ddf246f374354789209755a867d9b8f7273`。
- 上述事实不等于正式发布、生产就绪、Windows 10/11 干净环境验证完成，或真实 Provider 的质量、稳定性与费用得到证明。
- R10 的目标是发布准备，不是扩张内容运营、研究、质量、Provider 或平台业务功能。

## 2. 已冻结的十项产品决定

1. 首版采用 **Windows 每用户离线安装**，不要求管理员权限。
2. 首版采用 **手动升级**，不实现自动更新。
3. 先发布未签名的 **内部 beta**；公开分发前另行决定并实施代码签名。
4. 备份采用用户选择的本地磁盘 **受控目录快照**。
5. 恢复只允许 **同版本或明确声明兼容** 的版本；拒绝降级和未知版本。
6. Release Candidate 必须在 Windows 10 与 Windows 11 上分别进行人工候选验证。
7. Release Candidate 通过 **Draft GitHub Release** 交付；两平台验收均通过后，才可另行申请正式 GitHub Release。
8. 诊断信息先在本地供用户预览，再由用户手动导出；绝不自动上传，保留和删除由用户管理。
9. R10 不实现自动更新、云端运行依赖或隐藏更新接口。
10. R10B 的备份/恢复 UX 与 R10C 的诊断导出 UX 必须先完成 Figma 设计和用户确认，再进入实现。

## 3. 阶段顺序与共同门禁

阶段严格按 `R10A → R10B → R10C → R10D → R10E` 执行；不得并行跳过前序阶段门禁、自动合并、自动进入下一阶段或自动发布正式 Release。

每个阶段开始前必须遵守根级 `AGENTS.md`、动态核验 Git 基线与授权范围，并以真实验证证据回填验收。任何新 UI 必须先有已批准的 Figma 设计；本合同明确只有 R10B、R10C 在本轮已知范围内强制需要该前置设计。

## 4. R10A：文档与发布事实收口

**用户结果**：活跃 README、索引和治理测试不再将 R08/R09 误报为待验收，并把本合同作为唯一当前发布准备范围入口。
**进入门禁**：R09 已合并并经用户验收；文档事实已动态核验。
**完成门禁**：文档状态同步、合同与索引可访问、治理测试通过、仅创建 Draft PR。
**停止条件**：Draft PR 通过精确 HEAD CI 后停止等待用户审核；不得开始 R10B。

## 5. R10B：受控备份与恢复

**用户结果**：用户可对受控项目数据根建立本地磁盘受控目录快照，并得到恢复预检、兼容性判断、完整性校验和明确失败出口。
**进入门禁**：R10A 通过；备份/恢复 UX 已完成 Figma 设计和用户确认；备份位置、格式和兼容策略与本合同一致。
**完成门禁**：恢复前预检、受控路径与完整性校验、同版本/显式兼容判断、失败回退与数据保护均有行为证据。
**停止条件**：未知版本、降级、无法保护既有数据、不可验证路径或无法证明回滚时 fail closed；禁止自动覆盖现有数据。

备份不是迁移前数据库备份的别名：其格式必须是版本化 manifest 所描述的受控目录快照。只保存受管相对路径及必要摘要；不得复制 credential、绝对路径、原始模型响应或不受控目录内容。

## 6. R10C：脱敏诊断包

**用户结果**：用户先审阅本地诊断预览，再手动导出版本化、可校验、默认脱敏的诊断包。
**进入门禁**：R10B 完成；诊断导出 UX 已完成 Figma 设计和用户确认；诊断 allowlist、大小边界与保留语义已批准。
**完成门禁**：预览、审阅、hash/版本校验、导出失败清理和敏感字段拒绝均有行为证据。
**停止条件**：任何 credential、token、数据库正文、完整 prompt/response、绝对路径或用户未确认敏感内容将被导出时停止并拒绝。

诊断只能由用户手动导出；禁止后台上传、自动留存和云端支持依赖。

## 7. R10D：Windows 分发、安装、升级与卸载

**用户结果**：内部 beta 以每用户离线安装方式交付，用户可手动升级并理解卸载、数据保留、兼容升级与失败回退边界。
**进入门禁**：R10B、R10C 完成；安装范围、手动升级和未签名内部 beta 边界保持本合同规定。
**完成门禁**：受控安装、升级、卸载、数据根语义、版本/manifest/checksum 与失败回退在隔离 Windows 环境可验证。
**停止条件**：不得实现自动更新、后台下载、隐藏更新接口或未经授权的签名购买/证书配置；未签名内部 beta 不得宣称公开发行级可信安装。

## 8. R10E：Release Candidate 验证、用户指南与治理

**用户结果**：产生可审计的候选制品、checksum manifest、来源证明、最终用户指南和离线交接/回滚说明。
**进入门禁**：R10A—R10D 完成，且候选制品可重复构建。
**完成门禁**：候选经 Draft GitHub Release 交付；在干净 Windows 10 与 Windows 11 分别人工完成安装、手动升级、卸载、备份、恢复与关键工作流验证；用户指南覆盖安装、备份、恢复、诊断、离线交接、回滚和人工平台边界。
**停止条件**：任一平台或恢复验证失败即停止，不以 CI 替代人工候选验证。仅当两平台均通过用户验收，才可另行申请转为正式 GitHub Release。

## 9. 安装、升级、卸载、签名与制品边界

- 首版仅 Windows 每用户离线安装、手动升级；不要求管理员权限。
- 内部 beta 可以未签名，但必须如实说明；公开分发的代码签名另行审批与实施。
- 当前目录式 Windows 体验包不是正式安装器，也不是正式 GitHub Release。
- 不引入自动更新器、预埋隐藏更新接口、后台下载或云端运行依赖。
- 任何 release/tag、签名、公开分发或正式 GitHub Release 都需要该阶段以外的明确授权。

## 10. 数据、凭据、网络与费用安全边界

- 不读取、复制、输出、迁移或导出真实凭据；诊断默认脱敏。
- 不访问真实用户业务数据以外的测试数据根；不读取或传播未授权内容。
- 不调用真实模型、搜索、图片、平台或业务 API；任何可能产生费用的操作不属于 R10A。
- 不新增云端运行依赖、后台上传、自动平台操作、自动登录、发布、评论或私信。
- 保持 `aiDisclosure=false` 的既有约束；版权风险不进入门禁、评分、审批、排期或导出决策。

## 11. 明确排除项与未来决定

R10 不恢复或顺带实施 029B、M4、M5 或其他已推迟能力。旧 M6 Issue 044—048、PRD、路线图和历史指令仅作为审计参考，不是当前可执行授权。自动更新、公开分发签名、公开 Release、跨未知版本恢复、云端支持和后台上传均需新的用户决定与独立授权。

## 12. 文档冲突与变更审批

事实优先级依次为：当前用户明确指令、当前阶段指令、本合同、冻结 PRD/路线图、根级及作用域内 `AGENTS.md`、已提交 ADR/合同/测试。若不能按更严格规则消解冲突，立即停止并报告。对已批准决定、阶段顺序、安全边界或发布语义的改变必须由用户明确批准；不得通过 README、体验包或实现细节暗中扩大范围。
