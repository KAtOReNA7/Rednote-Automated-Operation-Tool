五、Manifest V3 与最小权限
-------------------------

插件使用事件驱动 MV3 Service Worker，不依赖长期存活或全局变量。

允许的 manifest 权限仅为：

- `activeTab`
- `scripting`
- `storage`

允许的 host permission 仅为：

- `http://127.0.0.1/*`

其用途只是在 Service Worker 中访问用户配置的 Local API 端口。

Manifest 必须：

- `manifest_version = 3`；
- `incognito = not_allowed`；
- 不包含 `<all_urls>`；
- 不包含 `content_scripts`；
- 不包含 `externally_connectable`；
- 不包含 `web_accessible_resources`，除非实际构建工具强制；如确需则必须空能力且 ADR 解释；
- 不包含 `update_url`、固定 `key`、远程 script、CDN、Wasm 或 eval；
- extension CSP 仅允许本包脚本，禁止 object、frame 和远程代码；
- 不将 source map、测试 fixture、`.env`、token 或内部文档打入发行目录。

若实现所需 API 在目标浏览器版本中不存在，真实显示不支持并停止；不得扩大权限补救。


六、上下文与消息隔离
--------------------

只有三类运行上下文：

1. action popup：表单和用户明确操作；
2. MV3 Service Worker：token、Local API、截图和编排；
3. 一次性 `chrome.scripting.executeScript`：读取当前主框架的有限页面信息。

注入规则：

- 只在用户点击插件 action 后；
- 只注入当前 active tab 的 top frame；
- 使用 `ISOLATED` world；
- 只返回 exact-object 的 URL、标题、选中文本、document identity 和采集时间；
- 不注入 allFrames；
- 不注册持久脚本；
- 不读 iframe；
- 不修改页面 DOM/CSS；
- 不建立 `window.postMessage` bridge；
- 不监听页面事件；
- 不调用 `chrome.storage`、Local API 或 token。

插件不声明 external messaging listener。popup 与 Service Worker 消息必须验证：

- `sender.id === chrome.runtime.id`；
- sender URL 属于当前扩展 origin；
- 固定 message kind allowlist；
- exact-object、长度、深度和枚举；
- 不接受函数、prototype pollution key 或任意 command。

页面脚本、网页 DOM 和一次性注入函数永远不能获得 endpoint、port、pairing code、token、
Authorization、clientId 或 Local API 响应。


七、页面与导航绑定
------------------

只允许当前已提交的主框架 HTTP/HTTPS 页面。

明确拒绝：

- `chrome:`、`edge:`、`about:`、`file:`、`data:`、`blob:`、`view-source:`；
- 其他扩展页面；
- 浏览器设置、下载、密码、开发者工具和新标签页；
- URL 中的 userinfo、控制字符或凭据型 query；
- incognito tab；
- 正在加载、discarded 或没有稳定 tab/document identity 的页面。

一次收藏必须绑定：

- tabId/windowId，仅驻内存；
- documentId；
- committed URL 与 URL hash；
- page title hash；
- capture startedAt；
- activeTab user gesture。

读取信息、生成截图和提交前分别重新确认 tab、document 和 URL 未变化。任一变化立即丢弃
内存截图和表单提交，返回 `CLIPPER_TAB_CHANGED`。

tabId、windowId 和 documentId 不写 SQLite、截图、日志、诊断或 Local API payload。


八、用户采集流程
----------------

action popup 的顺序固定：

1. 显示当前连接状态；
2. 未配对时显示配对表单；
3. 已配对时读取当前 HTTP/HTTPS 页面；
4. 显示 host、标题和选中文本预览；
5. 用户填写或确认字段；
6. 用户可明确生成可见区域截图并预览/移除；
7. 用户勾选“这是我主动选择保存的公开页面样本”；
8. 用户点击“保存样本”；
9. Service Worker 重新校验页面绑定；
10. 经过认证的 Local API 写入；
11. 只显示成功 ID 或有限错误；
12. 清除 popup 与 Service Worker 中的正文、备注、截图和 pairing code。

字段：

- 页面 URL：自动、只读；
- 页面标题：自动、允许用户修正后保存；
- 账号名称：用户填写，可空；
- 发布时间：用户填写，可空；
- 选中文本：自动读取，可空，不以整页正文兜底；
- 用户备注：用户填写，可空；
- 平台：用户选择有限枚举；
- 可见指标：用户手填有限字段；
- 内容类型标签：用户选择有限枚举；
- 截图：可选，默认关闭。

可见指标至少支持：

- views
- likes
- favorites
- comments
- shares

每项为可空、非负、安全整数。缺失必须为 `NULL`/省略，不能填成 0。

插件不得根据 DOM 自动识别账号、发布时间、平台、指标或标签；host 最多作为可见提示，
最终值由用户确认。


九、截图边界
------------

截图只通过用户点击“截取当前可见区域”触发：

- 使用 `chrome.tabs.captureVisibleTab`；
- 只截当前 viewport；
- 不滚动、不拼接、不截全页；
- 页面 scheme 已通过第七节校验后才调用；
- 截图生成后立即再次检查 document/URL binding；
- popup 显示缩略预览并允许移除；
- 不写 `chrome.storage`、IndexedDB、Cache Storage 或临时磁盘；
- 未保存、失败、取消或 popup 关闭时从内存释放。

只接受浏览器生成的 PNG 或 JPEG：

- data URL prefix 精确；
- base64 canonical；
- magic bytes、MIME、尺寸、像素数、解码字节和 hash 由桌面端重新验证；
- 发行版不引入 EXIF、OCR、裁剪、滤镜、压缩重编码或缩略图业务；
- 截图只写 `CLIP_SCREENSHOT` 内容寻址目录；
- SQLite 只保存 ManagedRelativePath 和有限图片元数据。

截图默认关闭。不得因截图未提供而阻止保存其他字段。


十、配对、token 与浏览器存储
---------------------------

复用 Issue 011：

`POST /v1/pairings/exchange`

插件配对时：

- 用户手动输入/粘贴精确的 `http://127.0.0.1:<port>` endpoint 与 pairing code；
- 不接受 localhost、IPv6、host name、HTTPS、path、query 或 fragment；
- 不扫描端口；
- Service Worker 用 `crypto.getRandomValues` 生成 32-byte token；
- extension origin 从 `chrome.runtime.getURL('')` 派生，不由用户输入；
- Origin header 由浏览器产生，代码不得伪造；
- 只把 token 发送给当前显式 endpoint；
- pairing 响应成功后才进入 PAIRED。

长期 token 只保存到 `chrome.storage.local`：

- 保存前必须把 access level 设为 `TRUSTED_CONTEXTS`；
- 浏览器不支持 `setAccessLevel` 时拒绝配对；
- 不使用 `storage.sync`；
- 不使用 Web Storage；
- popup 和一次性注入脚本不能读取 token；
- popup 状态 DTO 只含 `paired/reauthRequired/endpoint/clientLabel`；
- token 不进入 DOM、message payload、错误、日志、截图、测试快照或 source map。

配对采用可恢复的 pending 状态：

- 交换前先保存 pending token 与 pairing attempt ID；
- 成功响应后原子提升为 active；
- Service Worker 中途停止后，可用 pending token 调用 authenticated status 判定是否已成功；
- 不重新提交 pairing exchange；
- 确认失败后清除 pending；
- 同 origin 重新配对完成后替换旧 token；
- 收到统一 401 时清除 active token 并进入 `REAUTH_REQUIRED`。

Service Worker 不依赖全局变量保存任何必须恢复的状态。

`BrowserClipCreateV1` 至少包含：

- browserFamily：`CHROME / EDGE / CHROMIUM_UNKNOWN`；
- pageUrl；
- pageTitle；
- platform；
- accountName，可空；
- publishedAt，可空；
- selectedText，可空；
- userNote，可空；
- visibleMetrics；
- contentTags；
- publicPageConfirmed=true；
- screenshot，可空。

不得包含：

- tab/window/document ID；
- HTML/DOM；
- hidden text；
- Cookie/storage；
- request/response header；
- page script data；
- token、pairing code、Authorization；
- 任意文件路径；
- 模型、Fetch、Source 或 Claim 字段。

建议硬上限：

- URL 4,096 UTF-8 字节；

所有文本 NFC、去 NUL/控制字符；selectedText/note 保留用户原文，不做摘要、翻译或事实判断。


十二、Local API v1 增量
----------------------

只新增：

- `OPTIONS /v1/browser-clips`
- `POST /v1/browser-clips`
- `OPTIONS /v1/browser-clips/receipts/<captureId>`
- `GET /v1/browser-clips/receipts/<captureId>`

不得新增 clip 列表、文件下载、任意查询、删除、编辑、Fetch、Search、Book、Source、Claim、
模型或平台路由。

所有 route 继续要求：

- remote address/Host 精确为既有 `127.0.0.1:<actualPort>`；
- 合法 `chrome-extension://` Origin；
- Origin 与 active client 精确绑定；
- Bearer token digest 认证；
- CORS 只回显已验证 origin；
- exact method、path 和 content type；
- 不接受 query string；
- 有界 header、body、timeout、并发和每 client rate；
- stable error，不泄漏认证差异。

`POST`：

- 只接受 `application/json; charset=utf-8`；
- route-specific body 上限，不改变其他 route 的 8 KiB 上限；
- 按流计数，不信任 Content-Length；
- 截图 base64 在落库前完整验证；
- 同 client/origin 同时最多一个 ingest；
- 不使用压缩、multipart 或 chunk upload。

`GET receipt`：

- 只读取同 extension origin 创建的 captureId；
- 只返回 `UNKNOWN / IN_PROGRESS / SUCCEEDED / FAILED`、clipId、candidateId 和有限时间；
- 不返回正文、备注、截图、路径或错误细节；
- 仅用于 after-send 结果确认，不触发写入或重试。

`GET /v1/capabilities` 必须真实更新：

- `clipperBusinessRoutes=true`
- BrowserClip contract version；
- body/screenshot/text/metric/tag 限制；
- receipt lookup 支持；
- origin scheme 仍为 `chrome-extension`。


十三、幂等、限流与失败语义
------------------------

captureId 由 Service Worker 每次用户点击保存时生成。

数据库唯一键使用：

`extension_origin + captureId`

语义：

- 同 captureId + 同 canonical payload hash：返回既有 receipt/clip；
- 同 captureId + 不同 payload hash：`CLIPPER_CAPTURE_CONFLICT`；
- 成功响应丢失时，插件只查询 receipt，不重发；
- 可证明 before-send 失败时，用户可再次点击，继续使用同 captureId；
- after-send 仍无法确认时显示 `SAVE_STATUS_UNKNOWN`，提示用户在桌面应用查看；
- 不建立后台 outbox、不定时重试、不轮询；
- popup 关闭后不持久化未发送正文或截图。

每 client 必须有：

- 每分钟 clip 数量上限；
- 每日 clip 数量上限；
- 同时 ingest 上限；
- 每日截图字节上限；
- 失败请求上限；
- 有限 Retry-After。

限流状态可持久化或复用现有安全实现，但重启不能把已提交 capture 变成可重复写入。


十四、截图文件与事务
--------------------

桌面端对 screenshot：

1. 严格解码 base64；
2. 校验 magic/MIME/尺寸/像素/字节；
3. 计算 SHA-256；
4. 通过 `CLIP_SCREENSHOT` 不可变发布；
5. 在同一数据库事务中写 clip、receipt、SearchCandidate link；
6. 成功后返回有限 response。

文件先发布、数据库后关联。DB 失败时留下可检测 orphan，不删除可能共享的内容寻址文件。

无 screenshot 时不得创建空文件或伪路径。

截图字节不得进入 SQLite、WAL、SHM、日志、audit、diagnostic、IPC DTO 或 SearchCandidate。

十六、BrowserClipAdapter 激活
----------------------------

成功 ingest 必须在同一数据库事务中：

1. 保存 Clip；
2. 通过 Issue 015 BrowserClipAdapter 生成本地 SearchBatch/Candidate；
3. 保存 SearchRun 与 SearchCandidate；
4. 建立 `clip_search_candidate_links`；
5. 完成 receipt。

BrowserClipAdapter 运行时从 `PENDING_LATER_ISSUE` 变为：

- mode=`PASSIVE_LOCAL`
- readiness=`READY`
- externalRequestCount=0
- accounting=`NOT_INCURRED`
- userSupplied=true
- sourceMetadataKind=`BROWSER_CLIP_INPUT`

Candidate 只复制 URL、有限标题和 provenance，不复制 selectedText、note、metrics 或 screenshot。

Candidate 继续固定：

- `LEAD_ONLY`
- `NOT_FETCHED`
- `UNVERIFIED`
- `NOT_A_FACT`

BrowserClipAdapter READY 只能使总体状态成为 `PASSIVE_ONLY` 或相应真实状态，不能伪装成
`ACTIVE_SEARCH_READY`。

不得自动创建 `FETCH_PUBLIC_PAGE_V1` Job。


十七、桌面样本查看
------------------

在现有“资料研究”或最合适的既有入口增加“收藏样本”视图，不新增无关导航。

列表显示：

- page title；
- display host；
- platform；
- account name；
- publishedAt；
- capturedAt；
- tags；
- screenshot 是否存在；
- linked candidate 状态。

详情显示：

- 完整规范 URL，作为纯文本；
- selected text；
- user note；
- visible metrics；
- screenshot；
- 来源 client label 与 capture time；
- linked candidate ID/四项冻结状态。

所有文本使用 React text rendering，禁止 `dangerouslySetInnerHTML`。

截图通过 main 控制的同源/自定义安全 protocol 按 clipId 读取：

- renderer 不接收 ManagedRelativePath 或绝对路径；
- clipId 必须存在且有权限；
- main 再次校验 path category、hash、MIME 和 magic；

二十四、Issue 特有停止条件
-------------------------
