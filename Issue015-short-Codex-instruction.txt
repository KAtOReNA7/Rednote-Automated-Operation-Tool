M2 Issue 015：通用 SearchProvider——精简增量开发指令
=====================================================

本文件替代此前的长版 Issue 015 指令。

完整遵守根级及作用域内 AGENTS.md；本指令仅定义当前 Issue 的增量规则。

推荐模型：GPT-5.6 Sol
推荐推理强度：High；URL、安全执行、限流、幂等和 migration 使用 XHigh
目标提交信息：feat(search): add unified search providers


一、授权目标
------------

只实现 Roadmap Issue 015：

- 定义版本化 SearchProvider V1；
- 支持模型联网、独立 Search API 扩展点、定向来源、浏览器收藏输入合同和手工 URL；
- 五类来源返回统一 SearchCandidate/SearchBatch；
- 实现显式 Registry、Readiness、SearchPlan 和 SearchExecutionService；
- 请求具备有限速、超时、响应大小、结果数量、并发和幂等边界；
- 增加持久化 SearchRun、SearchResultCandidate 和 rate-limit state；
- 接入 Job Queue、CapabilityGuard 和 Issue 014 accounting；
- 增加设置/任务中心的有限状态展示；
- migration v8、专项测试、文档、120 项验收映射和一个本地提交。

完成后停止，不进入 Issue 016。


二、本 Issue 明确不做
--------------------

- 不抓取任何搜索结果 URL；
- 不下载或解析 HTML、PDF、图片、RSS、站点地图或附件；
- 不做正文抽取、HTML 净化、页面快照或内容 hash；
- 不做全站遍历、自动翻页或爬虫；
- 不实现 Chrome/Edge 插件或插件 Local API 业务 route；
- 不保存浏览器截图、选中文本或可见指标；
- 不实现书目发现、50 本去重、来源事实、研究档案或文案；
- 不把模型回答、snippet、标题或搜索排名当事实证据；
- 不写入 sources、claims、claim_evidence、clips、books 或 research_dossiers；
- 不配置具体独立 Search API 供应商或 credential；
- 不提供任意 HTTP method/path/header/body/解析脚本；
- 不实现自动 fallback、自动 retry 或多 Provider 并行聚合；
- 不进入 Issue 016、017、018 或后续范围。

真实密钥、真实模型、真实搜索服务、真实页面和真实费用继续按 AGENTS.md 保持为 0。

五、SearchProvider V1
--------------------

优先建立 Electron 无关的 `packages/search`；若现有依赖图要求其他位置，在 ADR 中解释且不得
形成循环依赖。

核心接口：

```ts
interface SearchProviderV1 {
  describe(): SearchProviderDescriptorV1
  preview(request: SearchRequestV1): Promise<SearchPreviewV1>
  execute(
    request: SearchRequestV1,
    context: SearchExecutionContextV1,
  ): Promise<SearchBatchV1>
}
```

`SearchProviderKind`：

- `MODEL_WEB_SEARCH`
- `SEARCH_API`
- `CURATED_SOURCE`
- `BROWSER_CLIP`
- `MANUAL_URL`

`SearchProviderMode`：

- `ACTIVE_REMOTE`
- `PASSIVE_LOCAL`
- `FIXTURE_ONLY`

`SearchProviderReadiness`：

- `READY`
- `DISABLED`
- `NOT_CONFIGURED`
- `CAPABILITY_UNKNOWN`
- `CAPABILITY_UNSUPPORTED`
- `CAPABILITY_STALE`
- `RATE_POLICY_REQUIRED`
- `BUDGET_POLICY_REQUIRED`
- `CODEC_UNAVAILABLE`
- `PENDING_LATER_ISSUE`
- `ERROR`

所有合同使用 discriminated union、显式版本和严格 runtime validator；输入、输出、数组、深度和
序列化大小均有限。


六、SearchRequest 与 ProviderDescriptor
--------------------------------------

`SearchIntent`：

- `BOOK_DISCOVERY`
- `BIBLIOGRAPHIC_LOOKUP`
- `AUTHOR_RESEARCH`
- `AWARD_RESEARCH`
- `PUBLISHING_NEWS`
- `REVIEW_LANDSCAPE`
- `CULTURAL_CONTEXT`
- `USER_PROVIDED_URL`
- `USER_PROVIDED_CLIP`

主动搜索请求至少包含：

- contractVersion；
- executionId；
- providerInstanceId；
- intent；
- query；
- maxResults；
- localeHints；
- countryHint，可空；
- publishedAfter/publishedBefore，可空；
- allowedDomains/blockedDomains；
- liveAccess：`LIVE/CACHED_ONLY/UNSPECIFIED`；
- cursor，可空；
- ratePolicyRef；
- jobId，可空。

建议上限：

- query 512 字符；
- maxResults 20；
- locale 4 个；
- allowed/blocked 各 100 个；
- cursor 2 KiB；
- URL 4,096 字符；
- title 512 字符；
- preview/note 2,000 字符。

Descriptor 必须逐项声明：

- 支持的 intent；
- query/manual URL；
- allowlist/blocklist；
- date、locale、country；
- live access；
- cursor；
- structured sources；
- max results/response bytes；
- capability、rate、budget、credential readiness。

调用方要求未支持功能时返回 `SEARCH_FEATURE_UNSUPPORTED`，不得静默忽略或写进自然语言
query 后声称已应用硬过滤。


七、统一 SearchCandidate/SearchBatch
-----------------------------------

`SearchCandidateV1` 至少包含：

- candidateId/searchRunId；
- providerInstanceId/providerKind/originKind；
- canonicalUrl/urlHash/domain/displayHost；
- title/previewText，可空且有限；
- previewKind；
- upstreamRank/upstreamIdHash，可空；
- publishedAt/languageHint，可空且标记为上游未验证；
- discoveredAt；
- userSupplied；
- sourceMetadataKind；
- citationState；
- wasConsulted/wasCited，可空；
- 四个冻结的 LEAD_ONLY 状态；
- duplicateOfCandidateId，可空；
- bounded warnings。

`SourceMetadataKind`：

- `WEB_SEARCH_SOURCE`
- `URL_CITATION`
- `SEARCH_API_RESULT`
- `CURATED_ENTRY`
- `BROWSER_CLIP_INPUT`
- `MANUAL_URL_INPUT`

`SearchBatchV1` 至少包含：

- searchRunId/executionId/requestSemanticHash；
- provider snapshot；
- status/certainty；
- candidates 和 counts；
- truncated/cursor；
- externalRequestCount；
- modelRunId/usage/costState，可空；
- startedAt/finishedAt；
- warnings/stableError。

Batch status：

- `SUCCEEDED`
- `PARTIAL`
- `EMPTY`
- `RATE_LIMITED_BEFORE_SEND`
- `BUDGET_BLOCKED`
- `CAPABILITY_BLOCKED`
- `CANCELLED_BEFORE_SEND`
- `CANCELLED_AFTER_SEND`
- `FAILED_BEFORE_SEND`
- `FAILED_AFTER_SEND`
- `AMBIGUOUS`

`PARTIAL` 只允许“远程响应确定完整，但部分 item 因字段不合法被拒绝”；连接截断或终态不明
必须是 FAILED/AMBIGUOUS。


八、URL 与域名规则
------------------

候选 URL 只接受 HTTP/HTTPS。

拒绝：

- 其他 scheme；
- userinfo；
- 控制字符/NUL/混淆空白；
- 无效 percent encoding；
- Windows/UNC/device/drive-relative path；
- 缺失 host；
- 超长 URL。

规范化：

- scheme/host 小写；
- 标准 IDNA；
- 移除默认端口和 fragment；
- 规范 dot segment；
- 保持 path 和 query 语义；
- 不删除 tracking 参数；
- 不排序 query；
- 不自动 HTTP→HTTPS；
- 不请求 canonical link；
- 不跟随结果 URL；
- 规则显式版本化。

同一 Batch 按 canonical URL 去重并保留所有 provenance appearance；不得按标题、书名、ISBN 或
模型判断做作品级合并。

域名过滤：

- 输入只能是 host；
- 标准化 IDNA、小写和尾点；
- 使用 label-boundary 匹配；
- blocked 优先；
- 不使用 regex；
- 只有上游协议真正支持时才标 `hardFilterApplied`。


九、五类适配器
--------------

## 9.1 ModelWebSearchAdapter

执行条件：

- 精确 research model/modelId/protocol 的 webSearch 当前为 `SUPPORTED` 且非 stale；
- ModelExecutionService、budget 和 rate policy ready。

执行规则：

- 固定版本化 search prompt，query 明确作为数据；
- 只允许 Web Search tool；
- 必须搜索时使用 required/specific tool choice；
- 只接受 codec 识别的 completed search event；
- 只从结构化 source list 或 URL citation 建候选；
- 模型正文中的 URL、事实和总结全部丢弃；
- source 与 citation 分别保存 `consulted/cited`；
- 不启用 unlimited/deep research/background；
- 每个 SearchRun 最多一个 model execution；
- `cachePolicy=BYPASS`；
- `budgetClassification=NONESSENTIAL`；
- 复用 Issue 014 usage/cost/ambiguous，不重复记账、不自动重试。

协议不支持 requested domain/date/live/source 功能时 fail closed。

## 9.2 SearchApiAdapter

本轮只实现：

- `SearchApiCodecV1`
- request encoder/response decoder；
- transport interface；
- credential resolver interface；
- Scripted codec；
- loopback codec，仅测试。

产品运行时没有具体生产 codec，因此 readiness 必须为 `CODEC_UNAVAILABLE` 或
`NOT_CONFIGURED`。

禁止用户自定义 method、path、header、body、JSONPath、JavaScript、curl 模板或 credential
注入。未来生产 codec 必须代码 allowlist 并单独审查。

Transport 合同冻结：

- 生产仅 HTTPS，loopback HTTP 仅测试；
- request/response headers 有界；
- connect/header/body/total timeout 有界；
- raw/decompressed bytes 双限；
- redirects 默认 0，codec 明确声明时最多一个 same-origin；
- cross-origin、downgrade、invalid MIME/schema 拒绝；
- 不连接 result URL。

## 9.3 CuratedSourceAdapter

纯本地 catalog：

- 返回明确配置的出版社、作者、奖项、书目或站内搜索入口；
- 不请求 URL、RSS、sitemap 或 HTML；
- 不翻页；
- externalRequestCount=0；
- 仍为 LEAD_ONLY。

如支持 query template，只允许代码审查过的单一 percent-encoded placeholder；scheme、host、
path 固定。

## 9.4 BrowserClipAdapter

本轮只定义输入合同和 fixture。产品 readiness 固定 `PENDING_LATER_ISSUE`：

- 不新增 Local API route；
- 不接收插件请求；
- 不保存 selectedText、metrics 或 screenshot；
- UI 明确留待 Issue 017。

## 9.5 ManualUrlAdapter

立即可用的被动本地输入：

- 校验并规范化用户 URL；
- 可接收有限 title/note；
- 不访问 URL、不调用模型、不产生费用；
- externalRequestCount=0；
- userSupplied=true；
- LEAD_ONLY。


十、Registry、SearchPlan 与 Readiness
------------------------------------

Registry 只在 main/composition root 构造：

- providerInstanceId 唯一；
- renderer 不能注册适配器；
- 不加载任意动态 JS/远程 codec。

总体 readiness：

- `ACTIVE_SEARCH_READY`
- `PASSIVE_ONLY`
- `NOT_READY`
- `DEGRADED`

Manual/Curated、interface-only Search API 和 pending BrowserClip 均不能证明 active search ready。

SearchPlan 包含：

- planId/planHash/request hash；
- provider；
- estimated external requests/internal search calls；
- feature application matrix；
- timeout/rate/budget verdict；
- max results；
- settings/capability binding；
- expiry。

产品 fallback 固定 `NONE`。empty、429、5xx、invalid response、ambiguous、budget blocked、
capability stale 和 unsupported filter 均不得自动换 Provider。


十一、SearchExecution、限速与 Queue
---------------------------------

每个远程 Provider 必须有版本化 SearchRatePolicy：

- maxConcurrent；
- minIntervalMs；
- maxRequestsPerWindow/windowMs；
- timeoutMs；
- maxResponseBytes/maxResults；
- revision。

Rate policy 缺失时不 READY。状态持久化；重启不清窗；多 worker 原子检查。429 的 allowlisted
Retry-After 只更新 nextAllowedAt，不自动 sleep/retry。每次远程 execution 最多一次 attempt。

新增 Job type：

`SEARCH_EXECUTE_V1`

Job payload 保存有限 request/plan/settings/capability identity，不含 secret、任意 endpoint/header、
页面正文或截图；Job result 只保存 searchRunId、终态、counts 和 stable error。

SearchExecutionService 顺序：

1. validate + semantic hash；
2. executionId 幂等检查；
3. provider/readiness；
4. plan/settings/capability binding；
5. 本地 adapter 直接执行，或远程原子领取 SearchRun；
6. 远程 rate reservation；
7. ModelWebSearch 进入 Issue 014 budget；
8. 事务外至多一次外部调用；
9. decode/normalize；
10. 短事务保存 run/candidates/rate settlement；
11. 完成 Job。

相同 executionId 重放不得产生第二请求。可证明 pre-send 才可恢复；after-send 未知转
`AMBIGUOUS` 且不自动恢复。

本轮不自动 enqueue 搜索任务；Issue 018 才创建书目发现计划。
