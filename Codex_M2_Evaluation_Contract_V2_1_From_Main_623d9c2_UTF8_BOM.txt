七、v2.1 必须修正的评价语义

### 7.1 身份、人口与可比性

每条结果必须显式携带：

- stableModelId；
- 中文模型名与英文原名；

禁止跨 target、人口、grain、horizon 或现金权威直接排总体冠军。
selected pipeline 不得伪造新的 stableModelId，也不得覆盖 raw candidate。

### 7.2 作品现金点预测

- 主指标仍为每个 horizon 的现金 WAPE；
- signed bias 与 absolute bias 是校准护栏；
- MAE、中位绝对误差、误差分位、头部与长尾分解并列报告；
- raw candidate、selected pipeline、operational fallback 分开；
- 跨 horizon 池化只作诊断；没有业务 horizon 权重时禁止统一冠军；
- 所有配对 FVA 使用完全相同 case key、actual 和 population；
- 同时报告绝对误差差、相对变化、case 数、work 数和 cluster interval。

top 1%/5%/10% 必须明确：

- case-level，或先按 standardWorkId 聚合后的 work-level；
- 每个 origin×horizon 内排序，或全人口排序；
- 排序依据是 origin-visible scale，还是未来 actual；
- 使用未来 actual 时标记 POSTHOC_ATTRIBUTION_ONLY；
- post-hoc 分群不得用于模型选择或部署路由。

### 7.3 occurrence

occurrence actual 必须绑定独立正发生事实 actualPositive。存在 reversal 时，不得用
最终 net actual 的正负替代。

必须同时报告：

- evaluation prevalence/base rate；
- Brier score；
- log loss；
- PR-AUC；
- 辅助 ROC-AUC；
- reliability/calibration；
- 与“训练期已冻结 constant-probability baseline”的 Brier skill 和
  log-loss improvement。

evaluation population 自身 prevalence 只可作为描述性或 oracle-constant 参考，
不得冒充可部署基线。缺少训练期冻结 prevalence 时必须标记：

NOT_COMPUTABLE_FROZEN_TRAINING_BASE_RATE_MISSING

0.5 threshold 下的 specificity、precision、recall 只能作为 diagnostic。
业务阈值只能来自外层训练或事前成本合同，不得在评价 actual 上优化。
PR-AUC 必须和 prevalence 并列；高 base-rate 下不得单凭 PR-AUC 宣称成功。

### 7.4 conditional amount 与 reversal

只允许显式 conditionalAmountPrediction 对比 actualPositiveAmount。
必须单独保留 reversal component。

最终 point estimate、positive-actual 子集上的无条件预测或 selected fallback，
都不得冒名为条件金额模型。

### 7.5 排序与资源分配

排序是独立 diagnostic capability，不进入现金点预测晋升 gate。

任何排序信号必须：

- candidate 与 fallback 使用相同 origin×horizon 完整合格集合；
- 分别报告 Spearman、Kendall、top-k capture；
- 报告 candidate-minus-fallback 配对差；
- 按 origin×horizon 展示分布、胜率和 work/time cluster interval；
- 公开 group 数、case 数及加权方式；
- 禁止只用 candidate mean Spearman 宣称改善。

缺少 fallback 配对值或 interval 时只能写：

UNCONFIRMED_RANKING_SIGNAL

### 7.6 风险与区间

使用 artifact 原生 quantile grid，不得插值补造未冻结分位。
当前已知网格为 0.05/0.10/0.20/0.50/0.80/0.90/0.95。

必须并列报告：

- nominal 与 observed coverage；
- interval width/sharpness；
- WIS 或适用的 CRPS approximation；
- 相同案例冻结 reference interval 的相对结果；
- horizon/time block 条件覆盖；
- 可用 case 数和缺失原因。

只有 coverage 接近 nominal、但没有宽度或 reference 时，只能写：

PROMISING_DEVELOPMENT_INTERVAL_EVIDENCE

不得写“区间模型合格”。

### 7.7 portfolio

- 逐 horizon 报告 ETS 与 seasonal naive；
- 每个 horizon 报告 origin 数、配对误差差和 origin-cluster uncertainty；
- 30 cells 或约 10 origins/horizon 必须标记小样本；
- 3/6 月胜、12 月负只能形成未来验证假设；
- 不得自动创建 horizon router；

### 7.8 稳定性、MASE、隐私与缺失

- 作品评价按 standardWorkId cluster bootstrap；
- 组合评价按 origin cluster bootstrap；
- 连续时间块定义为相邻 calendar origin 的最大连通块；

- 公共 cell 至少 30 cases、20 works；
- 组合 cell 至少 5 origins；
- 不满足时使用 SUPPRESSED_PRIVACY_THRESHOLD；
- 全零实际分母使用 UNDEFINED_ZERO_ACTUAL_DENOMINATOR；

- 缺少 raw 行的历史模型保持 NOT_RESCORABLE_RAW_ROWS_UNAVAILABLE，
